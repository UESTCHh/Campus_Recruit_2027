问题1：
为什么成员函数可以访问成员变量？
你的回答：
因为成员函数自带一个参数this，其为本对象的指针，可以通过该指针直接访问成员变量。
订正：
成员函数调用时，编译器会隐式传入当前对象的地址，
这个隐藏参数就是this指针。
通过this指针，成员函数可以知道当前操作的是哪个对象，
因此可以访问该对象的成员变量和成员函数。

问题2：
拷贝构造函数什么时候调用？
你的回答：
拷贝构造函数在将一个对象实例赋值给另一个对象实例时自动调用，并且将该对象实例作为参数自动传入。
订正：
拷贝构造函数在使用一个已经存在的对象初始化另一个新对象时调用。

常见情况：

1. 一个对象初始化另一个对象：

Student s1(22);

Student s2 = s1;


2. 以值传递方式传递对象：

void func(Student s)

{
}


3. 函数返回对象时：

Student func()
{
    Student s;
    return s;
}


拷贝构造函数参数通常形式：

Student(const Student& other)


注意：

对象初始化：

Student s2 = s1;

调用拷贝构造函数。


对象赋值：

Student s2;

s2 = s1;

调用赋值运算符operator=，
不是拷贝构造函数。

问题3：
为什么C++需要深拷贝？
你的回答：
因为当类中有指针时，浅拷贝只是简单的复制指针，当一个对象实例生命周期结束后，若调用析构函数会delete释放内存空间，那么另一个对象实例生命周期结束后调用析构函数会导致double free，重复释放同一块内存空间，造成错误。
订正：
默认拷贝构造函数执行的是浅拷贝，
对于指针成员，只复制地址，不复制实际数据。

因此多个对象可能指向同一块堆内存。

当析构函数释放资源时，
多个对象都会delete同一块内存，
导致重复释放(double free)。

因此需要深拷贝，
重新申请一块独立内存，
复制实际数据。

浅拷贝：两个对象共享一块堆空间。
深拷贝：两个对象拥有独立资源。

问题4：
默认拷贝构造函数做的是深拷贝还是浅拷贝？
你的回答：

默认拷贝构造函数进行浅拷贝，
只复制成员变量的值，
对于指针成员只复制地址。

订正：

C++编译器生成的默认拷贝构造函数采用逐成员拷贝。
对于普通变量复制值，
对于指针复制地址，因此属于浅拷贝。

问题5：
拷贝构造函数为什么参数必须使用const引用？
你的回答：
说明拷贝操作不能修改原对象的属性，属于一种保护功能，防止在拷贝构造函数中错误的修改原对象的属性值，用const说明该参数是只读的，不可修改。
订正：
拷贝构造函数参数必须使用const引用主要有两个原因：

### 1. 使用引用避免无限递归调用

如果参数使用值传递：

Student(Student other)

当调用：

Student s2 = s1;

编译器需要先复制s1生成参数other。

但是复制other本身又需要调用拷贝构造函数：

复制other
↓
调用拷贝构造函数
↓
继续复制other
↓
无限递归


因此拷贝构造函数参数必须使用引用：

Student(Student& other)


### 2. 使用const保护原对象

添加const：

Student(const Student& other)


表示：

拷贝过程中不会修改原对象。

因此：

const引用既避免了额外拷贝，
又保证不会修改源对象。


总结：

拷贝构造函数推荐写法：

Student(const Student& other)


原因：

1. 引用：
避免调用拷贝构造函数产生递归拷贝

2. const：
保证拷贝过程中不会修改原对象

补充一个面试容易追问的点：
为什么不是：
Student(Student& other)
而是：
Student(const Student& other)

因为若初始化操作为：
Student s2 = Student(22);
这里产生的是临时对象：
Student(22)
临时对象属于右值。

普通引用：
Student&
不能绑定右值。

而：
const Student&
可以绑定：
    左值对象
    右值临时对象
所以标准库和工程代码中基本都是：
ClassName(const ClassName& other)

问题6：
如果一个类没有显式定义拷贝构造函数，C++什么时候会自动生成默认拷贝构造函数？什么时候不会生成？

这个是连接：
    拷贝构造
    移动构造
    Rule of Three/Five
的入口。
答：当用一个已存在的对象实例初始化另一个对象时会自动生成，但是赋值操作“=”不会自动生成。
订正：
如果一个类没有显式定义拷贝构造函数，
编译器通常会自动生成一个默认拷贝构造函数。


例如：

class Student
{

};


Student s1;

Student s2 = s1;


此时编译器会自动生成：

Student(const Student& other)


默认拷贝构造函数执行逐成员拷贝：

普通成员：
复制值

指针成员：
复制地址（浅拷贝）


例如：

int age;

复制：

s1.age -> s2.age


int* p;

复制：

s1.p -> s2.p


但是以下情况可能不会生成默认拷贝构造函数：


1. 用户显式定义了拷贝构造函数

例如：

Student(const Student& other)
{

}


此时编译器不会再生成。


2. 类中存在不可拷贝成员

例如：

class A
{
    mutex m;
};


由于mutex禁止拷贝，
包含它的类也无法生成有效的拷贝构造。


补充：

赋值操作：

Student s2;

s2 = s1;


调用的是：

operator=赋值运算符


不是拷贝构造函数。


总结：

初始化新对象：

Student s2 = s1;

调用：
拷贝构造函数


已有对象赋值：

s2 = s1;

调用：
赋值运算符operator=

再补充一个和后续 Rule of Three/Five 相关的重要点：
你今天学到的：
class Student
{
    int* age;
};
如果只依赖默认拷贝构造：
s1
 |
 v
0x1000


s2
 |
 v
0x1000
会产生浅拷贝问题。

所以 C++ 有一个经典规则：
Rule of Three
如果一个类需要自定义其中一个：
    析构函数
    拷贝构造函数
    拷贝赋值运算符
通常三个都需要定义。

原因：
因为它们共同负责资源管理。
例如：
class Student
{
public:

    Student(const Student& other); // 拷贝构造

    Student& operator=(const Student& other); // 拷贝赋值

    ~Student(); // 析构
};

对象创建

 ↓
this指针
 ↓
对象复制
 ↓
拷贝构造
 ↓
浅拷贝问题
 ↓
深拷贝
 ↓
析构释放资源
 ↓
Rule of Three

问题7：
拷贝构造函数和赋值运算符 operator= 有什么区别？
答：拷贝构造函数和赋值运算符属于两个不同的函数，若类中未重载赋值运算符，那么使用 operator= 赋值可能出现错误，因为类中可能定义了一些编译器自带赋值操作无法实现的赋值属性，而拷贝构造函数是类中自带的也可以是自定义的，它传入const引用参数，不会修改原对象的属性值，并且通过深拷贝可以解决double free的问题，而赋值操作属于浅拷贝，会有double free的问题存在。
订正：
你的回答里面有几个点是正确的：
✅ 知道两者不是同一个函数
✅ 知道拷贝构造函数接收 const引用
✅ 知道深拷贝可以解决资源重复释放问题  

但是有两个地方需要修正：
1.赋值运算符不一定是浅拷贝
你说：
赋值操作属于浅拷贝，会有double free的问题存在。

这个不严谨。
实际上：
编译器默认生成的 operator= 是逐成员赋值
如果成员里面有指针，也会复制地址
这种情况下才会产生浅拷贝问题
但是：
如果程序员自己重载了operator=，也可以实现深拷贝。
所以不能说：
operator=一定是浅拷贝

应该说：
默认operator=可能产生浅拷贝问题。

2.拷贝构造函数和operator=区别核心不是深浅拷贝，而是调用时机

拷贝构造函数和赋值运算符的主要区别在于：

## 1. 调用时机不同


### 拷贝构造函数

用于：

使用已有对象初始化一个新的对象。


例如：

Student s1(22);

Student s2 = s1;


此时调用：

Student(const Student& other)



### operator=

用于：

两个已经存在的对象之间进行赋值。


例如：

Student s1(22);

Student s2(20);

s2 = s1;


此时调用：

operator=



## 2. 生命周期不同


拷贝构造：

创建新对象。

对象之前不存在。


operator=：

对象已经存在，
只是修改已有对象的内容。


## 3. 默认行为


如果没有自定义：

默认拷贝构造：

逐成员拷贝。

默认operator=：

逐成员赋值。


对于指针成员：

都会复制地址。


例如：

int* age;


复制后：

s1.age
 |
 v
0x1000


s2.age
 |
 v
0x1000


可能造成：

double free


因此需要手动实现深拷贝。


总结：

|区别|拷贝构造|operator=|
|-|-|-|
|作用|初始化新对象|给已有对象赋值|
|调用时机|对象创建时|赋值操作时|
|参数|const T&|const T&|
|是否创建对象|是|否|
|默认行为|逐成员拷贝|逐成员赋值|

注意：

两者默认都可能产生浅拷贝问题，
需要根据资源管理需求自行实现深拷贝。

另外补充一个面试非常喜欢追问的小细节：
为什么 operator= 返回：
Student& operator=(const Student& other)
而不是：
void operator=(...)

原因：
支持连续赋值：
a = b = c;
执行：
b = c
返回 b
再：
a = b
所以返回自身引用。
