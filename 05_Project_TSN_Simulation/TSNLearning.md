\#\# 📖 第一章：TSN 诞生的历史背景与核心痛点

在进入具体的协议栈之前，必须明确“为什么我们需要 TSN”。这是项目立项的根本逻辑，也是理解各种流控机制设计初衷的钥匙。

\#\#\# 1.1 传统以太网的“尽力而为”与 CSMA/CD 陷阱  
\* **\*\*底层机制\*\***：传统以太网 (IEEE 802.3) 底层采用的是 **\*\*CSMA/CD（载波侦听多路访问/冲突检测）\*\*** 机制。  
\* **\*\*物理隐喻\*\***：它就像一个没有红绿灯的十字路口。数据包发送前先“听”网络是否空闲。如果两人同时发送发生冲突，双方必须立刻停止，并各自在心里随机默数一个时间（**\*\*二进制指数退避算法\*\***）后再重传。  
\* **\*\*致命缺陷\*\***：这种随机等待导致了网络**\*\*延迟（Latency）\*\***和**\*\*抖动（Jitter）\*\***完全不可控。在工业 4.0 的场景（如机械臂高速同步），哪怕 1 毫秒的随机抖动也会导致灾难性的设备碰撞。当网络拥堵时，内部 FIFO 队列塞满，还会导致严重的**\*\*丢包\*\***。

\#\#\# 1.2 工业现场总线的“轮询”天花板  
\* **\*\*底层机制\*\***：传统的工业总线（如 CAN, Profibus）采用轮询（Polling）或中断机制。  
\* **\*\*致命缺陷\*\***：  
  1\. **\*\*带宽极低\*\***：通常在 Mbps 级别，无法承载现代工业的高清机器视觉图像和海量传感器数据。  
  2\. **\*\*扩展性差\*\***：网络节点越多，主机轮询一圈的开销（Overhead）呈指数级上升，系统效率随规模扩大而急剧下降。

\#\#\# 1.3 协议孤岛与 TSN 的破局  
\* **\*\*过渡期方案\*\***：以 EtherCAT、TTEthernet 为代表的技术通过魔改以太网实现了实时性，但它们是私有协议，互不兼容，导致工厂内部 IT 网络和 OT 网络物理割裂。  
\* **\*\*TSN 的终极使命\*\***：基于 IEEE 802.1 标准的纯正以太网，通过引入精确的时间同步、出站流控、入站安检等机制，实现**\*\*“混合关键性流量的共网传输”\*\***。让绝对准时的控制流和普通的视频/上网流量跑在同一根网线上，且互不干扰。

\#\# ⚙️ 第二章：TSN 交换机整机流水线架构 (The Packet Pipeline)

在 C++ 仿真器中，不能孤立地实现协议，必须构建一条严密的**\*\*数据包处理流水线\*\***。一条数据包从进入交换机到离开，必须依次经历以下四个防线。

\#\#\# 2.1 基础设施层：身份与排队映射 (802.1Q)  
传统以太网帧没有优先级。TSN 的一切调度基于 VLAN 标签。  
\* **\*\*PCP 字段\*\***：VLAN 标签中包含 3-bit 的 PCP (Priority Code Point)。  
\* **\*\*硬件映射\*\***：3-bit 刚好表示 $0 \\sim 7$ 共 8 个优先级，这完美映射到了现代 TSN 交换机出端口底层的 8 个硬件队列（\`TC0\` 到 \`TC7\`）。

\`\`\`cpp  
// \[C++ 架构构思\] 包解析与队列映射  
struct VlanTag {  
    uint16\_t tpid;  
    uint8\_t  pcp : 3;  // 3-bit 优先级 (0-7)  
    uint8\_t  dei : 1;  
    uint16\_t vid : 12;  
};

int mapToTrafficClass(VlanTag tag) {  
    // 严格按照 IEEE 802.1Q 映射标准  
    return tag.pcp; // 返回 0-7，对应 TC0-TC7 队列  
}

**🛡️ 第三章：入站安全与高可靠管线 (Ingress Pipeline)**

数据包到达交换机 Rx 端口，尚未进入交换矩阵和队列排队前，必须通过安检与去重。

### **3.1 PSFP \- 每流过滤与监管 (IEEE 802.1Qci)**

* **核心定位**：交换机的“安检大闸”。防范恶意攻击、终端故障引发的“流量洪峰”。实现防线前移，保护交换机内部宝贵的 RAM 缓存。  
* **三级防御流水线**：  
  1. **流过滤器 (Stream Filter)**：查身份。提取包头五元组，匹配白名单。  
  2. **流门控 (Stream Gate)**：查时间。基于时钟检查周期性流是否在合法的微秒窗口内到达。  
  3. **流计量器 (Stream Meter)**：查超速。针对当前流使用令牌桶 (Token Bucket) 算法，超过申请带宽的突发数据将被直接 Drop。

C++

// \[C++ 架构构思\] PSFP 令牌桶限速器伪代码  
class StreamMeter {  
private:  
    double tokens;         // 当前桶内令牌数  
    double burstSize;      // 桶容量上限 (最大突发量)  
    double cir;            // 承诺信息速率 (令牌恢复速度)  
    uint64\_t lastUpdateTime;

public:  
    bool consumeTokens(int packetSizeBytes, uint64\_t currentTime) {  
        // 1\. 根据时间差补充令牌  
        double timeDelta \= (currentTime \- lastUpdateTime) / 1e9;  
        tokens \+= timeDelta \* cir;  
        if (tokens \> burstSize) tokens \= burstSize;  
        lastUpdateTime \= currentTime;

        // 2\. 检查并扣除  
        if (tokens \>= packetSizeBytes) {  
            tokens \-= packetSizeBytes;  
            return true;  // 放行  
        }  
        return false; // 超速，拦截丢弃  
    }  
};

### **3.2 FRER \- 帧复制与消除 (IEEE 802.1CB)**

* **核心定位**：工业级与航空级的极高可靠性“双保险”。用双倍的空间（链路带宽）换取 0% 的丢包率。  
* **运作机制**：  
  * **发端 (Talker)**：克隆数据包，打上 R-tag（包含递增的 Sequence Number 序列号），分别发往路径 A 和路径 B。  
  * **收端 (Listener/Switch)**：维护已接收序号的历史记录哈希表。先到的包入库并放行，晚到的同序号克隆包直接消除（Drop）。

C++

// \[C++ 架构构思\] FRER 冗余消除器  
class FRER\_EliminationEngine {  
private:  
    // 存储近期收到的 Sequence Number，防止内存泄漏需定期清理旧记录  
    std::unordered\_set\<uint16\_t\> receivedHistory;

public:  
    bool processPacket(Packet\* pkt) {  
        uint16\_t seqNum \= pkt-\>getSeqNum();  
        if (receivedHistory.find(seqNum) \!= receivedHistory.end()) {  
            // 查到历史记录，说明是晚到的冗余包  
            pkt-\>drop();  
            return false;   
        }  
        // 第一次到达，记录并放行  
        receivedHistory.insert(seqNum);  
        return true;  
    }  
};

**🧠 第四章：出站宏观调度大脑 (Egress Pipeline)**

合法数据进入 TC0 \- TC7 八个队列后，这部分流控机制决定了“当前微秒，网卡到底把哪个队列的数据推向物理链路”。

### **4.1 TAS \- 时间感知整形 (IEEE 802.1Qbv)**

* **机制**：极其严苛的“列车时刻表”。基于 802.1AS 全局时间同步，配置全局门控列表 (GCL)。精确到微秒控制 8 个队列传输门的开与关。  
* **特性**：提供极致的确定性超低延时。  
* **痛点**：全网排表是 NP-Hard 数学难题。网络拓扑越大，越难算出不冲突的完美时刻表。

### **4.2 CQF \- 循环队列转发 (IEEE 802.1Qch)**

* **机制**：TAS 的高性价比降级平替方案。放弃全局精密排表，采用“双缓冲乒乓队列 (Double Buffering Ping-Pong Queues)”思想。  
* **运行逻辑**：  
  * 将同等优先级的流量绑定到 2 个硬件队列（如 Q0 和 Q1）。  
  * 周期 $T\_0$ (偶数时隙)：Q0 门开负责发送；Q1 门关负责接收上游数据。  
  * 周期 $T\_1$ (奇数时隙)：瞬间翻转。Q0 门关开始积攒数据；Q1 门开，排空刚才接收的数据。  
  * **铁律**：上游时隙 $n$ 收到的包，必须在时隙 $n+1$ 发出。  
* **工程代价**：消耗双倍的硬件队列资源（8个队列最多只能跑4种 CQF 流）。  
* **数学保障**：假设时隙为 $d$，经过 $h$ 跳，端到端时延下界为 $(h-1)d$，上界为 $(h+1)d$。

C++

// \[C++ 架构构思\] CQF 乒乓状态机  
class CQF\_Scheduler {  
private:  
    Queue\* Q0; // 偶数队列 (如 TC7)  
    Queue\* Q1; // 奇数队列 (如 TC6)  
    bool isEvenSlot;  
      
public:  
    void onSlotTimerTriggered() {  
        isEvenSlot \= \!isEvenSlot; // 时隙翻转  
        if (isEvenSlot) {  
            Q0-\>setGateState(OPEN);  
            Q1-\>setGateState(CLOSED);  
        } else {  
            Q0-\>setGateState(CLOSED);  
            Q1-\>setGateState(OPEN);  
        }  
    }  
      
    // 数据入队逻辑：永远丢进当前处于 CLOSED (正在积攒) 的队列  
    void enqueue(Packet\* pkt) {  
        if (isEvenSlot) Q1-\>push(pkt);   
        else            Q0-\>push(pkt);  
    }  
};

### **4.3 CBS \- 基于信用的整形 (IEEE 802.1Qav)**

* **机制**：专为音视频流设计的平滑机制。防止视频突发瞬间饿死底端普通上网数据。  
* **规则**：  
  * 队列里没包：积分归零。  
  * 正在发包：积分按斜率 $send\\\_slope$ 匀速下降。积分 $\< 0$ 就不准发下一个包。  
  * 有包等待但门关着：积分按斜率 $idle\\\_slope$ 匀速回升，直到 $\> 0$ 恢复发包权限。

### **4.4 ATS \- 异步流量整形 (IEEE 802.1Qcr)**

* **机制**：终极兜底方案。彻底抛弃 802.1AS 全局时间同步。  
* **逻辑**：采用 UBS（基于紧急度的调度器）。不针对“队列”限速，而是针对网络里的“每一条流 (Per-Flow)”独立分配一个漏桶定时器。把杂乱无章的输入流量“整形”成平滑均匀的输出流。  
* **代价**：极其消耗交换机 CPU 和内存（需维护海量的 Per-Flow 状态机）。

**🔪 第五章：物理层微观防线 (MAC Sublayer)**

### **5.1 帧抢占 (IEEE 802.1Qbu \+ 802.3br)**

* **核心痛点**：传输阻塞延时 (Transmission Blocking Delay)。如果 TAS 决定立刻发送紧急控制包，但网线上正堵着一个发了一半的 1500 字节普通长包，紧急包只能干等。  
* **传统妥协**：TAS 被迫设置极长的“保护频带 (Guard Band)”，在门控打开前提前禁止所有长包发送，导致大量带宽浪费。  
* **抢占机制**：  
  * 底层挂载 **eMAC (紧急引擎)** 和 **pMAC (普通引擎)**。  
  * 紧急帧到达时，MAC 合并子层像切香肠一样，瞬间**截断**正在发送的长帧（分片为多个 mPacket），强制让紧急帧插队发送。  
  * 紧急帧发送完毕后，重新缝合剩余的长帧片段。  
* **巨大收益**：彻底消灭阻塞延时，大幅压缩 TAS 保护频带，带宽利用率激增 20% 以上。

**🧬 第六章：系统级联合调度方案 (The Matrix)**

在真实的 C++ 交换机仿真模型中，一个物理端口的 8 个队列将发生如下复杂的**化学反应与调度映射**：

| 硬件队列 (TC) | 绑定的流控策略 | 流量类型范例 | 调度动作与协同逻辑 (TAS为基座) |
| :---- | :---- | :---- | :---- |
| **TC7** | CQF (Pong) | 周期性控制流 | TAS门控绝对控制：奇数时隙开，偶数关。 |
| **TC6** | CQF (Ping) | 周期性控制流 | TAS门控绝对控制：偶数时隙开，奇数关。 |
| **TC5** | TAS (单队) | 极紧急告警流 | 在全局 GCL 中预留极短绝对抢占窗口，不参与乒乓。 |
| **TC4** | CBS | 音视频 (Class A) | TAS门控常开(或非敏感期开)，发包受 CBS 积分严控。 |
| **TC3** | CBS | 音视频 (Class B) | 同上，但积分恢复速率 (idle\_slope) 低于 TC4。 |
| **TC0-2** | BE (尽力而为) | 普通上网数据 | 严格优先级，上方队列空闲且门开时才能“见缝插针”。 |

**四大巅峰联合优化模式**：

1. **带宽极限压榨：\[TAS\] \+ \[帧抢占\]**。宏观用 TAS 排表，微观用帧抢占消除保护频带。  
2. **防洪堤坝保护：\[PSFP\] \+ \[CBS\]**。入站用 PSFP 拦截超速，出站用 CBS 平滑，完美保护缓存。  
3. **高性价比混流：\[CQF\] \+ \[CBS\] \+ \[帧抢占\]**。无需排表，双缓冲打底，积分平滑视频，物理层防阻塞。  
4. **航天零容错架构：\[FRER\] \+ \[PSFP\] \+ \[TAS\]**。FRER 扛物理断线，PSFP 扛逻辑攻击，TAS 扛时间抖动。
