# 📚 TSN 核心流控机制与 C++ 仿真架构全景学习笔记

## 一、 TSN 诞生的历史背景与核心痛点

### 1.1 传统以太网的"尽力而为"与 CSMA/CD 陷阱

**底层机制**：传统以太网 (IEEE 802.3) 底层采用的是 **CSMA/CD（载波侦听多路访问/冲突检测）** 机制。

**物理隐喻**：它就像一个没有红绿灯的十字路口。数据包发送前先"听"网络是否空闲。如果两人同时发送发生冲突，双方必须立刻停止，并各自在心里随机默数一个时间（**二进制指数退避算法**）后再重传。

**致命缺陷**：
- 这种随机等待导致了网络**延迟（Latency）**和**抖动（Jitter）**完全不可控
- 在工业 4.0 的场景（如机械臂高速同步），哪怕 1 毫秒的随机抖动也会导致灾难性的设备碰撞
- 当网络拥堵时，内部 FIFO 队列塞满，还会导致严重的**丢包**

### 1.2 工业现场总线的"轮询"天花板

**底层机制**：传统的工业总线（如 CAN, Profibus）采用轮询（Polling）或中断机制。

**致命缺陷**：
1. **带宽极低**：通常在 Mbps 级别，无法承载现代工业的高清机器视觉图像和海量传感器数据
2. **扩展性差**：网络节点越多，主机轮询一圈的开销（Overhead）呈指数级上升，系统效率随规模扩大而急剧下降

### 1.3 协议孤岛与 TSN 的破局

**过渡期方案**：以 EtherCAT、TTEthernet 为代表的技术通过魔改以太网实现了实时性，但它们是私有协议，互不兼容，导致工厂内部 IT 网络和 OT 网络物理割裂。

**TSN 的终极使命**：基于 IEEE 802.1 标准的纯正以太网，通过引入精确的时间同步、出站流控、入站安检等机制，实现**"混合关键性流量的共网传输"**。让绝对准时的控制流和普通的视频/上网流量跑在同一根网线上，且互不干扰。

### 1.4 TSN 的核心价值总结

| 特性 | 传统以太网 | TSN |
|------|-----------|-----|
| 延迟确定性 | 无（尽力而为） | 有（微秒级） |
| 抖动控制 | 无 | 有 |
| 带宽利用率 | 低（冲突重传） | 高（无冲突） |
| 混合关键性 | 不支持 | 支持 |
| 标准性 | IEEE 802.3 | IEEE 802.1 |

## 二、 TSN 交换机整机流水线架构

### 2.1 数据包的完整生命周期

在底层软件架构设计中，一个数据包的完整生命周期经历以下五步严格的流水线：

```
┌─────────────────────────────────────────────────────────────┐
│            TSN 交换机数据包处理流水线                        │

│  │  ② 流门控：查时间窗口                                │   │
│  │  ③ 流计量器：查带宽，超速丢弃                        │   │
│  └─────────────────────────────────────────────────────┘   │
│                           │                                  │

│  ┌─────────────────────────────────────────────────────┐   │
```

### 2.2 基础设施层：VLAN 标签与优先级映射

**核心概念**：传统以太网帧没有优先级。TSN 的一切调度基于 VLAN 标签中的 PCP 字段。

**PCP 字段**：
- VLAN 标签中包含 3-bit 的 PCP (Priority Code Point)
- 3-bit 刚好表示 $0 \sim 7$ 共 8 个优先级
- 这完美映射到了现代 TSN 交换机出端口底层的 8 个硬件队列（TC0 到 TC7）

```
VLAN Tag 结构：

┌─────────┬─────────┬─────────┐
│  TPID   │  TCI    │ Length  │
│ (2Byte) │ (2Byte) │ /Type   │
└─────────┴────┬────┴─────────┘
               │
          ┌────┴────┐
          │ PCP=3bit │  ← 优先级代码点 (0-7)
          │ DEI=1bit │  ← 丢弃指示标志
          │ VID=12bit│  ← VLAN ID
          └─────────┘
```

### 2.3 C++ 数据结构设计

```cpp
/**
 * @brief VLAN 标签结构
 */
struct VlanTag {
    uint16_t tpid;      // Tag Protocol Identifier (0x8100)
    uint8_t  pcp : 3;   // 3-bit 优先级 (0-7)
    uint8_t  dei : 1;   // Drop Eligibility Indicator
    uint16_t vid : 12;  // 12-bit VLAN ID
};

/**
 * @brief 根据 VLAN PCP 映射到流量类
 * @param tag VLAN 标签
 * @return 流量类 (0-7)，对应 TC0-TC7 硬件队列
 */
int mapToTrafficClass(const VlanTag& tag) {
    return static_cast<int>(tag.pcp);
}
```

## 三、 入站安全与高可靠管线 (Ingress Pipeline)

数据包到达交换机 Rx 端口，尚未进入交换矩阵和队列排队前，必须通过安检与去重。

### 3.1 PSFP - 每流过滤与监管 (IEEE 802.1Qci)

**核心定位**：交换机的"安检大闸"。防范恶意攻击、终端故障引发的"流量洪峰"。实现防线前移，保护交换机内部宝贵的 RAM 缓存。

**三级防御流水线**：

| 层级 | 组件 | 功能 | 检查内容 |
|------|------|------|---------|
| 第1级 | 流过滤器 (Stream Filter) | 查身份 | 五元组、MAC 地址、VLAN ID |
| 第2级 | 流门控 (Stream Gate) | 查时间 | 是否在合法时间窗口内 |
| 第3级 | 流计量器 (Stream Meter) | 查带宽 | 是否超过承诺速率 |

**通俗理解**：PSFP 就像地铁站的"安检大闸"。每个进站乘客（数据包）都需要：
1. **查身份**：确认是否属于合法流
2. **查时间**：确认是否在规定时间窗口内到达
3. **查行李**：确认是否符合携带物品限制（带宽）

### 3.2 PSFP 核心组件详解

#### 3.2.1 流过滤器 (Stream Filter)

**功能**：基于数据包的特定标识识别其所属的流。

**流识别方式**：
- 源 MAC 地址 + VLAN ID
- 目标 MAC 地址 + VLAN ID
- IP 头部的五元组（源 IP、目标 IP、源端口、目标端口、协议号）
- TSN Stream ID

**关键概念：Stream Handle**
- 流过滤器将识别到的流映射到一个唯一的句柄（Stream Handle）
- 这个句柄用于索引后续的流门控和流计量器

#### 3.2.2 流门控 (Stream Gate)

**功能**：基于时间表控制流的发送窗口，超出时间窗口的帧将被丢弃。

**门控状态**：
- **Open (开启)**：允许帧通过
- **Closed (关闭)**：帧被丢弃

#### 3.2.3 流计量器 (Stream Meter)

**功能**：基于令牌桶算法检查流量是否超过预留带宽。

**关键参数**：
| 参数 | 说明 |
|------|------|
| Committed Information Rate (CIR) | 承诺信息速率（带宽上限） |
| Committed Burst Size (CBS) | 承诺突发大小（令牌桶容量） |

**计量结果处理**：
- **Conforming (符合)**：帧被标记为绿色，正常转发
- **Excess (超量)**：帧被标记为黄色，可能降级处理
- **Violating (违规)**：帧被标记为红色，直接丢弃

### 3.3 FRER - 帧复制与消除 (IEEE 802.1CB)

**核心定位**：工业级与航空级的极高可靠性"双保险"。用双倍的空间（链路带宽）换取 0% 的丢包率。

**通俗理解**：FRER 就像快递的"双重保险"机制。重要文件快递时，快递公司会：
1. **发送两份副本**：通过两条不同路线发送
2. **消除重复**：收件人收到第一份后，第二份直接拒收
3. **确保到达**：只要有一条路线正常，文件就能送达

### 3.4 FRER 工作原理详解

**运作机制**：
- **发端 (Talker)**：克隆数据包，打上 R-tag（包含递增的 Sequence Number 序列号），分别发往路径 A 和路径 B
- **收端 (Listener/Switch)**：维护已接收序号的历史记录哈希表。先到的包入库并放行，晚到的同序号克隆包直接消除（Drop）

**R-TAG 数据结构**：
```
以太网帧格式（含 R-TAG）：

┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
│ DA/SA   │ R-TAG   │ VLAN    │ Length/ │ Payload │ CRC     │
│         │         │ Tag     │ Type    │         │         │
└─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘
              ↑
        ┌─────┴─────┐
        │ Sequence  │  ← 16-bit 序列号
        │ Number    │
        └───────────┘
```

### 3.5 FRER 两种恢复算法

#### 3.5.1 Match Recovery Algorithm (MRA)

**原理**：只记录接收到的最高序列号

**限制**：适用于间歇性流（帧间隔 ≥ 接收窗口差异）

#### 3.5.2 Vector Recovery Algorithm (VRA)

**原理**：维护完整的历史窗口向量，能处理更复杂的场景

### 3.6 FRER 的网络拓扑要求

**关键要求**：网络必须能够形成**环路**，以提供冗余路径。

**适用架构**：Zonal 架构（区域架构），而非域控制器架构

## 四、 出站宏观调度大脑 (Egress Pipeline)

合法数据进入 TC0-TC7 八个队列后，这部分流控机制决定了"当前微秒，网卡到底把哪个队列的数据推向物理链路"。

### 4.1 TAS - 时间感知整形 (IEEE 802.1Qbv)

**机制**：极其严苛的"列车时刻表"。基于 802.1AS 全局时间同步，配置全局门控列表 (GCL)。精确到微秒控制 8 个队列传输门的开与关。

**特性**：提供极致的确定性超低延时。

**痛点**：全网排表是 NP-Hard 数学难题。网络拓扑越大，越难算出不冲突的完美时刻表。

### 4.2 CQF - 循环队列转发 (IEEE 802.1Qch)

**机制**：TAS 的高性价比降级平替方案。放弃全局精密排表，采用"双缓冲乒乓队列 (Double Buffering Ping-Pong Queues)"思想。

**运行逻辑**：
- 将同等优先级的流量绑定到 2 个硬件队列（如 Q0 和 Q1）
- 周期 $T_0$ (偶数时隙)：Q0 门开负责发送；Q1 门关负责接收上游数据
- 周期 $T_1$ (奇数时隙)：瞬间翻转。Q0 门关开始积攒数据；Q1 门开，排空刚才接收的数据
- **铁律**：上游时隙 $n$ 收到的包，必须在时隙 $n+1$ 发出

**工程代价**：消耗双倍的硬件队列资源（8个队列最多只能跑4种 CQF 流）。

**数学保障**：假设时隙为 $d$，经过 $h$ 跳，端到端时延下界为 $(h-1)d$，上界为 $(h+1)d$。

### 4.3 CBS - 基于信用的整形 (IEEE 802.1Qav)

**机制**：专为音视频流设计的平滑机制。防止视频突发瞬间饿死底端普通上网数据。

**规则**：
- 队列里没包：积分归零
- 正在发包：积分按斜率 $send\_slope$ 匀速下降。积分 $< 0$ 就不准发下一个包
- 有包等待但门关着：积分按斜率 $idle\_slope$ 匀速回升，直到 $> 0$ 恢复发包权限

### 4.4 ATS - 异步流量整形 (IEEE 802.1Qcr)

**机制**：终极兜底方案。彻底抛弃 802.1AS 全局时间同步。

**逻辑**：采用 UBS（基于紧急度的调度器）。不针对"队列"限速，而是针对网络里的"每一条流 (Per-Flow)"独立分配一个漏桶定时器。把杂乱无章的输入流量"整形"成平滑均匀的输出流。

**代价**：极其消耗交换机 CPU 和内存（需维护海量的 Per-Flow 状态机）。

## 五、 物理层微观防线 (MAC Sublayer)

### 5.1 帧抢占 (IEEE 802.1Qbu + 802.3br)

**核心痛点**：传输阻塞延时 (Transmission Blocking Delay)。如果 TAS 决定立刻发送紧急控制包，但网线上正堵着一个发了一半的 1500 字节普通长包，紧急包只能干等。

**传统妥协**：TAS 被迫设置极长的"保护频带 (Guard Band)"，在门控打开前提前禁止所有长包发送，导致大量带宽浪费。

**抢占机制**：
- 底层挂载 **eMAC (紧急引擎)** 和 **pMAC (普通引擎)**
- 紧急帧到达时，MAC 合并子层像切香肠一样，瞬间**截断**正在发送的长帧（分片为多个 mPacket），强制让紧急帧插队发送
- 紧急帧发送完毕后，重新缝合剩余的长帧片段

**巨大收益**：彻底消灭阻塞延时，大幅压缩 TAS 保护频带，带宽利用率激增 20% 以上。

### 5.2 MAC 层双引擎架构

| 引擎 | 全称 | 职责 | 处理帧类型 |
|------|------|------|-----------|
| **eMAC** | Express MAC | 处理紧急高优先级帧 | 快速帧 (Express Frame) |
| **pMAC** | Preemptable MAC | 处理普通可抢占帧 | 可被抢占帧 (Preemptable Frame) |

```
┌─────────────────────────────────────────────────────────────┐
│                  MAC 层双引擎架构                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  高优先级队列 ────────► eMAC ────────► 物理层 (PHY)         │
│         │                                                       │
│         │ 抢占控制                                             │
│         ▼                                                       │
│  ┌───────────────────────────────────────────────────────┐ │
│  │              MAC 合并子层 (MAC Merge)                  │ │
│  │                                                       │ │
│  │   接收 eMAC 和 pMAC 的帧，                            │ │
│  │   在物理层合并输出                                    │ │
│  └───────────────────────────────────────────────────────┘ │
│         ▲                                                       │
│         │                                                       │
│  低优先级队列 ────────► pMAC ────────►        │               │
```

## 六、 系统级联合调度方案

### 6.1 交换机端口队列映射

在真实的 C++ 交换机仿真模型中，一个物理端口的 8 个队列将发生如下复杂的调度映射：

| 硬件队列 (TC) | 绑定的流控策略 | 流量类型范例 | 调度动作与协同逻辑 (TAS为基座) |
|:------------|:-------------|:------------|:------------------------------|
| **TC7** | CQF (Pong) | 周期性控制流 | TAS门控绝对控制：奇数时隙开，偶数关 |
| **TC6** | CQF (Ping) | 周期性控制流 | TAS门控绝对控制：偶数时隙开，奇数关 |
| **TC5** | TAS (单队) | 极紧急告警流 | 在全局 GCL 中预留极短绝对抢占窗口，不参与乒乓 |
| **TC4** | CBS | 音视频 (Class A) | TAS门控常开(或非敏感期开)，发包受 CBS 积分严控 |
| **TC3** | CBS | 音视频 (Class B) | 同上，但积分恢复速率 (idle_slope) 低于 TC4 |
| **TC0-2** | BE (尽力而为) | 普通上网数据 | 严格优先级，上方队列空闲且门开时才能"见缝插针" |

### 6.2 四大巅峰联合优化模式

#### 6.2.1 带宽极限压榨：TAS + 帧抢占

**组合**：宏观用 TAS 排表，微观用帧抢占消除保护频带。

**效果**：大幅压缩 Guard Band，提升全网有效带宽利用率。

#### 6.2.2 防洪堤坝保护：PSFP + CBS

**组合**：入站用 PSFP 拦截超速，出站用 CBS 平滑。

**效果**：实现防线前移，保护交换机缓存资源。

#### 6.2.3 高性价比混流：CQF + CBS + 帧抢占

**组合**：无需排表，双缓冲打底，积分平滑视频，物理层防阻塞。

**效果**：配置简单，适用于大多数工业应用场景。

#### 6.2.4 航天零容错架构：FRER + PSFP + TAS

**组合**：FRER 扛物理断线，PSFP 扛逻辑攻击，TAS 扛时间抖动。

**效果**：实现最高级别的可靠性与实时性，适用于航空级应用。

## 八、 C++ 仿真架构设计

### 8.1 PSFP 令牌桶实现

```cpp
/**
 * @brief PSFP 令牌桶限速器
 */
class StreamMeter {
private:
    double tokens_;           // 当前桶内令牌数
    double burstSize_;        // 桶容量上限 (最大突发量)
    double cir_;              // 承诺信息速率 (令牌恢复速度)
    uint64_t lastUpdateTime_;

public:
    StreamMeter(double cir, double burstSize)
        : tokens_(burstSize), burstSize_(burstSize), 
          cir_(cir), lastUpdateTime_(0) {}

    bool consumeTokens(int packetSizeBytes, uint64_t currentTime) {
        double timeDelta = (currentTime - lastUpdateTime_) / 1e9;
        tokens_ += timeDelta * cir_;
        if (tokens_ > burstSize_) tokens_ = burstSize_;
        lastUpdateTime_ = currentTime;

        if (tokens_ >= packetSizeBytes) {
            tokens_ -= packetSizeBytes;
            return true;  // 放行
        }
        return false; // 超速，拦截丢弃
    }
};
```

### 8.2 FRER 消除器实现

```cpp
/**
 * @brief FRER 冗余消除器
 */
class FREREliminationEngine {
private:
    std::unordered_set<uint16_t> receivedHistory_;
    size_t historyMaxSize_ = 65536;

public:
    bool processPacket(Packet* pkt) {
        uint16_t seqNum = pkt->getSeqNum();
        if (receivedHistory_.find(seqNum) != receivedHistory_.end()) {
            pkt->drop();
            return false;
        }
        receivedHistory_.insert(seqNum);
        if (receivedHistory_.size() > historyMaxSize_) {
            receivedHistory_.clear();
        }
        return true;
    }
};
```

### 8.3 CQF 乒乓状态机实现

```cpp
/**
 * @brief CQF 乒乓状态机
 */
class CQFScheduler {
private:
    Queue* Q0_;  // 偶数队列 (如 TC7)
    Queue* Q1_;  // 奇数队列 (如 TC6)
    bool isEvenSlot_;

public:
    CQFScheduler() : isEvenSlot_(true) {
        Q0_ = new Queue();
        Q1_ = new Queue();
    }

    void onSlotTimerTriggered() {
        isEvenSlot_ = !isEvenSlot_;
        if (isEvenSlot_) {
            Q0_->setGateState(GateState::OPEN);
            Q1_->setGateState(GateState::CLOSED);
        } else {
            Q0_->setGateState(GateState::CLOSED);
            Q1_->setGateState(GateState::OPEN);
        }
    }

    void enqueue(Packet* pkt) {
        if (isEvenSlot_) Q1_->push(pkt);
        else Q0_->push(pkt);
    }
};
```

## 九、 面试高频问题与解答

### 9.1 基础问题

#### Q1：为什么传统以太网无法满足工业实时性需求？

**答案**：
- 传统以太网采用 CSMA/CD 机制，冲突后随机退避导致延迟不可控
- 二进制指数退避算法使重传时间呈指数增长，网络拥塞时延迟爆炸
- FIFO 队列满导致丢包，无法保证关键数据的到达时间
- 抖动 (Jitter) 完全不可预测，对实时控制是致命的

#### Q2：TSN 的核心价值是什么？

**答案**：
- **确定性延迟**：通过时间同步和精确调度，实现微秒级的确定延迟
- **混合关键性**：支持时间敏感流和普通流量共网传输，互不干扰
- **标准化**：基于 IEEE 802.1 标准，不同厂商设备可互操作
- **高可靠性**：通过 FRER 等机制提供冗余传输

#### Q3：TSN 交换机数据包处理流水线有哪些步骤？

**答案**：
1. **Ingress - PSFP**：入站安检（流过滤、门控、计量）
2. **Ingress - FRER**：冗余消除（序列号去重）
3. **Fabric**：交换与 VLAN PCP 映射
4. **Egress - TAS/CQF/CBS**：出站宏观调度
5. **MAC 层 - 帧抢占**：物理层微观防阻塞

### 9.2 PSFP 相关问题

#### Q4：PSFP 的三级防御流水线是什么？

**答案**：
1. **流过滤器 (Stream Filter)**：基于五元组等标识识别流的身份
2. **流门控 (Stream Gate)**：基于时间表检查是否在合法时间窗口内
3. **流计量器 (Stream Meter)**：基于令牌桶算法检查是否超速

#### Q5：PSFP 在 TSN 架构中的作用是什么？

**答案**：
- 位于 Ingress（入端口），是交换机的第一道安检防线
- 防止异常流量（恶意攻击、终端故障、配置错误）进入核心交换架构
- 保护交换机宝贵的 RAM 缓存资源
- 确保关键流量的服务质量不被影响

### 9.3 FRER 相关问题

#### Q6：FRER 的核心原理是什么？

**答案**：
- **发送端复制**：为每个帧添加 R-TAG（包含 Sequence Number），通过多条冗余路径发送副本
- **接收端消除**：维护序列号历史窗口，第一个到达的帧被接收，后续重复帧被丢弃
- **关键数据结构**：R-TAG（冗余标签），包含 16-bit 序列号

#### Q7：FRER 对网络拓扑有什么要求？

**答案**：
- 网络必须能够形成**环路**，以提供冗余路径
- FRER 本身不创建冗余路径，需要网络拓扑本身具有环路
- 常用于 Zonal 架构（区域架构），而非域控制器架构

### 9.4 TAS/CQF 相关问题

#### Q8：TAS 和 CQF 的区别是什么？

**答案**：
| 特性 | TAS | CQF |
|------|-----|-----|
| 调度方式 | 基于 GCL 门控列表 | 基于时隙轮转 |
| 配置复杂度 | 高 (NP-Hard) | 中等 |
| 硬件消耗 | 1 队列/优先级 | 2 队列/优先级 |
| 延迟特性 | 完全固定 | 有 $2d$ 抖动范围 |
| 同步要求 | 高精度时钟同步 | 频率同步即可 |

#### Q9：为什么说 CQF 是 TAS 的"降级平替"？

**答案**：
- TAS 需要计算极其复杂的全局门控列表，多节点协调是 NP-Hard 问题
- CQF 只需全网同步周期时间，无需复杂计算
- 实现简单，配置容易，维护成本低
- 代价是每个优先级需要消耗 2 个硬件队列

### 9.5 帧抢占相关问题

#### Q10：帧抢占的原理是什么？有什么好处？

**答案**：
- 由 IEEE 802.1Qbu 和 IEEE 802.3br 联合定义
- 在 MAC 层引入双引擎：eMAC（处理高优先级帧）和 pMAC（处理低优先级帧）
- 当高优先级帧到达时，可以"切断"正在传输的低优先级长帧
- **好处**：彻底消灭阻塞延时，大幅压缩 TAS 保护频带，带宽利用率激增 20% 以上
