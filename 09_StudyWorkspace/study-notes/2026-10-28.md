# 二、C++ Stage 1｜BST 最近公共祖先原理

## 2.1 题意与前置知识

题目：[LeetCode 235：二叉搜索树的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-search-tree/)。

最近公共祖先（Lowest Common Ancestor，LCA）是同时作为两个目标节点 `p`、`q` 的祖先、并且**在这些公共祖先中最深**的节点。**一个节点可以作为它自己的祖先**，这也是 `p` 本身是 `q` 的祖先时能够直接返回 `p` 的依据。

BST 的有序性质（题目中的节点值互不相同）：

- 左子树每个节点值小于当前节点值；
- 右子树每个节点值大于当前节点值；
- 左右子树也分别满足 BST 性质。

因此，当 `p` 和 `q` 都小于当前节点时，最近公共祖先必定位于左子树；都大于当前节点时，必定位于右子树；**否则当前节点就是分叉点，或者当前节点自身等于 `p`/`q`，可以直接返回**。

经典示例树：

```text
           6
         /   \
        2     8
       / \   / \
      0   4 7   9
         / \
        3   5
```

## 2.2 检查题 1：分别求三个最近公共祖先

**问题：** 求 `p=3,q=5`；`p=0,q=5`；`p=7,q=9` 的最近公共祖先，并说明搜索过程。

**我的回答（准确原话）：**

> 1. `p = 3, q = 5` 的最近公共祖先。3 < 6, 5 < 6，均位于6的左子树，故6不是最近公共祖先，3 > 2, 5 > 2，均为与2的右子树，故2不是最近的公共祖先，3 < 4，5 > 4，4为最近的公共祖先。
> 2. `p = 0, q = 5` 的最近公共祖先。0 < 6, 5 < 6, 均位于6的左子树，故6不符合要求，0 < 2, 5 > 2，故2为最近公共祖先
> 3. `p = 7, q = 9` 的最近公共祖先。7 > 6, 9 > 6,均位于6的右子树，故6不符合要求，7 < 8, 9 > 8，故8为最近公共祖先

**订正：** 三个答案完全正确，分别为 **4、2、8**。措辞需要更严谨：根节点 6 仍然是这些节点对的**公共祖先**，只是并非最深的那个，所以“不符合要求”应表述为“不是**最近**公共祖先”。

**相关示例：** 对 `p=3,q=5`：`6 → 2 → 4`。到达 4 时，一个目标在左，一个在右，无需真正递归到 3、5 即可返回 4。

**面试专用回答：** BST 中两个目标都小于当前节点时向左搜索；都大于当前节点时向右搜索；首次无法继续共同向同一侧搜索时，当前节点就是最近公共祖先。

## 2.3 检查题 2：节点自身也可以是祖先

**问题：** 当 `p=2,q=5` 时，为什么答案是 2 而不是 6？

**我的回答（准确原话）：**

> 题目要求的是最近的公共祖先，即所有公共祖先中最深的，6肯定满足公共祖先这一要求，但并不一定是最深的，当p = 2, q = 5时，此时p的右子树含有q，故p节点本身就是q的祖先，然后任意节点是其自身的祖先，所以p是满足公共祖先这一要求的，而题目要求最近，故需要选择最深的那个公共祖先，而这种情况下最近的公共祖先就是节点2，而不是节点6

**订正：** 完全正确。节点 2 是自身的祖先，也是节点 5 的祖先；比节点 6 更深，因此 LCA 为 **2**。

**相关示例：** 如果搜索过程中 `root == p`（或在本题的唯一节点值条件下 `root->val == p->val`），且 `q` 位于它的子树内，那么直接返回 `root`，无须继续往下。

**面试专用回答：** 最近公共祖先允许是目标节点自身；当其中一个目标节点位于另一个目标节点的子树中时，较高的目标节点就是最近公共祖先。

## 2.4 检查题 3：搜索方向与复杂度

**问题：** 当前节点为 10。`p=3,q=7` 时怎么办？`p=6,q=15` 时怎么办？为什么复杂度为 `O(h)`？

**我的回答（准确原话）：**

> 1. 如果 `p->val = 3`、`q->val = 7`，应该向左、向右，还是直接返回当前节点？向左，因为这两个节点均在当前节点的左子树中，所以应该继续向左搜索是否还有更深的公共祖先。
> 2. 如果 `p->val = 6`、`q->val = 15`，应该怎么处理？直接返回当前节点，因为这是一个分界点，从此节点开始，p进入左子树，q进入右子树，无论向哪个方向搜索都不会再出现p和q的公共祖先了，所以当前节点就是最深的公共祖先。
> 3. 为什么 BST 最近公共祖先的时间复杂度可以写成 `O(h)`，而不是普通二叉树遍历的 `O(n)`？因为利用BST的特性，每次搜索最坏都只会沿一条根节点到遍历到叶子节点，所以时间复杂度即一条最长路径的节点个数，即树的高度O(h)，不需要遍历所有节点的O(n)

**订正：** 全部正确。`3,7` 都比 10 小，向左；`6,15` 分属两侧，直接返回当前节点。`O(h)` 是沿一条向下路径访问至多 `h` 层，不是遍历所有 `n` 个节点。

**相关示例：** 高度平衡 BST 的 `h=O(log n)`，所以时间 `O(log n)`；退化成链表时 `h=O(n)`，最坏 `O(n)`。普通 BST **不能保证**高度平衡。

**面试专用回答：** BST 的有序性质使每一步只需要选择左或右一条分支，最多经过树高 `h` 个节点，因此时间 `O(h)`；递归栈空间 `O(h)`，迭代可以做到额外空间 `O(1)`。

**Stage 1 验收：** 三道理解检查全部正确，进入独立编码。

# 三、C++ Stage 2｜LC235 独立实现与 Accepted

## 3.1 我的独立提交代码（原样保留）

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        int m = max(p -> val, q -> val);
        int l = min(p -> val, q -> val);
        int current = root -> val;
        if(current == p -> val || current == q -> val || (current > l && current < m)){
            return root;
        }
        if(current > m){
            return lowestCommonAncestor(root -> left, p, q);
        }
        else if(current < l){
            return lowestCommonAncestor(root -> right, p, q);
        }
        return nullptr;
    }
};
```

> 提交成功

**实际验收：LeetCode Accepted。** 本次没有提供具体耗时、内存百分位，因此不记录这些数据。

## 3.2 原理解读

先定义 `l = min(p->val,q->val)`、`m = max(p->val,q->val)`，将 p 和 q 的顺序归一化。

- `current > m`：p、q 都在当前节点左侧，递归左子树。
- `current < l`：p、q 都在当前节点右侧，递归右子树。
- `l <= current <= m`：当前节点是分叉点，或者恰好是其中一个目标，返回 `root`。

**今天借用了 Day50 LC230 的一个关键经验：** 用户写了 `return lowestCommonAncestor(root->left,p,q)` 和 `return lowestCommonAncestor(root->right,p,q)`，把子递归返回的节点指针正确地继续传给上层，没有犯“调用递归却丢弃返回值”的错误。

## 3.3 边界条件

- 返回值是 **`TreeNode*` 节点指针**，不是 `root->val` 整数。
- 一个目标可以等于当前节点，直接返回它。
- LC235 题目保证 `p`、`q` 均存在于 BST 中、目标节点非空且节点值唯一；在这个前提下，用户代码不会沿错误路径递归到空节点。用于通用库代码时，应另外设计空指针与目标不存在的处理方式。
- 用户代码最后 `return nullptr;` 在上述题目约束下是兜底分支，实际不会走到。
- 在本地独立编译、脱离 LeetCode 环境时，使用 `std::min/std::max` 需考虑包含 `<algorithm>`。

## 3.4 精简版（讲解建议，不代表第二次提交）

用户原代码已 Accepted，无需为简化重新提交。可将分叉判断简化为 `l <= current <= m`，进而采用：

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        int l = min(p->val, q->val);
        int m = max(p->val, q->val);
        if (root->val > m) {
            return lowestCommonAncestor(root->left, p, q);
        }
        if (root->val < l) {
            return lowestCommonAncestor(root->right, p, q);
        }
        return root;
    }
};
```

**复杂度：** 时间 `O(h)`；递归额外空间 `O(h)`。平衡时 `O(log n)`，退化时最坏 `O(n)`。使用循环和指针还可以实现 `O(1)` 额外空间，但今天不另开新 Stage。

**面试专用回答：** BST 最近公共祖先从根节点开始；若两个目标值均小于当前值，走左子树；均大于当前值，走右子树；否则当前节点就是最深分叉点，或当前节点本身是目标节点，直接返回。每次仅走一条路径，时间 `O(h)`、递归空间 `O(h)`。

# 七、核心理解检查｜先初始化表，还是先创建 Repository？

## 7.1 用户的问题

> 我有个问题，先// 复用现有Repository
> 	repo := NewStudentRepository(db)再// 数据库连接正常后，确保 students 表存在
> 	if err := initStudentTable(db); err != nil {
> 		log.Fatalf("initialize students table failed: %v", err)
> 	}可以吗？

### 订正

**当前项目可以这样写。** 因为真实的构造函数只是保存句柄：

```go
func NewStudentRepository(db *sql.DB) *StudentRepository {
    return &StudentRepository{db: db}
}
```

这一行不执行 SQL，也不立即访问 `students` 表。因此先构造一个仅持有数据库句柄的 Repository，再调用 `initStudentTable(db)`，只要在初始化完成前**不使用 Repository 执行 CRUD**，仍可正常工作。

**更推荐**先初始化表、再创建 Repository、最后启动服务。这是依赖准备的工程习惯，而不是当前版本的语法强制要求。

## 7.2 我的进一步理解（准确原话）

> 意思是Repository可能已经会执行相关的SQL语句对数据库进行操作了，但是如果将initStudentTable()放在创建Repository后就会出现我先用数据库再初始化数据库的问题，所以必须先初始化把数据库结构初始化好，再创建Repository使其能够正确的操作初始化好的数据库，即先将东西准备好，再给别人用（别人怎么用是通过db *sql.DB获取操作数据库的权力）。

### 订正

整体方向正确，“先把东西准备好，再给别人用”的概括很好，但有两个技术限定：

1. **并非所有 Repository 构造器都会执行 SQL。** 当前项目的 `NewStudentRepository()` 只存储 `db`，所以先构造并非立即“使用数据库”。如果未来构造器添加表存在性检查、预查询或其他 SQL，先构造就可能因表尚不存在而失败。
2. **`*sql.DB` 更准确地说是管理数据库连接池的数据库句柄。** 它提供 `Exec`、`Query`、`QueryRow`、`Ping` 等操作入口，不是数据库自身，也不等于 SQL 表结构。`sql.Open()` 获取句柄；`initStudentTable()` 准备 `students` 表；Repository 保存句柄供后续数据库操作使用。

### 相关示例

假设未来构造器改为在创建时查询：

```go
func NewStudentRepository(db *sql.DB) (*StudentRepository, error) {
    var count int
    err := db.QueryRow("SELECT COUNT(*) FROM students").Scan(&count)
    if err != nil {
        return nil, err
    }
    return &StudentRepository{db: db}, nil
}
```

这只是**假设扩展示例，并非当前实际源码**。若在没有表的情况下先执行该构造器，就会出现类似 `no such table: students` 的错误。

### 面试专用回答

项目启动时先取得 `*sql.DB` 数据库句柄、检查连接，再初始化业务所需的表结构，然后构造 Repository、注册 HTTP 路由并启动服务。当前 Repository 构造函数只保存 `*sql.DB`，先构造在技术上也可行；但先准备依赖再创建业务组件，使启动顺序清晰，能适应未来构造器需要执行 SQL 的扩展。

# 八、Day51 易错点、排错与工程边界

| 问题 | 订正 / 当前结论 |
|---|---|
| “6 不符合公共祖先要求” | 6 是公共祖先，但**不是最近**公共祖先。 |
| LCA 返回节点值还是指针？ | LC235 返回 **`TreeNode*`**，不是 `int`。 |
