# 三、Stage 1：从 Next Greater Element 开始

## 3.1 问题定义

给定：

```text
2 1 2 4 3
```

对于每个元素，寻找：

> 右边第一个严格大于当前元素的值。

结果：

```text
原数组：
2 1 2 4 3

答案：
4 2 4 -1 -1
```

例如：

```text
第一个 2
↓
右边依次是 1、2、4、3
↓
第一个严格大于 2 的是 4
↓
答案 = 4
```

注意：

> Next Greater Element 是“第一个更大的元素”，而不是“右边最大的元素”。

例如：

```text
2 3 100
```

对于 `2`：

```text
答案 = 3
```

而不是：

```text
100
```

---

## 3.2 暴力解法

最直接的方法：

对于每一个：

```text
nums[i]
```

从：

```text
i + 1
```

开始不断向右扫描。

找到第一个：

```cpp
nums[j] > nums[i]
```

立即停止。

---

## 3.3 暴力代码

文件：

```text
next_greater_bruteforce.cpp
```

完整代码：

```cpp
#include <iostream>
#include <vector>

using namespace std;

int main()
{
    // nums中的每一个元素，
    // 都要寻找：
    //
    // “右边第一个严格大于它的元素”
    //
    // 如果不存在，答案为-1。
    vector<int> nums{
        2, 1, 2, 4, 3
    };

    // answer[i]：
    //
    // nums[i]右边第一个更大的元素。
    //
    // 默认值先全部设置为-1，
    // 表示暂时没有找到。
    vector<int> answer(
        nums.size(),
        -1
    );

    // --------------------------------------------------
    // 暴力方法
    // --------------------------------------------------
    //
    // 对于每一个nums[i]，
    // 从i + 1开始向右扫描。
    for (int i = 0;
         i < static_cast<int>(nums.size());
         ++i)
    {
        for (int j = i + 1;
             j < static_cast<int>(nums.size());
             ++j)
        {
            // 找到右边第一个严格更大的元素。
            if (nums[j] > nums[i])
            {
                answer[i] =
                    nums[j];

                // 题目要求的是“第一个”更大的元素，
                // 所以找到以后必须立即停止。
                break;
            }
        }
    }

    cout << "nums:   ";

    for (int value : nums)
    {
        cout << value << ' ';
    }

    cout << endl;

    cout << "answer: ";

    for (int value : answer)
    {
        cout << value << ' ';
    }

    cout << endl;

    return 0;
}
```

## 4.1 `nums.size()` 的类型

```cpp
nums.size()
```

返回的通常不是：

```text
int
```

而是：

```text
size_t
```

`size_t` 可以暂时理解为：

> 专门用于表示对象大小、容器长度等信息的无符号整数类型。

所以：

```cpp
int i = 0;

i < nums.size();
```

实际上是在比较：

```text
int
vs
size_t
```

也就是：

```text
signed
vs
unsigned
```

这种混合比较容易产生：

- Compiler Warning
- 边界问题
- 负数转换问题

---

## 4.2 `static_cast`

语法：

```cpp
static_cast<目标类型>(原值)
```

例如：

```cpp
double value = 3.14;

int number =
    static_cast<int>(value);
```

结果：

```text
number = 3
```

所以：

```cpp
static_cast<int>(nums.size())
```

就是：

> 明确要求把 `nums.size()` 返回的值转换成 `int`。

---

## 4.3 为什么算法代码常写

```cpp
int n =
    static_cast<int>(
        nums.size()
    );
```

因为算法题中经常需要：

```text
下标 - 1
返回 -1
从右向左遍历
```

使用 `int` 通常比较方便。

后续更推荐：

```cpp
int n =
    static_cast<int>(
        nums.size()
    );

for (int i = 0; i < n; ++i)
{
}
```

而不是重复写：

```cpp
static_cast<int>(nums.size())
```

---

## 4.4 `static_cast` 核心记忆

```text
static_cast<T>(value)

=
显式把 value 转换成 T 类型
```

例如：

```cpp
int n =
    static_cast<int>(
        nums.size()
    );
```

# 六、Stage 2：真正实现 Monotonic Stack

## 6.1 思维变化

暴力：

```text
旧元素
↓
主动向未来搜索自己的答案
```

单调栈：

```text
旧元素没有答案
↓
进入Stack等待

未来新元素到来
↓
由新元素反过来解决旧元素
```

核心思想：

> 不让每个旧元素反复向右搜索，而保存尚未解决对象，等待未来的新元素来解决。

---

## 6.2 为什么保存 Index

Stack 中保存：

```text
Index
```

而不是只保存：

```text
Value
```

原因：

### 原因 1：数组可能有重复值

例如：

```text
2 1 2 4
```

两个：

```text
2
```

只保存值无法区分具体位置。

### 原因 2：最终需要知道给哪个答案位置赋值

通过：

```cpp
nums[index]
```

可以获得原值。

通过：

```cpp
answer[index]
```

可以写对应答案。

所以：

```text
Index
↓
同时连接 nums 和 answer
```

---

## 6.3 核心代码

```cpp
while (
    !st.empty() &&
    nums[i] > nums[st.top()]
)
{
    answer[st.top()] =
        nums[i];

    st.pop();
}

st.push(i);
```

翻译成人话：

```text
Stack还有未解决对象吗？
↓
当前元素能解决栈顶吗？
↓
能
↓
写答案
↓
pop
↓
继续看新的top
```

为什么是：

```cpp
while
```

而不是：

```cpp
if
```

因为：

> 一个新的更大元素可能连续解决多个旧元素。

---

## 6.4 完整代码

文件：

```text
next_greater_stack.cpp
```

```cpp
#include <iostream>
#include <stack>
#include <vector>

using namespace std;

int main()
{
    vector<int> nums{
        2, 1, 2, 4, 3
    };

    int n =
        static_cast<int>(
            nums.size()
        );

    // 如果最终没有找到右边更大的元素，
    // 默认保持-1。
    vector<int> answer(
        n,
        -1
    );

    // Stack保存下标。
    //
    // 这些下标对应的元素：
    // 已经扫描到，
    // 但还没有找到Next Greater Element。
    stack<int> st;

    for (int i = 0; i < n; ++i)
    {
        while (
            !st.empty() &&
            nums[i] > nums[st.top()]
        )
        {
            int unresolvedIndex =
                st.top();

            answer[unresolvedIndex] =
                nums[i];

            st.pop();
        }

        // 当前元素自己暂时还没有答案，
        // 所以进入Stack等待未来元素。
        st.push(i);
    }

    cout << "nums:   ";

    for (int value : nums)
    {
        cout << value << ' ';
    }

    cout << endl;

    cout << "answer: ";

    for (int value : answer)
    {
        cout << value << ' ';
    }

    cout << endl;

    return 0;
}
```

# 八、Stage 3：为什么 `for + while` 仍然是 O(n)

## 8.1 不能通过循环层数直接判断复杂度

看到：

```cpp
for (...)
{
    while (...)
    {
    }
}
```

不能机械判断：

```text
O(n²)
```

真正需要分析：

> 每一个元素在整个算法生命周期里到底被处理了多少次。

---

## 8.2 每个元素的生命周期

一个元素：

```text
最多 push 1 次
最多 pop 1 次
```

所以 n 个元素：

```text
push ≤ n
pop ≤ n
```

总操作数量：

```text
≤ 2n
```

因此：

```text
O(2n)
→ O(n)
```

---

## 8.3 为什么某一次 while 很长也没关系

例如：

```text
5 4 3 2 1 100
```

扫描到：

```text
100
```

时：

```text
while
```

可能连续执行 5 次。

但：

```text
1
2
3
4
5
```

一旦被 pop：

> 永远不会重新进入 Stack。

所以这 5 次操作不会在以后重复发生在这些元素上。

# 九、Amortized Analysis

术语：

```text
Amortized Analysis
摊还分析
```

今天不需要数学化定义。

当前理解：

> 不能只看某一次操作最坏需要多少工作，而应该观察整个算法过程中所有相关操作总共发生多少次。

Monotonic Stack：

```text
每个元素push一次
最多pop一次
↓
总操作O(n)
```

---

## 9.1 和 Sliding Window 的联系

今天主动联想到可变长度 Sliding Window。

Sliding Window：

```text
right只向右移动
left也只向右移动
```

虽然代码可能：

```cpp
for (...)
{
    while (...)
    {
    }
}
```

但是：

```text
left总移动次数 ≤ n
right总移动次数 ≤ n
```

所以仍然：

```text
O(n)
```

Monotonic Stack：

```text
push总次数 ≤ n
pop总次数 ≤ n
```

所以：

```text
O(n)
```

共同思想：

> 复杂度应该分析实际总操作次数，而不能简单根据嵌套循环层数判断。

# 十、复杂度观察实验

文件：

```text
monotonic_stack_count_demo.cpp
```

完整代码：

```cpp
#include <iostream>
#include <stack>
#include <vector>

using namespace std;

int main()
{
    vector<int> nums{
        2, 1, 2, 4, 3
    };

    int n =
        static_cast<int>(
            nums.size()
        );

    vector<int> answer(
        n,
        -1
    );

    stack<int> st;

    int pushCount = 0;
    int popCount = 0;

    for (int i = 0; i < n; ++i)
    {
        cout << "scan nums["
             << i
             << "] = "
             << nums[i]
             << endl;

        while (
            !st.empty() &&
            nums[i] > nums[st.top()]
        )
        {
            int unresolvedIndex =
                st.top();

            cout << "  solve nums["
                 << unresolvedIndex
                 << "] = "
                 << nums[unresolvedIndex]
                 << " with "
                 << nums[i]
                 << endl;

            answer[unresolvedIndex] =
                nums[i];

            st.pop();
            ++popCount;
        }

        st.push(i);
        ++pushCount;

        cout << "  push index "
             << i
             << endl;

        cout << endl;
    }

    cout << "answer: ";

    for (int value : answer)
    {
        cout << value << ' ';
    }

    cout << endl;

    cout << "push count = "
         << pushCount
         << endl;

    cout << "pop count = "
         << popCount
         << endl;

    cout << "total stack operations = "
         << pushCount + popCount
         << endl;

    return 0;
}
```

预期关键输出：

```text
push count = 5
pop count = 3
total stack operations = 8
```

核心观察：

```text
push ≤ n
pop ≤ n
```

# 十一、Stage 3 检查

## 问题 1

为什么 `for + while` 不能直接判断为 O(n²)？

### 我的回答

> 因为实际的复杂度要看在整个操作过程中每个元素实际被操作多少次，而不是单单看嵌套了几层循环，类似可变长度滑动窗口，只需要看每个元素被操作的次数

### 订正

完全正确。

这是今天非常重要的一次知识迁移。

### 相关示例

Sliding Window：

```text
left最多移动n次
right最多移动n次
```

Monotonic Stack：

```text
push最多n次
pop最多n次
```

### 面试专用回答

> 嵌套循环并不一定意味着 O(n²)。需要分析内层循环在整个算法生命周期中的累计执行次数。单调栈中每个元素最多入栈一次、出栈一次，因此所有 while 的累计工作量仍然是 O(n)。

---

## 问题 2

一个元素最多 push/pop 几次？与 O(n) 有什么关系？

### 我的回答

```text
最多push n次
最多pop n次
```

> 叠加后O(n + n) = O(2n) 去掉常数 = O(n)

### 订正

总体结论正确，但语言需要精确。

应该是：

```text
每个元素：
最多push 1次
最多pop 1次

所有n个元素：
push最多n次
pop最多n次
```

所以：

```text
O(n + n)
=
O(2n)
=
O(n)
```

### 相关示例

有 100 个元素：

```text
push最多100次
pop最多100次
```

总 Stack 操作不会变成：

```text
100 × 100
```

### 面试专用回答

> 每个元素最多入栈一次，并且一旦出栈不会重新入栈，因此所有元素的总入栈次数和总出栈次数都最多为 n，整体时间复杂度为 O(n)。

---

## 问题 3

为什么 `100` 一次 pop 很多元素仍然不是 O(n²)？

### 我的回答

> 因为一次操作多次并不代表以后每次都要操作多次，这涉及到摊还分析，整体复杂度还是需要看整个过程中元素总体操作次数

### 订正

完全正确。

### 相关示例

```text
5 4 3 2 1 100
```

虽然 `100` 到来时：

```text
while执行5次
```

但是被 pop 的：

```text
1 2 3 4 5
```

之后不会再被处理。

### 面试专用回答

> 单次迭代可能弹出多个元素，但这些元素被弹出后不会再次进入栈，因此不能把一次 O(n) 的 while 机械乘以外层 n。累计所有 pop 的次数仍然最多是 n。

---

## 问题 4

如何理解 Amortized Analysis？

### 我的回答

> 不能只看某一次while，而要看整个过程中所有push/pop的总次数

### 订正

完全正确。

### 相关示例

某一次：

```text
while运行5次
```

不代表：

```text
以后每一次外层循环都运行5次
```

应该分析：

```text
整个算法总共运行多少次
```

### 面试专用回答

> 摊还分析关注一系列操作在整个执行过程中的总成本，而不是单独看某一次操作的最坏成本。单调栈中虽然某次 while 可能执行多次，但所有元素累计最多 push 和 pop 各一次，因此总体仍为 O(n)。

# 十五、用户独立完成代码

文件：

```text
leetcode_739_daily_temperatures.cpp
```

用户完成：

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = static_cast<int> (temperatures.size());
        vector<int> answer(n, 0);
        stack<int> s;

        for(int i = 0; i < n; i++){
            while(!s.empty() && temperatures[i] > temperatures[s.top()]){
                answer[s.top()] = i - s.top();
                s.pop();
            }
            s.push(i);
        }

        return answer;
    }
};
```

该实现正确。

# 十六、LeetCode 739 检查

## 问题

对于：

```text
73 74 75 71 69 72 76 73
```

为什么扫描到 `76` 时，它能够连续解决多个还留在 Stack 中的温度？

### 我的回答

> 因为通过单调栈保存所有未找到下一个更高温度的温度下标，通过while和pop比较新位置下的温度和栈里的保存的对应温度，一次性解决多个还留在stack中的温度

### 订正

正确。

更精确：

> Stack 保存已经扫描但尚未找到下一更高温度的下标。新温度到来以后，通过 while 不断和栈顶下标对应的温度比较，如果当前温度更高，就说明栈顶那一天已经找到答案，因此计算距离并 pop，然后继续检查新的栈顶。

这里：

```text
一次性解决多个
```

是指：

```text
同一个新元素
↓
通过多次while
↓
连续解决多个旧元素
```

而不是一个 `pop()` 删除多个元素。

---

### 相关示例

扫描到：

```text
76
```

之前剩余的重要未解决元素：

```text
75
72
```

分别位于：

```text
index 2
index 5
```

所以：

```text
76 > 72
→ answer[5] = 6 - 5 = 1
→ pop

76 > 75
→ answer[2] = 6 - 2 = 4
→ pop
```

---

### 面试专用回答

> Daily Temperatures 本质上是 Next Greater Element 的位置距离变体。单调栈保存尚未找到更高温度的下标，当当前温度高于栈顶下标对应温度时，就计算 `i - oldIndex` 作为等待天数，并持续弹出所有能够被当前温度解决的旧下标。每个下标最多入栈和出栈一次，因此时间复杂度为 O(n)，空间复杂度为 O(n)。

### 我的回答
