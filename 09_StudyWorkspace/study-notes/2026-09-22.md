# 五、使用 unordered_map 统计频率

定义：

```cpp
unordered_map<int, int> frequency;
```

含义：

```text
key
→ 原数组中的元素

value
→ 该元素出现的次数
```

统计：

```cpp
for (int value : nums)
{

}
```

# 六、为什么 `++frequency[value]` 可以统计次数？

第一次出现某个元素：

```cpp
frequency[value]
```

如果 key 不存在：

```text
unordered_map::operator[]
```

会创建这个 key，并将对应的 `int` 默认初始化为：

```text
0
```

然后：

```cpp
++frequency[value];
```

变成：

```text
1
```

以后每再次遇到这个元素：

```text
1 → 2 → 3 → ...
```

因此最终：

```text
frequency[value]
```

就是：

```text
该元素总出现次数
```

# 八、Stage 1 检查 1

## 问题

为什么 Top K Frequent 不能像 Top K Largest 一样，一开始就把原数组元素直接放进 Heap？

## 我的回答

> 因为Top K Frequent 要记录元素出现的次数，而不是元素本身的值，一开始就把原数组元素直接放进 Heap  无法知道保存的元素的出现次数。

## 订正

完全正确。

Top K Largest：

```text
排名依据
→ 原始元素值
```

所以原始元素可以直接进入 Heap。

Top K Frequent：

```text
排名依据
→ frequency
```

单独看到：

```text
8
```

并不知道：

```text
8出现了几次
```

因此必须先：

```text
完整扫描nums
↓
统计frequency
```

再进行 Heap Top K。

## 相关示例

数组：

```text
100 1 1 1 1 1
```

按照元素值：

```text
100 > 1
```

但按照 frequency：

```text
100 → 1次
1   → 5次
```

所以：

```text
Top Frequent
→ 1
```

而不是：

```text
100
```

## 面试专用回答

> Top K Frequent 的排名依据是元素出现频率，而不是元素值本身，因此需要先通过哈希表统计每个元素的 frequency，再基于 frequency 使用 Heap 维护 Top K。

# 九、Stage 1 检查 2

## 问题

对于：

```cpp

```

## 订正

完全正确。

```text
8
```


# 十一、Stage 1 检查 4

## 问题

## 订正

核心完全正确。



门槛：



# 二十二、Stage 2 检查 3

## 问题

为什么：

```cpp
minHeap.push({count, value});

    minHeap.pop();
```

> 因为当minheap的大小超过k个时，就会将当前内部出现频率最小的元素踢出，只保留目前出现过的所有元素中出现频率最高的K个元素

完全正确。

# 二十三、Stage 2 检查 4：复杂度

## 问题

设：

```text
n
→ 原数组长度

m
→ 不同元素数量

k
→ Heap大小
```

为什么：

```text
时间
O(n + m log k)

额外空间
O(m + k)
```

？

## 我的回答

> 时间：首先遍历原数组元素并记录到哈希表中 O(n) 再遍历m个不同元素并将其维护到minheap中 O(mlogk) 所以总时间为O(n + m log k)，而空间即原数组大小O(n)，哈希表大小O(m)，故额外空间：O(m + k).
>
> 最坏情况下：m=n故O(n + n logk) = O(nlogk) ,O(m + k) = O(n + k) = O(n) (k一般不超过n且比n小很多）

## 订正

时间复杂度推导正确。

第一步：

```text
遍历nums
→ O(n)
```

第二步：

```text
m个不同元素
×
每次Heap操作O(log k)
→ O(m log k)
```

所以：

```text
O(n + m log k)
```

最坏：

```text
m = n
```

所以：

```text
O(n log k)
```

---

额外空间部分最终答案：

```text
O(m + k)
```

也是正确的。

但中间有一个重要修正：

```text
nums
```

本身属于题目输入。

计算：

```text
额外空间复杂度
```

时通常不计算输入数组本身。

真正额外创建：

```text
unordered_map
→ O(m)

Min Heap
→ O(k)
```

因此：

```text
O(m + k)
```

最坏：

```text
m = n
```

并且：

```text
k <= m <= n
```

因此：

```text
O(n + k)
=
O(n)
```

这里不是因为：

```text
k通常比n小很多
```

才得到 `O(n)`。

而是因为：

```text
k <= n
```

所以即使：

```text
k = n
```

：

```text
O(n+n)
=
O(n)
```

仍然成立。

## 相关示例

如果：

```text
n = 100
m = 100
k = 100
```

：

```text
Hash Map
→ 100

Heap
→ 100
```

：

```text
O(100 + 100)
=
O(n)
```

并不要求：

```text
k << n
```

## 面试专用回答

> 统计 frequency 需要遍历 N 个元素，平均时间为 O(N)；随后遍历 M 个不同元素，每个元素在大小最多为 K 的 Heap 中进行 O(log K) 操作，因此总时间复杂度为 O(N + M log K)，最坏情况下 M=N，通常写为 O(N log K)。额外空间主要来自保存 M 个不同元素的哈希表和大小为 K 的 Heap，因此为 O(M+K)，由于 K≤M≤N，最坏为 O(N)。

# 二十六、我的 LeetCode 347 实现

## 我的回答

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        int n = static_cast<int> (nums.size());

        unordered_map<int, int> map;

        for(int val : nums){
            ++map[val];
        }

        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > minheap;

        for(auto val : map){
            minheap.push({
                val.second,
                val.first
            });

            if(minheap.size() > k){
                minheap.pop();
            }
        }

        vector<int> answer;

        while(!minheap.empty()){
            answer.push_back(
                minheap.top().second
            );

            minheap.pop();
        }

        return answer;
    }
};
```

# 二十九、整理后的 LeetCode 347 版本

```cpp
class Solution {
public:
    vector<int> topKFrequent(
        vector<int>& nums,
        int k
    ) {
        unordered_map<int, int> frequency;

        // value -> frequency
        for (int value : nums) {
            ++frequency[value];
        }

        // pair.first  = frequency
        // pair.second = 原始元素
        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > minHeap;

        for (const auto& entry : frequency) {
            minHeap.push({
                entry.second,
                entry.first
            });

            if (
                static_cast<int>(
                    minHeap.size()
                ) > k
            ) {
                minHeap.pop();
            }
        }

        vector<int> answer;

        while (!minHeap.empty()) {
            answer.push_back(
                minHeap.top().second
            );

            minHeap.pop();
        }

        return answer;
    }
};
```

# 三十、LeetCode 347 复杂度

设：

```text
n
→ nums长度

m
→ 不同元素数量
```

统计 frequency：

```text
O(n)
```

遍历不同元素：

```text
m个候选
```

每个候选进行：

```text
Heap操作
→ O(log k)
```

因此：

```text
O(m log k)
```

总时间：

```text
O(n + m log k)
```

最坏：

```text
m = n
```

因此通常写：

```text
O(n log k)
```

额外空间：

```text
unordered_map
→ O(m)

Min Heap
→ O(k)

answer
→ O(k)
```

整体：

```text
O(m + k)
```

由于：

```text
k <= m <= n
```

最坏：

```text
O(n)
```

# 三十一、LeetCode 347 面试专用回答

> 对于 Top K Frequent Elements，我首先使用 `unordered_map` 在平均 O(n) 时间内统计每个元素的出现频率。然后将每个不同元素表示成 `(frequency, value)`，使用大小为 K 的 Min Heap 按 frequency 维护当前出现次数最高的 K 个元素。每加入一个候选，如果 Heap 大小超过 K，就删除 frequency 最小的元素。最终 Heap 中留下的就是 Top K Frequent Elements。设不同元素数量为 m，总时间复杂度为 O(n + m log k)，最坏为 O(n log k)，额外空间为 O(m + k)，最坏为 O(n)。
