# 五、为什么 nums[mid] == target 不能直接return

## 我的回答

> 因为要找的是第一个大于等于target的元素，当nums[mid] == target时，只能说明nums[mid]大于等于target，而不能说明它是第一个，所以需要继续搜索

## 订正

完全正确。

```text
找到一个满足条件的位置
≠
找到第一个满足条件的位置
```

例如：

```text
[1,3,5,5,5,7]
     ↑ ↑
```

如果 mid 指向后面的 5，左侧仍可能存在更早的 5。

### 面试专用回答

> 边界二分寻找的是第一个满足条件的位置，因此即使 `nums[mid] == target`，也只能说明 mid 是一个合法候选，还必须继续向左确认是否有更早的位置。

# 六、为什么 right = mid

## 我的回答

> 这里我觉得应该是虽然不能说明nums[mid]是第一个大于等于target的元素但是它是满足大于等于target的元素所以不能将其排除在结果候选外

## 订正

完全正确。

当：

```text

```

时：

```text

```

因此不能像：


> 当 `nums[mid] >= target` 时，mid 已经满足目标条件，因此它可能就是最左边界，只能继续向左收缩，不能跨过 mid。

# 八、精确二分 vs 边界二分

## 我的回答

> 精确二分查找解决该元素是否在数组中，而边界二分查找解决该元素在数组中应当插入的位置，即第一个大于等于该元素的数组下标

## 订正

精确二分部分完全正确。

边界二分需要扩展：

```text
不只是找插入位置
```

更一般是：

```text
在具有单调性的条件中
寻找分界位置
```

例如：

```text
first >= target
first > target
last <= target
last < target
```

### 面试专用回答

> 精确二分用于寻找某个具体值；边界二分用于在具有单调性的判断结果中寻找分界点，例如第一个大于等于 target 或第一个大于 target 的位置。

# 十八、我的LeetCode 34代码

```cpp
class Solution {
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int n = static_cast<int>(nums.size());
        if(n == 0) return {-1, -1};

        int left1 = 0;
        int right1 = n;
        while(left1 < right1){
            int mid = left1 + (right1 - left1) / 2;
            if(nums[mid] < target){
                left1 = mid + 1;
            }
            else{
                right1 = mid;
            }
        }

        if(left1 == n || nums[left1] != target) {
            return {-1, -1};
        }

        int left2 = 0;
        int right2 = n;
        while(left2 < right2){
            int mid = left2 + (right2 - left2) / 2;
            if(nums[mid] <= target){
                left2 = mid + 1;
            }
            else{
                right2 = mid;
            }
        }

        return {left1, left2 - 1};
    }
};
```

完全正确。

> 放入Response Header后客户端可以通过告知服务器Request ID帮助其检查日志，并且Response Header很适合保存这种于请求本身相关的元数据，而Response Body更适合保存业务请求的结果

## 订正

完全正确。

### 面试专用回答

> Request ID 属于追踪元数据，因此适合通过 Response Header 返回；Response Body 则保持用于业务结果。

# 四十四、为什么Header必须先设置

## 我的回答

> 因为在handler第一次显式写body前没有调用w.Header().Set设置header，所以Go服务器会自动提交默认 200 ok + 当前已有Header，后续再通过w.Header().Set设置header不能修改已经提交过的response Header了

## 订正

完全正确。

顺序：

```text
Header
↓
WriteHeader
↓
Body
```

如果没显式 WriteHeader：

```text
第一次Write Body
→ 自动提交200
```

# 四十六、完整Request ID链路

## 我的回答

```text
Request进入服务器
↓
middleware 生成id
↓
w.Header.Set("X-Request-ID",
    requestID,)
↓
ctx.WithValue
↓
Context
↓
r.WithContext
↓
Handler / 下游
↓
日志
```

## 订正

核心正确，但少：

```text
next.ServeHTTP
```

以及返回客户端说明。

完整：

```text
Request进入
↓
Request ID Middleware
↓
生成requestID
↓
context.WithValue
↓
new Context
↓
r.WithContext
↓
new Request
↓
设置X-Request-ID Response Header
↓
next.ServeHTTP
↓
Handler / Service / 下游
↓
requestIDFromContext
↓
日志
```

返回：

```text
X-Request-ID
↓
Response Header
↓
Client
```

### 面试专用回答

> Middleware 生成 Request ID 后，将其通过 Context 绑定到当前 Request 并传递给下游，同时提前设置 `X-Request-ID` Response Header。下游可以从 Context 中读取 ID 用于日志，客户端则从响应 Header 中得到同一个 ID。
