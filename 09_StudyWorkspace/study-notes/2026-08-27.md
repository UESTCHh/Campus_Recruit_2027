````markdown
# Part 2：为什么需要 unordered_map

对于：

```cpp
vector<int> nums = {10, 20, 30, 40};
```

如果使用线性查找：

```cpp
find(nums.begin(), nums.end(), 30);
```

通常需要：

```text
从前往后逐个检查元素
```

最坏复杂度：

```text
O(n)
```

而现实程序经常需要：

```text
学生ID → 学生信息
用户名 → 用户信息
商品ID → 商品
单词 → 出现次数
```

这是一种：

```text
key → value
```

的关联关系。

因此可以使用：

```cpp
unordered_map<Key, Value>
```

# Part 3：unordered_map_demo.cpp

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

using namespace std;

int main()
{
    unordered_map<int, string> students;

    students[1001] = "Alice";
    students[1002] = "Bob";
    students[1003] = "Tom";

    cout << "student 1002: "
         << students[1002]
         << endl;

    students[1002] = "Bobby";

    cout << "after update: "
         << students[1002]
         << endl;

    auto it = students.find(1003);

    if (it != students.end())
    {
        cout << "found key: "
             << it->first
             << endl;

        cout << "found value: "
             << it->second
             << endl;
    }

    auto missing = students.find(9999);

    if (missing == students.end())
    {
        cout << "9999 not found" << endl;
    }

    cout << endl;
    cout << "all students:" << endl;

    for (const auto& item : students)
    {
        cout << item.first
             << " -> "
             << item.second
             << endl;
    }

    return 0;
}
```

# Part 6：operator[] 不只是查询

假设：

```cpp
students[9999];
```

但 key `9999` 原本不存在。

`operator[]` 会创建这个 key，并默认构造 value。

对于：

```cpp
unordered_map<int, string>
```

可能得到：

```text
9999 → ""
```

因此：

```cpp
students[9999]
```

不是纯粹的存在性查询。

如果只想判断 key 是否存在，更适合：

```cpp
students.find(9999)
```

C++20 以后还可以：

```cpp
students.contains(9999)
```

当前继续以 `find()` 为主。

# Part 12：为什么还需要 bucket

hash value 的取值空间可能非常大。

例如哈希表当前只有：

```text
8 个 bucket
```

那么 bucket 编号只有：

```text
0 ~ 7
```

因此必须把：

```text
hash value
```

映射到：

```text
[0, bucket_count)
```

范围。

注意：

```text
hash value
≠
bucket index
```

具体如何映射属于标准库实现细节。

不能把：

```text
hash(key) % bucket_count
```

死记成 C++ 标准要求的唯一实现。

# Part 13：Bucket

某个 key：

```

查询时不用遍历整个容器，而是先缩小到候选 bucket。

# Part 14：Hash Collision

不同 key 可能最终进入同一个 bucket。

例如：

```text
1001
 ↓
bucket 2

5009
 ↓
bucket 2
```

这叫：

```text
hash collision
哈希冲突
```

collision：

```text
不是程序错误
```

而是哈希表正常必须处理的情况。

#include <iostream>

int main()

# Part 20：rehash

随着元素增加：

```text
load_factor变高
```

哈希表可能扩大 bucket 结构。

然后重新组织已有元素：

```text
旧bucket结构
    ↓
bucket_count改变
    ↓
重新组织key对应的bucket
```

称为：

```text
rehash
```

rehash 并不是：

```text
key发生改变
```

也不是：

```text
std::hash<Key>这个hash函数本身变了
```

而是：

```text
哈希表的bucket结构发生变化，
已有元素需要按照新的bucket结构重新组织。
```

struct BadHash

    }

int main()
{
    unordered_map<int, string, BadHash> students;

    students[1001] = "Alice";
    students[1002] = "Bobby";
    students[1003] = "Tom";
    students[2001] = "Jack";
    students[3001] = "Rose";

    cout << "size: "
         << students.size()
         << endl;

    cout << "bucket count: "
         << students.bucket_count()
         << endl;

    cout << "load factor: "
         << students.load_factor()
         << endl;

    cout << endl;
    cout << "element buckets:" << endl;

    for (const auto& item : students)
    {
        cout << "key: "
             << item.first
             << ", bucket: "
             << students.bucket(item.first)
             << endl;
    }

    cout << endl;

         << endl;

# Part 31：unordered_map_rehash.cpp

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

using namespace std;

int main()
{
    unordered_map<int, string> students;

    students[1001] = "Alice";
    students[1002] = "Bobby";
    students[1003] = "Tom";

    auto it = students.find(1002);

    string* p = &it->second;
    string& ref = it->second;

    cout << "before rehash" << endl;

    cout << "bucket count: "
         << students.bucket_count()
         << endl;

    cout << "value: "
         << *p
         << endl;

    cout << "value address: "
         << static_cast<const void*>(p)
         << endl;

    size_t oldBucketCount =
        students.bucket_count();

    students.rehash(
        oldBucketCount * 10 + 1
    );

    cout << endl;
    cout << "after rehash" << endl;

    cout << "bucket count: "
         << students.bucket_count()
         << endl;

    cout << "value through pointer: "
         << *p
         << endl;

    cout << "value through reference: "
         << ref
         << endl;

    cout << "old value address: "
         << static_cast<const void*>(p)
         << endl;

    auto newIt = students.find(1002);

                &newIt->second

}

# Part 77：今日高频面试表达

## C++：unordered_map 为什么平均 O(1)？

可以回答：

> `unordered_map` 通常通过哈希表实现。查询时先通过 hash function 将 key 映射到对应 bucket，再在 bucket 内寻找真正匹配的 key。如果 hash 分布较好，每个 bucket 中候选元素很少，所以平均查询复杂度可以达到 O(1)。但如果发生严重哈希冲突，大量元素集中在少数 bucket 中，最坏可能退化到 O(n)。

---

## C++：什么是 hash collision？

可以回答：

> Hash collision 是不同 key 最终被映射到同一个 bucket 的情况。它是哈希表必须正常处理的情况，并不是程序错误。哈希表在定位 bucket 后，还需要通过 key equality 判断真正的目标 key。

---

## C++：什么是 load factor？

可以回答：

> `unordered_map` 的 load factor 可以理解为 `size / bucket_count`，也就是平均每个 bucket 对应多少个元素。load factor 较高通常意味着 collision 风险上升，容器可能通过 rehash 增加 bucket 数量。

---

## C++：rehash 会导致什么失效？

可以回答：

> `unordered_map` 发生 rehash 后，已有 iterator 会失效，但标准保证指向已有元素的 pointer 和 reference 不会仅仅因为 rehash 而失效。这一点和 `vector` reallocation 不同，后者会使 iterator、pointer 和 reference 全部失效。

---

## Go：errors.Is 和 errors.As 区别？

可以回答：

> `errors.Is` 主要用于判断错误链是否匹配某个目标错误；`errors.As` 用于判断错误链中是否存在可以赋给某种目标类型的错误，并把那个具体错误值提取出来。因此 sentinel error 常见于 `errors.Is`，携带结构化信息的 custom error type 常见于 `errors.As`。

---

## Go：为什么 errors.As 经常传二级指针？

可以回答：

> 例如目标变量是 `var validationErr *ValidationError`，它本身已经是一个指针。`errors.As` 需要修改这个指针变量，让它指向错误链中找到的具体 `ValidationError`，因此需要传 `&validationErr`，其类型自然是 `**ValidationError`。Go 仍然是值传递，传入的是这个二级指针值的副本。

---

## Go：Context 是什么？

可以回答：

> `context.Context` 主要用于在请求调用链中传播取消、deadline、timeout 等请求级信息。例如 HTTP 请求已经取消时，可以让 Service、Repository、数据库查询或外部 API 调用及时停止不再需要的工作，避免资源浪费。

---

## Go：Context 会强行终止 goroutine 吗？

可以回答：

> 不会。Context 使用协作式取消。取消发生后，Context 只是进入取消状态并关闭 Done channel，业务代码需要主动检查 `ctx.Err()` 或等待 `ctx.Done()`，然后自行停止工作。

---

## Go：ctx.Done 和 ctx.Err 区别？

可以回答：

> `ctx.Done()` 主要负责通知“Context 已经结束”，而 `ctx.Err()` 负责说明“为什么结束”。例如主动 `cancel()` 后 `ctx.Err()` 返回 `context.Canceled`，timeout 或 deadline 到达时返回 `context.DeadlineExceeded`。
````
