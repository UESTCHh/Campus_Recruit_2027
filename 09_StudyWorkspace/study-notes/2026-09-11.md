# 七、Difference Array 为什么可以恢复 Original Array

定义：

```text
difference[0]
=
numbers[0]
```

以及：

```text
difference[i]
=
numbers[i] - numbers[i - 1]
```

移项：

```text
numbers[i]
=
numbers[i - 1] + difference[i]
```

因此：

```text
numbers[0]
=
difference[0]
```

然后：

```text
numbers[1]
=
numbers[0] + difference[1]
=
difference[0] + difference[1]
```

继续：

```text
numbers[2]
=
numbers[1] + difference[2]
=
difference[0]
+ difference[1]
+ difference[2]
```

一般：

```text
numbers[i]

=
difference[0]
+ difference[1]
+ ...
+ difference[i]
```

因此：

> Difference Array 的 Prefix Sum 就是 Original Array。

# 九、数学上的抵消

```text
+ a[1]
- a[0]
```


抵消。

```text

```

抵消。

最后：

```text
a[2]
```

因此：

```text
d[0] + d[1] + ... + d[i]
=
a[i]
```

# 十、面试时如何回答

如果面试官问：

> 用一句话解释为什么 Difference Array 做 Prefix Sum 能恢复 Original Array？

推荐回答：

> 因为差分数组记录的是相邻元素之间的变化量，其中 `difference[0] = numbers[0]`、`difference[i] = numbers[i] - numbers[i - 1]`，所以从头对这些变化量不断累加时，中间的增减项会依次抵消，最终第 `i` 个前缀和正好等于 `numbers[i]`，因此对 Difference Array 做 Prefix Sum 就能恢复 Original Array。

口语一些：

> 差分数组保存的是每个位置相对前一个位置增加或减少了多少，而第一个差分值就是原数组第一个元素，所以从头不断累加这些变化量，就可以一步一步恢复每个原数组元素。

如果继续追问数学证明：

```text
difference[i]
=
numbers[i] - numbers[i - 1]
```

因此：

```text
difference[0]
+ ...
+ difference[i]
```

中的中间项会两两抵消，最终只剩：

```text
numbers[i]
```

# 十一、Difference Array 的 Range Update

要求：

```text
[left, right]
```

中所有元素：

```text
+ value
```

只需要：

```cpp
difference[left] += value;
difference[right + 1] -= value;
```

---

# 十二、第一句代表什么

```cpp
difference[left] += value;
```

含义：

```text
从left开始
开启 +value 的影响
```

因为以后恢复 Original Array 时会不断做 Prefix Sum。

所以在：

```text
left
```

位置给 Difference 增加 `value`：

```text
left以及后续位置的累计结果
都会继承这个value
```

如果没有第二句：

```text
[left, n - 1]
```

都会受到影响。

---

# 十三、第二句代表什么

```cpp
difference[right + 1] -= value;
```

表示：

```text
从right + 1开始
取消之前的 +value 影响
```

所以最终：

```text
left
↓
开启影响

[left, right]
↓
持续受到影响

right + 1
↓
取消影响
```

真正受到修改的正好：

```text
[left, right]
```

---

# 十四、为什么必须 right + 1

我们修改的是闭区间：

```text
[left, right]
```

因此：

```text
numbers[right]
```

必须仍然受到：

```text
+value
```

影响。

如果错误写成：

```cpp
difference[right] -= value;
```

那么：

```text
right
```

位置就开始抵消影响。

最终真正修改：

```text
[left, right - 1]
```

所以必须：

```cpp
difference[right + 1] -= value;
```

让：

```text
right
```

仍然属于修改区间。

# 十五、为什么 difference.size() = n + 1

假设原数组：

```text
n个元素
```

合法下标：

```text
0 ... n - 1
```

如果：

```text
right == n - 1
```

则：

```text
right + 1 == n
```

需要：

```cpp
difference[n]
```

如果 Difference 只有：

```text
n
```

个元素，最大合法下标：

```text
n - 1
```

访问：

```text
difference[n]
```

就越界。

因此：

```text
difference.size()
=
n + 1
```

合法下标：

```text
0 ... n
```

就可以统一写：

```cpp
difference[right + 1] -= value;
```

不需要额外：

```cpp
if (right + 1 < n)
```

判断。

# 二十五、Difference Array 复杂度

假设：

```text
n个元素
q次Range Increment Update
```

暴力：

```text
一次Update
→ O(n)

q次
→ O(qn)

Extra Space
→ O(1)
```

Difference Array：

```text
构造Difference
→ O(n)

q次Range Update
→ q × O(1)
→ O(q)

最终Prefix Sum恢复
→ O(n)
```

所以：

```text
Time
=
O(n + q + n)
=
O(n + q)
```

Extra Space：

```text
O(n)
```

# 二十六、Prefix Sum vs Difference Array

Prefix Sum：

```text
Original Array
↓
O(n) Preprocessing
↓
Prefix Sum
↓
Range Query O(1)
```

更适合：

```text
大量Range Query
```

Difference Array：

```text
Original Array
↓
构造Difference
↓
Range Update O(1)
↓
最后做一次Prefix Sum
↓
Final Array
```

更适合：

```text
大量Range Increment Update
```

二者关系：

```text
Difference Array
↓ Prefix Sum
Original Array
```

即：

```text
Difference的Prefix Sum
=
Original Array
```

# 三十七、next 是什么

`next` 表示：

> 当前 Middleware 后面需要继续执行的那个 Handler。

今天调用：

```go
handler :=
    loggingMiddleware(mux)
```

因此：

```text
next == mux
```

这一点非常重要。

`next` 不是：

```text
helloHandler
```

而是：

```text
mux
```

然后由 `mux` 自己根据 Route 决定最终调用哪个 Handler。

# 三十八、next.ServeHTTP

Middleware 中：

```go
next.ServeHTTP(w, r)
```

今天因为：

```text
next == mux
```

所以实际相当于：

```go
mux.ServeHTTP(w, r)
```

含义：

```text
Middleware前置工作完成
↓
把当前Request继续传给下一个Handler
```

如果删掉：

```go
next.ServeHTTP(w, r)
```

则：

```text
本次Request
↓
Middleware
↓
到此为止
```

后面的：

```text
mux
helloHandler
```

不会执行。

不是整个程序停止，而是：

```text
本次Request不会继续向后传递
```

# 三十九、Before / After

例如：

```go

fmt.Println("after")
```

执行：

```text

↓
next.ServeHTTP
↓
Handler
↓
Handler返回
↓
after
```

这和普通函数：

```go
fmt.Println("A")

someFunction()

fmt.Println("B")
```

本质相同。

因此：

```text
Middleware Before
↓
Handler
↓
Middleware After
```
