# 三、K Closest Points模型

二维点：

```text
point = (x,y)
```

到原点距离：

```text
sqrt(x²+y²)
```

仅比较大小时无需真正计算sqrt：

```text
priority
→ distance²
→ x²+y²
```

目标：

```text
保留distance²最小的K个
```

当前保留集合中最容易淘汰：

```text
distance²最大的那个
```

因此：

```text
Size-K Max Heap
```

：

```text
heap.top()
→ 当前K个最近点中最远的那个
→ 当前淘汰门槛
```

# 四、Heap Candidate设计

不能只保存：

```text
(distance², point)
```

C++ 中：

```cpp

```

：

```text

→ distance²
```

# 十一、Stage 2：LeetCode 973

文件：

```text
leetcode_973_k_closest_points.cpp
```

## 我的代码

```cpp
class Solution {
public:
    vector<vector<int>> kClosest(
        vector<vector<int>>& points,
        int k
    ) {
        int n = static_cast<int>(points.size());
        priority_queue<pair<int, pair<int, int>>> pq;
        for(int i = 0; i < n; i++){
            int x = points[i][0];
            int y = points[i][1];
            int distance2 = x * x + y * y;
            pq.push({distance2, {x, y}});
            if(static_cast<int>(pq.size()) > k){
                pq.pop();
            }
        }
        vector<vector<int>> answer;
        while(!pq.empty()){
            answer.push_back({pq.top().second.first,pq.top().second.second});
            pq.pop();
        }
        return answer;
    }
};
```

## 订正

实现正确。

核心：

```text
point
↓
distance²
↓
(distance², point)
↓
Size-K Max Heap
↓
answer
```

时间复杂度：

```text
O(n log k)
```

额外空间：

```text
O(k)
```

题目不要求答案按照距离排序，因此 Heap 最终 pop 顺序不需要额外 sort。

## 面试专用回答

> 对于 K Closest Points，我以每个点的距离平方 `x²+y²` 作为 priority，并使用大小为 K 的 Max Heap 维护当前距离最近的 K 个点。堆顶是当前 K 个最近点中距离最大的候选，每加入一个点，如果 Heap 大小超过 K 就删除堆顶。时间复杂度为 O(n log k)，额外空间复杂度为 O(k)。

# 十六、Stage 3检查 4

## 我的回答

> 判断 Heap 方向时 ，不能直接看题目说“最大”还是“最小”，而应该先找“最容易被淘汰的人” ，因为最容易被淘汰的对象是当作Heap的堆顶，而Heap的堆顶对应heap优先级最高的对象，根据堆顶的元素值在堆里的大小排序关系，就可以判断使用Max heap还是Min heap

## 订正

核心正确。

标准判断过程：

```text
我要长期保留谁？
↓
谁最容易被淘汰？
↓
我要让谁成为top()？
↓
它应该是最大值
→ Max Heap

它应该是最小值
→ Min Heap
```

## 面试专用回答

> 判断 Heap 方向不能只看题目中的“最大”或“最小”，而应该先确定当前保留集合中最容易被淘汰的对象，并让它位于堆顶。如果淘汰对象是最大值，就用 Max Heap；如果是最小值，就用 Min Heap。

# 三十七、Stage 3检查 2

## 我的回答

> 函数调用的顺序是A -> B -> Handler，所以从函数调用栈的角度来看，返回的顺序应该相反：Handler -> B -> A，每一层真正返回给调用自己的对象，即Handler返回给B再返回给A

## 订正

完全正确。

这就是洋葱模型真正底层原因：

```text
调用：
A → B → Handler

返回：
Handler → B → A
```

## 面试专用回答

> B After 会先于 A After，是因为 Handler 首先返回给直接调用它的 B，B 完成后才返回 A，因此 After 的执行顺序与进入顺序相反。
