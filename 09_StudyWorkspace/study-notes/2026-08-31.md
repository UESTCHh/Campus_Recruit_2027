# 第一阶段：map 基础

## 1. `map<Key, Value>`

示例：

```cpp
map<int, string> students;
```

其中：

```text
int
→ Key类型

string
→ mapped value类型
```

普通：

```cpp
std::map
```

要求：

```text
Key唯一
```

而：

```text
Value可以重复
```

---

## 2. map 的有序性

例如按照：

```text
3001
1001
2001
```

顺序插入。

遍历时却会得到：

```text
1001
2001
3001
```

原因：

```text
std::map
```

不是按照：

```text
插入顺序
```

遍历。

而是按照：

```text
Comparator定义的Key顺序
```

进行遍历。

默认：

```cpp
std::less<Key>
```

所以对于：

```cpp
int
```

表现为：

```text
Key升序
```

```cpp

```

```text

```


```cpp
upper_bound(k)
```

表示：

```text
第一个 Key > k 的元素
```

例如：


得到：

```text

```

# C++ Day08 易错点

```text
1. map的Key不能通过普通iterator直接修改

2. map遍历：
   不是按插入顺序
   而是按Comparator定义的Key顺序

3. map::find
   不能简单称为“二分查找”

4. map组织核心：
   Comparator + Ordered Structure

5. unordered_map组织核心：
   Hash + Bucket

6. lower_bound：
   默认升序下 >=

7. upper_bound：
   默认升序下 >

8. insert重复Key：
   不覆盖原Value

9. insert失败：
   result.first不是end()
   而是指向已有元素

10. map insert：
    原有iterator/pointer/reference保持有效

11. map erase：
    只有被删除元素相关引用失效

12. map第三个参数：
    是模板参数
    不是构造函数参数

13. map
    ≠
    排序后的unordered_map
```

# 第一阶段：Goroutine

普通：

```go
doWork("worker")
```

表示：

```text
当前goroutine进入doWork
↓
等待函数执行结束
↓
继续执行
```

而：

```go
go doWork("worker")
```

表示：

```text
启动一个新的goroutine执行doWork
↓
当前goroutine继续向下运行
```

---

## Main Goroutine

Go 程序启动：

```text
Go Runtime
↓
Main Goroutine
↓
func main()
```

所以即使还没写：

```go
go ...
```

程序也已经存在：

```text
main goroutine
```

---

## Main 返回

非常重要：

```text
main()
return
↓
整个程序结束
```

不会自动等待其他 goroutine。

所以：

```text
启动goroutine
≠
等待goroutine
```

---

# WaitGroup

核心：

```go
var wg sync.WaitGroup
```

三个操作：

```text
Add
Done
Wait
```

---

## Add

```go
wg.Add(2)
```

表示：

```text
counter += 2
```

即：

```text
有两份待完成工作需要等待
```

注意：

```text
Add(2)
≠
启动两个goroutine
```

---

## Done

```go
wg.Done()
```

可以理解：

```text
counter -= 1
```

语义：

```text
当前这一份工作已经完成
```

---

## Wait

```go
wg.Wait()
```

当：

```text
counter > 0
```

当前 goroutine 阻塞。

直到：

```text
counter == 0
```

Wait 返回。

# 第二阶段：Unbuffered Channel

Channel 主要解决：

```text
goroutine之间通信
+
同步
```

---

## 创建

```go
result := make(chan int)
```

表示：

```text
创建一个能够传递int值的channel
```

类型：

```go
chan int
```

---

## Send

```go
result <- 42
```

表示：

```text
把42发送到result channel
```

---

## Receive

```go
value := <-result
```

表示：

```text
从result channel接收一个值
```

---

## Unbuffered Channel

```go
make(chan int)
```

创建：

```text
unbuffered channel
```

核心：

```text
Send
↔
Receive
```

需要配对。

如果发送方没有 receiver：

```text
Send阻塞
```

如果接收方没有 sender：

```text
Receive阻塞
```

# 第三阶段：Buffered Channel

创建：

```go
make(chan int, 2)
```

表示：

```text
Buffered Channel
Capacity = 2
```

内部最多暂存：

```text
2个int
```

---

## Buffer 未满

例如：

```go
ch <- 10
ch <- 20
```

可以先暂存：

```text
[10,20]
```

不要求 receiver 立即准备好。

---

## Buffer 已满

再：

```go
ch <- 30
```

如果没有 receiver：

```text
Send阻塞
```

所以：

```text
Buffered
≠
永远不阻塞
```

---

# close

```go
close(ch)
```

表示：

```text
这个Channel以后不会再发送新的值
```

不是：

```text
销毁Channel
```

也不是：

```text
清空Buffer
```

---

## Closed Channel

Channel close 后：

```text
Buffer中已经存在的数据
```

仍然可以继续 Receive。

但是：

```go
close(ch)
ch <- 100
```

继续 Send：

```text
panic
```

---

# range channel

```go
for value := range ch {
    ...
}
```

会：

```text
不断Receive
↓
Channel Close
↓
继续消费剩余数据
↓
没有剩余数据
↓
Range结束
```

# Go Day09 易错点

```text
1. go f()
   → 启动新的goroutine
   ≠ 自动等待

2. main return
   → 整个程序结束
   → 不会自动等待其他goroutine

3. Sleep
   ≠ 正确等待任务完成的方法

4. WaitGroup.Add(n)
   → counter += n
   ≠ 创建n个goroutine

5. WaitGroup.Done()
   → counter -= 1
   → 完成通知
   ≠ 主要是释放资源

6. WaitGroup.Wait()
   → counter归零后返回

7. &wg
   → 仍然Pass-by-Value
   → 复制的是指针值

8. Goroutine执行顺序
   → 不能根据源码书写顺序推断

9. Unbuffered Channel
   → Send / Receive必须配合

10. Channel
    → Communication
    +
    Synchronization

11. Buffered Channel
    → 有有限Buffer
    ≠ 永不阻塞

12. Buffer满
    → Send阻塞

13. Buffer空
    → Receive阻塞

14. close
    → 不会再发送新数据
    ≠ 销毁
    ≠ 清空

15. Closed Channel
    → 剩余数据仍然可以Receive

16. Send to Closed Channel
    → panic

17. range channel
    → closed + drained后结束

18. <-ctx.Done()
    → Receive Operation
    → 利用Channel Closure
```
