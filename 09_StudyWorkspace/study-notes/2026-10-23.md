# 二、C++ Stage 1：LeetCode 112《路径总和》

## 2.1 题目

LeetCode 112：https://leetcode.cn/problems/path-sum/

给定一棵二叉树的根节点 `root` 和一个整数 `targetSum`，判断是否存在一条从**根节点到叶子节点**的路径，使得路径上所有节点值之和等于 `targetSum`。

存在返回 `true`，否则返回 `false`。

### 2.2 本题与 LC111 的联系

Day47 学习 LC111《二叉树的最小深度》时，已经明确：

**叶子节点必须同时满足左右孩子均为空。**

```cpp
root->left == nullptr &&
root->right == nullptr
```

LC112 同样要求路径必须到达真正的叶子节点。

例如：

```text
        5
       /
      4
     /
    11
   /  \
  7    2
```

当 `targetSum = 20`：

```text
5 + 4 + 11 = 20
```

虽然在节点 11 达到了目标和，但节点 11 不是叶子节点，所以不能返回 `true`。

当 `targetSum = 22`：

```text
5 → 4 → 11 → 2
5 + 4 + 11 + 2 = 22
```

节点 2 是叶子节点，因此可以返回 `true`。

## 2.3 递归状态设计

函数定义：

```cpp
bool hasPathSum(TreeNode* root, int targetSum);
```

两个参数的含义：

- `root`：当前要处理的节点。
- `targetSum`：从当前节点出发，还需要凑出的路径值之和。

返回值：

- `true`：当前节点以下存在满足要求的完整路径。
- `false`：不存在符合要求的完整路径。

沿路径向下时，逐渐扣除当前节点值。

```text
目标总和：22

当前节点 5：
下一层需要 22 - 5 = 17

当前节点 4：
下一层需要 17 - 4 = 13

当前节点 11：
下一层需要 13 - 11 = 2

当前叶子节点 2：
2 == 当前剩余目标值 2
```

因此不需要 `vector` 记录已经走过哪些节点，因为题目只要求判断符合条件的路径是否存在。

## 2.4 递归终止条件

情况一：当前节点为空。

```cpp
if (root == nullptr) {
    return false;
}
```

空节点无法形成一条根到叶的有效路径。

情况二：当前节点为叶子节点。

```cpp
if (root->left == nullptr &&
    root->right == nullptr) {
    return root->val == targetSum;
}
```

由于此前递归已经扣除了所有祖先节点的值，此时只需要比较叶子节点值与剩余目标值。

情况三：当前节点不是叶子节点。

继续递归左右子树。

因为只要找到一条符合条件的路径即可，因此使用逻辑或运算符 `||` 合并左右子树的结果。

## 2.5 理解检查题 1

**问题：**

对于示例二叉树，当 `targetSum = 20` 时，能否因为 `5 + 4 + 11 = 20` 就返回 `true`？最终应返回什么？

**我的回答（原话）：**

> 不能，因为题目要求的是找一条从根节点的叶子节点的路径，且路径上的节点值之和刚好等于targetSum，所以最终的路径终点一定是左右孩子为空的叶子节点。在targetSum = 20是最终返回false，因为没有一条从根节点的叶子节点的路径，且路径上的节点值之和刚好等于targetSum

**订正：**

核心判断正确。

“从根节点的叶子节点的路径”应表述为“从根节点到叶子节点的路径”。

对本题所给树而言，完整路径的节点和分别为：

```text
5 → 4 → 11 → 7       和为 27
5 → 4 → 11 → 2       和为 22
5 → 8 → 13           和为 26
5 → 8 → 4 → 1        和为 18
```

没有路径和为 20，因此最终返回 `false`。

**相关示例：**

```text
    1
   /
  2
```

若目标值为 1，虽然根节点值为 1，但根节点不是叶子节点，因此不能直接返回 `true`。

**面试专用回答：**

LC112 需要判断是否存在从根节点到叶子节点的路径，使路径和等于目标值。因此不仅需要判断路径值之和，还必须确认路径已经到达叶子节点，不能在非叶子节点处提前返回成功。

## 2.6 理解检查题 2

**问题：**

当前节点值为 5、`targetSum = 22`，递归进入孩子时应该传递什么？为什么不需要保存路径？

**我的回答（原话）：**

> 传递22 - 5 = 17，代表当前节点到叶子节点的所需值。因为每次向下递归传递的是当前处理节点所需的targetSum值而不是题目要求的targetSum值，这样不需要知道已经经过的节点，只需要判断当前处理节点为叶子节点时当前节点值是否等于targetSum即可，即题目要求的只是存在性不是确定性，不是另外知道这条路径是哪条。

**订正：**

回答正确。

需要进一步明确：在任意一次递归调用中，`targetSum` 都表示**从当前节点开始还需要凑出的总和**，而不再始终表示最初传入的目标值。

**相关示例：**

```text
hasPathSum(节点5, 22)
    ↓
hasPathSum(节点4, 17)
    ↓
hasPathSum(节点11, 13)
    ↓
hasPathSum(节点2, 2)
```

到达叶子节点 2 时，检查：

```cpp
2 == 2
```

得到 `true`。

**面试专用回答：**

可以通过递归参数维护剩余目标值。每访问一个非叶子节点，就从目标值中减去当前节点值，再递归查找左右子树；到达叶子节点时直接比较其节点值与剩余目标值。由于只需判断路径是否存在，因此无需额外容器记录路径。

## 2.7 理解检查题 3

**问题：**

空树返回什么？到达叶子节点时检查什么？只有一侧满足要求时，应使用 `&&` 还是 `||`？

**我的回答（原话）：**

> 1. false 2. 检查当前节点值是否等于targetSum 3.返回true，应该使用||

**订正：**

全部正确。

`||` 表示左右子树只要有一侧存在目标路径即可。

它还具有短路求值特性：如果左侧已经返回 `true`，右侧就不再执行。

**相关示例：**

```text
左子树结果：false
右子树结果：true
```

使用：

```cpp
false || true  // true
```

如果误用 `&&`，就会错误地要求左右两侧都存在目标路径。

**面试专用回答：**

空树返回 false；到达叶子节点时比较当前节点值与剩余目标值；对于非叶子节点，分别递归左右子树，使用逻辑或合并，因为只要任意一侧存在满足条件的路径，整个函数就应返回 true。

# 三、C++ Stage 2：独立实现 LC112

## 3.1 我的独立代码

以下保留用户提交的实际实现：

```cpp
class Solution {
public:
    bool hasPathSum(TreeNode* root, int targetSum) {
        if(root == nullptr){
            return false;
        }
        if(root -> left == nullptr && root -> right == nullptr){
            return root -> val == targetSum;
        }
        return hasPathSum(root -> left, targetSum - root -> val) || hasPathSum(root -> right, targetSum - root -> val);
    }
};
```

## 3.2 代码检查

| 条件 | 处理方式 | 结论 |
|---|---|---|
| 空节点 | 返回 `false` | 正确 |
| 到达叶子节点 | 比较 `root->val` 与 `targetSum` | 正确 |
| 继续递归 | 传递 `targetSum - root->val` | 正确 |
| 左右结果合并 | 使用 `||` | 正确 |

该实现不需要额外的辅助函数或 `vector`。

### 易错点

不能仅因为递归过程中剩余目标值变成 0 就提前返回 `true`。

另外，本题可能存在负数节点，因此也不能简单认为剩余值小于 0 时就可以剪枝。

## 3.3 LeetCode 验收

用户反馈：

> 2.提交正确

**记录：LeetCode 112 提交通过（依据用户反馈）。**

没有提供具体提交耗时和内存数据，因此不编造这些指标。

## 3.4 复杂度分析

**我的回答（原话）：**

> 时间复杂度：O(n)，每个节点最多遍历一次，每次处理时的复杂度为O(1)，因为每次处理只是判断是否为空节点，是否为叶子节点，是就判断是否节点值等于目标值，否就继续将剩余目标值传入子节点继续递归。

> 空间复杂度：O(h)，跟递归调用栈深度有关，而递归调度栈深度与树的最大深度相关，因为在递归处理左子树时递归调用栈不会存在右子树的递归，所以只需看树的最大深度而不是宽度。平衡树为O(log n)，退化为链表的树为O(n)

**订正：**

分析正确。

- 最坏时间复杂度：`O(n)`。
- 递归额外空间复杂度：`O(h)`。
- 树高为 `O(log n)` 时，递归空间为 `O(log n)`。
- 退化为链表时，递归空间为 `O(n)`。

`||` 可能提前终止部分搜索，因此实际访问节点数可能少于 n，但最坏时间复杂度仍为 `O(n)`。

**面试专用回答：**

LC112 可以使用 DFS 递归求解。空节点返回 false；叶子节点判断剩余目标值是否等于当前节点值；非叶子节点则减去当前节点值后继续递归左右子树。只要任意一侧满足条件就返回 true。最坏时间复杂度 O(n)，递归空间复杂度 O(h)。

**Stage 2 结论：通过。**

## 4.5 为什么这是依赖注入？

路由注册函数接收：

```go
mux *http.ServeMux
repo *StudentRepository
```

其中 `repo` 由外部创建后传入各个 Handler 工厂函数。

例如：

```go
mux.HandleFunc(
    "GET /students/{id}",
    studentByIDHandler(repo),
)
```

注册时，`studentByIDHandler(repo)` 返回一个 `http.HandlerFunc`。

这不会立即执行 GET 查询。

真正的 SQL 查询是在收到匹配的 HTTP 请求、Handler 执行并调用 `repo.GetByID()` 时发生。

# 五、C++ 加餐 Stage 3：BST 二叉搜索树入门

## 5.1 BST 的定义

BST：Binary Search Tree，二叉搜索树。

对于本阶段不允许重复键值的经典 BST：

1. 当前节点左子树的全部节点值都小于当前节点值。
2. 当前节点右子树的全部节点值都大于当前节点值。
3. 左右子树本身也必须分别满足 BST 的性质。

例如：

```text
          8
        /   \
       3     10
      / \      \
     1   6      14
        / \    /
       4   7  13
```

这是一棵合法 BST。

### 与普通二叉树的区别

普通二叉树只约束节点之间的树形结构，不要求数值有序。

BST 可以利用数值大小决定下一步向左还是向右查找。

因此不必像一般二叉树搜索那样，在最坏情况下同时探索大量左右分支。

## 5.2 BST 查找原理

设目标值为 `val`，当前节点指针为 `root`。

| 条件 | 处理 |
|---|---|
| `root == nullptr` | 返回 `nullptr` |
| `root->val == val` | 返回 `root` |
| `root->val > val` | 搜索左子树 |
| `root->val < val` | 搜索右子树 |

例如查找 7：

```text
8 → 3 → 6 → 7
```

每次只沿一个方向深入。

## 5.3 BST 查找复杂度

BST 的查找路径长度取决于树高 `h`。

**时间复杂度：`O(h)`。**

当树高为 `O(log n)`：

```text
查找时间：O(log n)
```

当 BST 退化为链表，树高为 `O(n)`：

```text
查找时间：O(n)
```

所以普通 BST 查找并不一定是 `O(log n)`。

# 六、C++ 加餐 Stage 4：LC700 递归与迭代

## 6.1 题目

LeetCode 700：https://leetcode.cn/problems/search-in-a-binary-search-tree/

函数要求：

```cpp
TreeNode* searchBST(TreeNode* root, int val);
```

找到目标值则返回对应节点指针，否则返回 `nullptr`。

## 6.2 第一种解法：递归

### 我的独立代码

```cpp
class Solution {
public:
    TreeNode* searchBST(TreeNode* root, int val) {
        if(root == nullptr){
            return nullptr;
        }
        if(root -> val > val){
            return searchBST(root -> left, val);
        }
        else if(root -> val < val){
            return searchBST(root -> right, val);
        }
        else{
            return root;
        }
    }
};
```

### 原理

- 递归终止：`root == nullptr`。
- 当前值大于目标值：递归左子树。
- 当前值小于目标值：递归右子树。
- 当前值等于目标值：返回当前节点指针。

递归调用前的 `return` 很重要，它将搜索结果逐层返回给最初的调用者。

### 提交结果

用户反馈：

> 2.实际提交正确

**结论：递归版 LeetCode 提交通过。**

### 复杂度分析原话

> 使用的是递归（但是同时也想掌握迭代）；时间复杂度为O(h)即树的高度，若树高为O(log n)则为O(log n)，若树高为O(n)即退化为链表的树，则为O(n)；空间复杂度与递归调用栈的深度相关，一般为O(h)即依据为树的高度，同样若树高为O(log n)则为O(log n)，若树高为O(n)即退化为链表的树，则为O(n)

**订正：**

完全正确。

- 时间：`O(h)`。
- 额外空间：`O(h)`，来自递归调用栈。
- 树高为 `O(log n)` 时，两者均为 `O(log n)`。
- 退化成链表时，两者均为 `O(n)`。

C++ 不保证一定进行尾调用优化，因此正常算法分析不能把递归额外空间直接写成 `O(1)`。

## 6.3 第二种解法：迭代

本次用户主动提出希望同时掌握迭代解法，因此在 Stage 4 内补充学习，不新增独立 Stage。

### 迭代原理

LC700 不需要在子树递归返回后再额外计算父节点状态，只需要不断比较当前节点与目标值。

因此，可以使用一个指针保存当前访问节点：

```cpp
TreeNode* cur = root;
```

循环中根据大小关系移动：

```cpp
cur = cur->left;
```

或者：

```cpp
cur = cur->right;
```

直到找到目标节点或者指针为空。

### 我的独立代码

```cpp
class Solution {
public:
    TreeNode* searchBST(TreeNode* root, int val) {
        TreeNode* cur = root;

        while (cur != nullptr) {
            // 1. 当前节点等于 val，返回什么？
            if(cur -> val == val) return cur;

            // 2. 当前节点值大于 val，cur 应怎样移动？
            if(cur -> val > val) cur = cur -> left;

            // 3. 当前节点值小于 val，cur 应怎样移动？
            else if(cur -> val < val) cur = cur -> right;
        }

        // 4. 循环结束后应该返回什么？
        return cur;
    }
};
```

### 代码检查

逻辑正确。

当循环结束时：

```cpp
cur == nullptr
```

所以：

```cpp
return cur;
```

与：

```cpp
return nullptr;
```

在这里等价。

### 提交结果

用户反馈：

> 提交正确

**结论：迭代版 LeetCode 提交通过。**

## 6.4 递归与迭代的空间复杂度区别

### 我的回答（原话）

> 这一版通过用指针保存遍历过的节点，只使用了常数变量，故空间为O(1)，而递归版则是一步步递归深入子树，会不断产生递归调用栈帧，空间复杂度取决于递归调用栈的深度，即O(h)

### 订正

复杂度判断正确。

唯一的表述问题是：`cur` 保存的是**当前正在访问的节点指针**，不是所有已经遍历过的节点。

如果真的保存全部经过的节点，就可能需要额外的数组或容器。

而本次迭代始终只复用一个指针变量。

| 解法 | 时间 | 额外空间 |
|---|---|---|
| 递归 | `O(h)` | `O(h)` |
| 迭代 | `O(h)` | `O(1)` |

### 相关示例

```text
cur = 8
cur = 3
cur = 6
cur = 7
```

虽然访问了四个节点，但并没有保存四个额外的节点指针。

`cur` 只是不断更新。

### 面试专用回答

BST 查找可以使用递归或迭代。两者都利用二叉搜索树的有序性，每次只往一侧搜索，时间复杂度均为 O(h)。递归实现存在深度为 O(h) 的函数调用栈；迭代实现只使用常数个指针变量，因此额外空间复杂度为 O(1)。

**Stage 4 结论：LC700 递归与迭代均已通过验收。**

原来的 `main.go` 将 SQLite 数据库路径固定为：

dbPath := filepath.Join(

希望实现：

**程序代码不变，启动程序时通过环境变量决定使用哪个 SQLite 文件。**

## 7.2 什么是环境变量？

环境变量是操作系统向进程提供的名称和值。

例如：

```text
变量名：
STUDENT_DB_PATH

变量值：
D:\...\day38-sql-persistence\students.db
```

PowerShell 可以设置当前进程环境中的变量：

```powershell
$env:STUDENT_DB_PATH = "D:\Data\students.db"
```

Go 程序可读取：

```go
dbPath := os.Getenv("STUDENT_DB_PATH")
```

需要区分：

- `STUDENT_DB_PATH`：操作系统进程环境中的配置名称。
- `dbPath`：Go 程序内部的普通字符串变量。
- SQLite 数据库：真正保存学生记录的文件。

环境变量本身不会连接数据库，也不会自动检查数据库是否存在。

### Windows PowerShell 中的环境变量作用范围

在当前 PowerShell 会话中设置：

```powershell
$env:STUDENT_DB_PATH = "..."
```

由该 PowerShell 启动的 Go 子进程通常会继承此环境变量。

另一个独立启动的 PowerShell 会话不一定具有相同值。

这种写法通常不会永久修改 Windows 的系统级环境变量。

## 7.3 我的独立实现

根据用户提供的代码内容整理排版：

```go
// 1. 优先读取环境变量
dbPath := os.Getenv("STUDENT_DB_PATH")

// 2. 没有设置时使用默认路径
if dbPath == "" {
    dbPath = filepath.Join(
        "..",
        "day38-sql-persistence",
        "students.db",
    )
}

// 3. 检查数据库文件是否存在
if _, err := os.Stat(dbPath); err != nil {
    log.Fatal(err)
}
```

### 运行规则

| 环境变量情况 | 处理 |
|---|---|
| 有非空路径 | 优先使用环境变量路径 |
| 未设置 | 使用默认 Day38 路径 |
| 设置为空字符串 | 使用默认 Day38 路径 |
| 指定路径不存在 | `os.Stat()` 报错，程序终止 |

保留 `os.Stat()` 的目的是避免 SQLite 在路径错误时意外创建一个新的空数据库文件。

但也要注意：`os.Stat()` 只能检查文件系统中的目标是否存在及元数据是否可访问，不等于确认文件内容一定是合法 SQLite 数据库。

# 十、今日易错点与重点复盘

## 10.1 C++：路径满足目标值不代表已经到达叶子

LC112 必须同时满足：

1. 路径从根节点开始。
2. 路径到叶子节点结束。
3. 路径和等于 `targetSum`。

不能在中间节点提前成功返回。

## 10.2 C++：递归参数要明确语义

在 LC112 中，每次传递的是剩余目标值，而不是始终传入原始 `targetSum`。

递归参数本身就可以保存所需状态。

## 10.3 C++：BST 约束整棵子树

节点值满足与直接父节点的大小关系，不代表整棵树一定是 BST。

祖先节点的取值范围也必须满足。

这是后续 LC98 的重点。

## 10.4 C++：区分递归与迭代空间

递归会形成调用栈：

```text
O(h)
```

迭代只更新当前节点指针：

```text
O(1)
```

不能把“访问过的节点数量”等同于“额外存储的节点数量”。

## 10.5 Go：路由注册与 Handler 执行是不同动作

注册：

```go
mux.HandleFunc(
    "GET /students/{id}",
    studentByIDHandler(repo),
)
```

不代表立即执行数据库查询。

只有真正处理 HTTP 请求时才进入 Handler 的业务逻辑。

## 10.6 Go：测试要尽可能覆盖真实应用配置

测试如果自行注册一套路由，可能遗漏生产路由配置错误。

复用 `registerStudentRoutes()` 更能保证测试与实际服务的配置保持一致。

## 10.7 Go：环境变量与普通局部变量不同

```powershell
$env:STUDENT_DB_PATH = "..."
```

由 PowerShell 设置进程环境。

```go
dbPath := os.Getenv("STUDENT_DB_PATH")
```

由 Go 程序读取进程环境并保存到局部变量。

环境变量不等于数据库连接，也不等于永久的 Windows 系统设置。

## 10.8 Go：成功场景与失败场景都要验证

本日一个很好的实验是：

- 正确路径：服务器启动。
- 错误路径：服务器按预期失败。
- 恢复路径：服务器重新启动。

这比只运行一次正常启动更能说明配置逻辑有效。
