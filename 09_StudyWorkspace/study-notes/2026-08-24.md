# 1. this指针


## 基本概念


在C++中，每一个非静态成员函数内部都隐藏了一个this指针。


例如：


```cpp
class Student
{

public:

    int age;


    void show()
    {
        cout << age;
    }

};
调用：
Student s;

s.show();
实际上类似于：
show(&s);
编译器会自动将当前对象地址传递给成员函数。
这个隐藏参数就是：
this
this指针作用
通过this指针：
成员函数可以知道当前操作的是哪个对象
可以访问当前对象的成员变量
可以访问当前对象的成员函数
例如：
Student(int age)
{
    this->age = age;
}
这里：
左边：
this->age
表示当前对象成员变量。
右边：
age
表示构造函数参数。
通过this解决成员变量和参数同名问题。
实验结果
代码：
class Student
{

public:

    int age;


    Student(int age)
    {
        this->age = age;
    }


    void show()
    {
        cout << this << endl;
        cout << this->age << endl;
    }

};
运行结果：
0x1026710
0x1026710
22
说明：
对象地址：
&s
和：
this
地址相同。
验证this指针保存当前对象地址。
问题1：
为什么成员函数可以访问成员变量？
我的回答：
因为成员函数自带一个参数this，其为本对象的指针，可以通过该指针直接访问成员变量。
订正：
成员函数调用时，编译器会隐式传入当前对象的地址。
这个隐藏参数就是this指针。
通过this指针，成员函数可以知道当前操作的是哪个对象，因此可以访问该对象的成员变量和成员函数。

基本概念
拷贝构造函数用于：

形式：

{

}
参数通常使用：
const引用
调用场景
1. 使用对象初始化新对象
例如：

Student s2 = s1;
调用：
拷贝构造函数
2. 函数参数值传递
例如：
void func(Student s)
{

}
调用函数时：

3. 函数返回对象

注意：
对象初始化：
Student s2=s1;
调用拷贝构造函数。
对象赋值：

3. 浅拷贝与深拷贝
浅拷贝
默认拷贝构造函数：
Student s2=s1;
对于普通变量：
复制值。
对于指针：
复制地址。
例如：
int* age;
复制后：
s1.age
 |
 v
0x1000


s2.age
 |
 v
0x1000
两个对象指向同一块内存。
问题
当析构函数：
delete age;
第一次释放：
正常。
第二次释放：
double free。
原因：
多个对象释放同一块内存。
深拷贝
深拷贝：
重新申请一块新的内存。
例如：
Student(const Student& other)
{
    age = new int(*other.age);
}
结果：
s1.age

0x1000


s2.age

0x2000
两个对象拥有独立资源。
实验结果
浅拷贝：
输出：
0x1026710
0x1026710
说明：
两个对象共享地址。
深拷贝：
输出：
0xf927b0
0xf927d0
22
22
说明：
两个对象拥有不同地址，但是数据一致。
问题3：
为什么C++需要深拷贝？
我的回答：
因为当类中有指针时，浅拷贝只是简单复制指针，当一个对象生命周期结束后，若调用析构函数会delete释放内存空间，那么另一个对象生命周期结束后调用析构函数会导致double free，重复释放同一块内存空间，造成错误。
订正：
默认拷贝构造函数执行的是浅拷贝。
对于指针成员：
只复制地址，不复制实际数据。
因此多个对象可能指向同一块堆内存。
当析构函数释放资源时：
多个对象都会delete同一块内存。
导致：
double free。
因此需要深拷贝：
重新申请一块独立内存，复制实际数据。
总结：
浅拷贝：
两个对象共享一块堆空间。
深拷贝：
两个对象拥有独立资源。
4. 默认拷贝构造函数
概念
如果类没有显式定义拷贝构造函数。
编译器会自动生成默认拷贝构造函数。
默认行为：
逐成员拷贝。
例如：
普通变量：
int age;
复制：
值。
指针：
复制：
地址。
所以默认拷贝构造函数对于指针成员可能产生浅拷贝问题。
问题4：
默认拷贝构造函数做的是深拷贝还是浅拷贝？
我的回答：
默认拷贝构造函数进行浅拷贝，只复制成员变量的值，对于指针成员只复制地址。
订正：
C++编译器生成的默认拷贝构造函数采用逐成员拷贝。
对于普通变量：
复制值。
对于指针：
复制地址。
因此属于浅拷贝。
5. 为什么拷贝构造函数使用const引用
形式：
Student(const Student& other)
原因：
1. 使用引用避免无限递归
如果：
Student(Student other)
参数使用值传递。
调用：
Student s2=s1;
需要先复制参数other。
复制other：
↓
调用拷贝构造函数
↓
再次复制other
↓
无限递归。
所以必须使用引用。
2. const保护源对象
const表示：
不会修改原对象。
保证：
拷贝过程只读取数据。
问题5：
拷贝构造函数为什么参数必须使用const引用？
我的回答：
说明拷贝操作不能修改原对象的属性，属于一种保护功能，防止在拷贝构造函数中错误修改原对象属性值，用const说明该参数是只读的。
订正：
拷贝构造函数参数使用const引用主要有两个原因：
引用：
避免传值产生递归调用。
const：
保证不会修改源对象。
因此标准形式：
Student(const Student& other)

拷贝构造函数
用于：
创建新对象。
例如：
Student s2=s1;
operator=
用于：
已有对象之间赋值。
例如：
Student s2;

s2=s1;
问题6：
如果一个类没有显式定义拷贝构造函数，
C++什么时候会自动生成默认拷贝构造函数？什么时候不会生成？
我的回答：
当用一个已存在的对象实例初始化另一个对象时会自动生成，但是赋值操作“=”不会自动生成。
订正：
如果一个类没有显式定义拷贝构造函数，编译器通常会自动生成默认拷贝构造函数。
默认拷贝构造：
逐成员拷贝。
但是：
如果用户自己定义了拷贝构造函数：
Student(const Student& other)
{

}
编译器不会再次生成。
如果类中存在不可拷贝成员，也可能无法生成有效拷贝构造函数。
例如：
不可复制的mutex。
问题7：
拷贝构造函数和赋值运算符operator=有什么区别？
我的回答：
拷贝构造函数和赋值运算符属于两个不同函数。
若类中未重载赋值运算符，使用operator=可能出现错误。
拷贝构造函数传入const引用参数，可以通过深拷贝解决double free问题。
赋值操作属于浅拷贝，会有double free问题。
订正：
主要区别：
	拷贝构造	operator=
作用	创建新对象	修改已有对象
调用时机	初始化	赋值
是否创建对象	是	否

默认情况下：
二者都会进行逐成员操作。
如果成员存在指针：
都可能产生浅拷贝问题。
需要根据资源管理需求实现深拷贝。

问题10：
value receiver 和 pointer receiver最大区别是什么？
我的回答：
前者传值，传的是对象复制品，函数内修改不会影响原对象。
后者传指针（地址），传的是原对象本身，函数内修改直接影响原对象。
订正：
value receiver：
会复制对象。
修改的是副本。
原对象不变。
pointer receiver：
传递保存对象地址的指针。
通过指针访问并修改原对象。
注意：
Go所有参数都是值传递。
pointer receiver并不是引用传递。
只是传递了指针副本。

问题11：
为什么：
service.Add()
没有改变count？
但是：
service.AddPointer()
改变了？
我的回答：
因为Add()方法是value receiver，传进来的是原对象复制品，对其修改不会同步到原对象。
AddPointer()是pointer receiver，传进来的是原对象地址，对其修改直接作用于原对象。
订正：
value receiver：
创建对象副本。
修改副本。
原对象不改变。
pointer receiver：
接收保存对象地址的指针。
通过指针修改真实对象。
因此：
Add()不会改变count。
AddPointer()会改变count。
