```text
滑动窗口
```




```text
[left, right]
```

```text
3 2 6
```

```text
连续子数组
```

# 五、固定窗口的暴力方法

暴力方式可以：

```text
枚举每一个Window的左边界
↓
重新遍历这个Window中的k个元素
↓
重新计算sum
```

窗口数量：

```text
n - k + 1
```

每个窗口重新计算：

```text
O(k)
```

因此：

```text
O((n-k+1) × k)
```

通常表示：

```text
O(nk)
```

如果：

```text
k ≈ n
```

则可能接近：

```text
O(n²)
```

# 九、固定窗口如何滑动

当：

```text
right
```

表示新进入窗口的元素下标时：

```text
进入元素下标
→ right

离开元素下标
→ right - k
```

例如：

```text
right = 3
k = 3
```

新进入：

```text
numbers[3]
→ 6
```

离开：

```text
numbers[0]
→ 1
```

更新：

```cpp
windowSum -= numbers[right - k];
windowSum += numbers[right];
```

# 十二、Fixed-size Sliding Window 复杂度

第一个窗口完整计算：

```text
O(k)
```

剩余：

```text
n - k
```

次窗口滑动。

每次只执行：

```text
减去离开元素
加入进入元素
更新最大值
```

都是：

```text
O(1)
```

所以：

```text
O(k + n - k)
=
O(n)
```

Extra Space：

```text
O(1)
```

因为只使用：

```text
windowSum
maxSum
left / right 等下标
```

常数数量辅助变量。

## 问题 7

为什么是 `O(n)` / `O(1)`？

### 我的回答

> 首先只要计算一次第一个窗口的累加和：O(k)
>
> 后续只用维护window state，每次移动只用计算边界元素的加入和移出带来的影响即可，这是常数操作故O(n - k)

### 订正

完全正确。

这一分析比：

```text
“只有一个for循环所以O(n)”
```

更加准确。

## 问题 8

Binary Search / Two Pointers / Sliding Window 如何避免重复工作？

### 我的回答

> Binary Search 是通过有序性每次对比中间值然后缩短一半的搜索空间，避免重复的无意义的一半搜索；
>
> Two Pointers 也是通过有序性以及维护每次计算得到的结果值对比目标值排除不可能的端点，逐步减小搜索空间，避免重复的无意义的搜索；
>
> Sliding Window 通过维护Window State的方法每次只用计算边界带来的影响，而不用重新计算整个窗口，避免重复工作

### 订正

完全正确。

整理：

```text
Binary Search
→ 利用有序性
→ 排除不可能的搜索区间
```

```text
Two Pointers
→ 利用数据性质
→ 安全排除候选端点
```

```text
Sliding Window
→ 利用相邻Window高度重叠
→ 维护State
→ 避免重新计算整个区间
```

共同点：

```text
利用已经知道的信息
避免从头重复做同样的工作
```

# 二十、为什么要求所有元素是正整数

这个版本依赖：

```text
Window Sum变化的单调性
```

全部正数时：

```text
right右移
→ 加入正数
→ windowSum只会增加
```

以及：

```text
left右移
→ 移除正数
→ windowSum只会减少
```

因此可以稳定判断：

```text
sum < target
→ 继续扩大

sum >= target
→ 尝试缩小
```

如果存在负数：

```text
加入一个新元素
→ sum可能下降

删除一个元素
→ sum可能上升
```

这样：

```text
扩大 / 缩小
```

与：

```text
sum变化
```

之间失去单调关系。

因此：

```text
今天这套简单可变Sliding Window
不再保证正确
```

注意：

```text
不是说有负数就不存在最短子数组
```

而是：

```text
这套移动规则不再可靠
```

# 二十三、Variable-size Sliding Window 复杂度

代码结构：

```cpp
for (...)
{
    while (...)
    {
    }
}
```

不能机械判断：

```text
两层循环
→ O(n²)
```

因为：

```text
right
```

整个算法生命周期内：

```text
最多向右移动n次
```

而：

```text
left
```

也：

```text
最多向右移动n次
```

没有任何一个 Pointer 会重新向左返回。

总移动量：

```text
O(n) + O(n)
=
O(n)
```

所以：

```text
Time Complexity
→ O(n)
```

Extra Space：

```text
O(1)
```

>
> shrink: leave = 1, new left = 3, sum = 6

### 订正

完全正确。

---

## 问题 6

为什么要求全部正数？

### 我的回答

> 因为只有全是正数才能保证扩大窗口是使累加和变大，缩小窗口是使和变小，如果存在负数，那么扩大窗口可能使和变小，而缩小窗口使累加和变大，就不满足找最小窗口的要求了

### 订正

核心完全正确。

更加准确：

```text
正数
→ Window Sum随Expand / Shrink具有单调性
```

负数会破坏这种单调性：

```text
Expand不一定使sum变大
Shrink不一定使sum变小
```

所以今天的简单规则不再保证正确。

## 问题 7

为什么 `for + while` 仍然 O(n)？

### 我的回答

> 因为left和right都是最多移动n个单位，O(n) + O(n)均摊下来就是O(n)

### 订正

完全正确。

重点：

```text
不要只看循环嵌套层数
要看所有Pointer在整个算法中总共移动多少次
```

## 问题 8

Fixed / Variable 如何维护 State？

### 我的回答

> Fixed-size Window 维护窗口中所有元素的和，每次都只计算移动边界带来的影响，移动边界是遍历所有子数组的可能 Variable-size Window 也是维护窗口中所有元素的和，每次都只计算移动边界带来的影响，但右边界一直移动直到找到满足条件的位置为止，而左边界是一直移动直到找到不满足条件的位置为止。

### 订正

核心正确。

整理：

```text
Fixed-size Window

窗口长度始终等于k

每次：
一个元素离开
一个元素进入

left / right整体向右
窗口大小不变
```

```text
Variable-size Window

right
→ 持续扩张

满足条件后：
left
→ 持续收缩

直到条件不再满足
```

共同点：

```text
都维护Window State
都通过边界变化增量更新State
都避免重新扫描整个Window
```
