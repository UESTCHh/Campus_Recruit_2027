#include <iostream>
using namespace std;

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;

    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

// 只比较当前两个节点，不是完整的二叉树递归比较算法
bool sameCurrentNode(TreeNode* p, TreeNode* q) {
    if (p == nullptr || q == nullptr) {
        return p == q;
    }
    return p->val == q->val;
}

int main() {

    TreeNode b1(1), b2(3);

    a1.left = &a2;
    b1.left = &b2;

    TreeNode* p = &a1;
    TreeNode* q = &b1;

    cout << boolalpha;
    cout << "Same address: " << (p == q) << '\n';
    cout << "Same root value: " << sameCurrentNode(p, q) << '\n';
    cout << "Same left child: " << sameCurrentNode(p->left, q->left) << '\n';
    cout << "Same right child: " << sameCurrentNode(p->right, q->right) << '\n';
}

2.3 Stage 1 检查 1：指针相同和节点值相同
问题
TreeNode a(10);
TreeNode b(10);
TreeNode* p = &a;
TreeNode* q = &b;
1. p == q 的结果是什么，为什么？
2. p->val == q->val 的结果是什么，为什么？
3. 判断二叉树相同时应该比较地址还是结构和值？
我的回答（原文）
1. p == q 的结果是什么？为什么？false，因为a和b是不同的节点，故地址也不一样，所以p、q这两个存储这两个节点地址的指针当然不是同一个对象。
2. p->val == q->val 的结果是什么？为什么？true，因为节点a和节点b存储的数据值是一样的
3. 判断两棵二叉树相同时，应该比较节点地址还是节点的结构和值？比较节点的结构和值，因为两棵二叉树的节点地址一般不一样。

订正
结论均正确。细节：p == q 比较的是两个指针变量保存的地址值，并不是判断 p、q 两个指针变量自身是否为同一个变量。TreeNode* q = p; 时，即使 p、q 是独立变量，p == q 仍为真。
相关示例
TreeNode a(10), b(10);
TreeNode* p = &a;
TreeNode* q = &b;
// p == q: false; p->val == q->val: true
q = p;
// 此时 p == q: true
面试专用回答
相同二叉树比较的是两棵树对应节点的值与结构，而非节点实际所在的内存地址。两个不同地址的节点可以具有相同的值，两棵树也可以在不同地址上拥有完全相同的结构。

2.4 Stage 1 检查 2：空指针判断
问题：两空、一空一非空、两非空但当前值不同时分别返回什么？
我的回答（原文）
1. p == nullptr，q == nullptr。返回true，此时两个节点都是空指针，代表两棵树全是空树，故是相同的树
2. p != nullptr，q == nullptr。返回false，一个是空树，另一个不是空树，必然不相同
3. p == nullptr，q != nullptr。返回false，一个是空树，另一个不是空树，必然不相同
4. p != nullptr，q != nullptr，但 p->val != q->val。返回false，虽然两棵树都不为空树，但是两棵树存储的数据值不同，所以也不是相同的树

订正
四问均正确。注意递归中 p 和 q 不一定是最初整棵树的根，它们也可能代表某层子树根节点。必须在解引用 p->val / q->val 之前处理空指针。
if (p == nullptr || q == nullptr) {
    return p == q;
}
这一种写法可以同时处理“双空 true”和“仅一空 false”。
相关示例
p 子树：    2        q 子树：  2
             \                  （没有右孩子）
              3
比较 p->right 与 q->right 时，仅一方非空，必须返回 false。
面试专用回答
同步递归比较树时，应先处理空指针：两个都空则相同，只有一个为空则不同。两者都非空才能安全比较节点值并继续递归，以避免空指针解引用。

2.5 Stage 1 检查 3：为什么继续比较子树
问题：根节点值相同是否足够？应比较哪些子树？结果如何组合？
我的回答（原文）
1. 为什么仅比较根节点 1 无法判断两棵树完全相同？因为两棵树相同必须比较节点的值和树的结构，不能仅比较根节点，还需要比较所有节点的左右子树。
2. 若两个根节点值相同，后续应该递归比较哪两组子树？两棵树的左子树以及两棵树的右子树
3. 最终要判定两棵树完全相同，两组子树的比较结果应该满足什么关系？两组子树的比较结果应该是同时满足相同的关系才行，用与来判断比较结果。

订正
全部正确。完整树相同的条件是：当前节点值相同 && 左子树相同 && 右子树相同。必须保持左右位置对应，不能用一棵树的左子树交叉比较另一棵树的右子树。
相关示例
树 A：     1        树 B：     1
          / \                / \
         2   3              2   4
左子树比较 true，右子树比较 false，整体 true && true && false 为 false。
面试专用回答
只比较根节点不足以确认两棵树相同，还要比较对应的左右子树。递归条件是当前节点值相同、左子树相同、右子树相同，三者通过逻辑与组合；只有全部满足才能返回 true。

问题：提供完整 Solution、提交情况，解释递归终止条件。
我的回答（原始代码）
class Solution {
public:
    bool isSameTree(TreeNode* p, TreeNode* q) {
        if(p == nullptr || q == nullptr){
            return p == q;
        }
        return (p -> val == q -> val) && isSameTree(p -> left, q -> left) && isSameTree(p -> right, q -> right);
    }

2.提交正确
3.第一个解决节点存储的数据值是否相同，第二个解决两棵树的左子树是否相同，第三个解决两棵树的右子树是否相同

订正
代码正确、提交通过。需区分术语：if (p == nullptr || q == nullptr) return p == q; 是明确的递归终止条件；p->val == q->val 是当前值判断，两次 isSameTree 是递归子问题。它们可以合称三个逻辑判断条件，但不能称为三个“递归终止条件”。&& 有短路性质，当前节点值不同则无需访问后续子树。
相关示例
p 根值 1，q 根值 9：
(p->val == q->val) == false
→ && 短路，不再调用 isSameTree(left/right)
面试专用回答
相同二叉树采用双节点递归：先处理两空或仅一空的结构差异，再比较当前节点值，最后递归比较对应左右子树。三个条件通过短路逻辑与组合，可以在发现差异时尽早返回 false。

3.3 Stage 2 检查 5：复杂度
问题：为什么最坏时间 O(n)、空间 O(h)？不同树形如何变化？根节点值不同能否提前结束？
我的回答（原文）
1. 为什么最坏时间复杂度可以表示为 O(n)？当两棵相同的树均有n个节点时，最坏需要比对n对节点，每次比较为O(1)
2. 为什么递归额外空间复杂度是 O(h)？因为递归额外空间复杂度取决于递归调用栈最大的深度，而递归调用栈的最大的深度即树的最大深度h
3. 平衡二叉树和退化为链表的情况分别是多少？O(log n) 和 O(n)
4. 如果一开始发现两个根节点值不同，后续还需要递归比较左右子树吗？为什么？不需要，因为一开始就发现两个根节点存储的数据值不同，那这两棵树必定不是同一棵树，所以可以直接返回，不用耗费复杂度再去递归比较左右子树

订正
四问正确。在两棵树结构相同、有 n 个节点且需要完整比较时，最多比较 n 对非空对应节点，时间 O(n)；递归栈最大深度随树高 h 变化，空间 O(h)。早期发现不同时实际耗时可能更小。
树形	时间	递归额外空间
平衡树	O(n)	O(log n)
退化为链表	O(n)	O(n)
一般二叉树	O(n)	O(h)


相关示例
两棵根节点值分别为 1、9 的非空树，比较根值后短路返回 false，实际只进行常数次操作；但最坏情况下仍需要比较完整树。
面试专用回答
最坏情况下，每对对应节点只比较一次，n 个节点得到 O(n) 时间复杂度；递归栈最大深度由树高 h 决定，因此额外空间为 O(h)，平衡树 O(log n)，链式树 O(n)。若根节点或子树早期存在差异，可利用 && 短路提前返回。

4.1 本阶段概念
- r.Body 是可读取 HTTP 请求体的 io.ReadCloser。
- json.NewDecoder(r.Body).Decode(&student)：从 JSON 请求体解码到 Go 结构体，需要可修改的目标地址。
- JSON 类型错误（如字符串 "abc" 解码到 int）与业务校验错误（如负 ID、空姓名）属于不同阶段。

4.2 完整预览接口代码（本阶段使用的 main.go）
package main

import (
    "encoding/json"
    "log"
    "net/http"
)

type Student struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
    Age  int    `json:"age"`
}

type ErrorResponse struct {
    Error string `json:"error"`
}

func writeJSON(w http.ResponseWriter, status int, data any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    if err := json.NewEncoder(w).Encode(data); err != nil {
        log.Printf("write JSON failed: %v", err)
    }
}

func studentPreviewHandler(w http.ResponseWriter, r *http.Request) {
    var student Student
    if err := json.NewDecoder(r.Body).Decode(&student); err != nil {
        writeJSON(w, http.StatusBadRequest, ErrorResponse{Error: "invalid JSON body"})
        return
    }
    if student.ID <= 0 || student.Name == "" || student.Age <= 0 {
        writeJSON(w, http.StatusBadRequest, ErrorResponse{Error: "invalid student data"})
        return
    }
    writeJSON(w, http.StatusOK, student)
}

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("POST /students/preview", studentPreviewHandler)
    log.Println("Preview server listening on http://127.0.0.1:8081")
    log.Fatal(http.ListenAndServe("127.0.0.1:8081", mux))
}

type StudentRepository struct {
    db *sql.DB
}

func NewStudentRepository(db *sql.DB) *StudentRepository {
    return &StudentRepository{db: db}
}

func (r *StudentRepository) GetByID(id int) (Student, error) {
    var student Student
    err := r.db.QueryRow(
        "SELECT id, name, age FROM students WHERE id = ?", id,
    ).Scan(&student.ID, &student.Name, &student.Age)
    if err != nil {
        return Student{}, err
    }
    return student, nil
}

func (r *StudentRepository) List() ([]Student, error) {
    rows, err := r.db.Query("SELECT id, name, age FROM students ORDER BY id")
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    students := make([]Student, 0)
    for rows.Next() {
        var student Student
        if err := rows.Scan(&student.ID, &student.Name, &student.Age); err != nil {
            return nil, err
        }
        students = append(students, student)
    }
    if err := rows.Err(); err != nil {
        return nil, err
    }
    return students, nil
}

func (r *StudentRepository) Create(student Student) error {
    _, err := r.db.Exec(
        "INSERT INTO students (id, name, age) VALUES (?, ?, ?)",
        student.ID, student.Name, student.Age,
    )
    return err
}

func (r *StudentRepository) Update(student Student) (int64, error) {
    result, err := r.db.Exec(
        "UPDATE students SET name = ?, age = ? WHERE id = ?",
        student.Name, student.Age, student.ID,
    )
    if err != nil {
        return 0, err
    }
    return result.RowsAffected()
}

func (r *StudentRepository) Delete(id int) (int64, error) {
    result, err := r.db.Exec("DELETE FROM students WHERE id = ?", id)
    if err != nil {
        return 0, err
    }
    return result.RowsAffected()
}

package main

import (

type ErrorResponse struct {
    Error string `json:"error"`
}

// 先完成序列化，再写出状态码，避免序列化失败后响应头已发送
func writeJSON(w http.ResponseWriter, status int, data any) {
    body, err := json.Marshal(data)
    if err != nil {
        log.Printf("JSON encoding failed: %v", err)
        http.Error(w, "internal server error", http.StatusInternalServerError)
        return
    }
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    if _, err := w.Write(append(body, '\n')); err != nil {
        log.Printf("write response failed: %v", err)
    }
}

func studentByIDHandler(repo *StudentRepository) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        idText := r.PathValue("id")
        studentID, err := strconv.Atoi(idText)
        if err != nil || studentID <= 0 {
            writeJSON(w, http.StatusBadRequest,
                ErrorResponse{Error: "invalid student id"})
            return
        }

        student, err := repo.GetByID(studentID)
        if errors.Is(err, sql.ErrNoRows) {
            writeJSON(w, http.StatusNotFound,
                ErrorResponse{Error: "student not found"})
            return
        }
        if err != nil {
            log.Printf("GetByID failed: %v", err)
            writeJSON(w, http.StatusInternalServerError,
                ErrorResponse{Error: "internal server error"})
            return
        }
        writeJSON(w, http.StatusOK, student)
    }
}

func studentsHandler(repo *StudentRepository) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        students, err := repo.List()
        if err != nil {
            log.Printf("List failed: %v", err)
            writeJSON(w, http.StatusInternalServerError,
                ErrorResponse{Error: "internal server error"})
            return
        }
        writeJSON(w, http.StatusOK, students)
    }
}

func createStudentHandler(repo *StudentRepository) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        var student Student
        err := json.NewDecoder(r.Body).Decode(&student)
        if err != nil {
            writeJSON(w, http.StatusBadRequest,
                ErrorResponse{Error: "invalid JSON body"})
            return
        }

        if student.ID <= 0 ||
            strings.TrimSpace(student.Name) == "" ||
            student.Age <= 0 {
            writeJSON(w, http.StatusBadRequest,
                ErrorResponse{Error: "invalid student data"})
            return
        }

        err = repo.Create(student)
        if err != nil {
            var sqliteErr sqlite3.Error
            if errors.As(err, &sqliteErr) &&
                (sqliteErr.ExtendedCode == sqlite3.ErrConstraintPrimaryKey ||
                    sqliteErr.ExtendedCode == sqlite3.ErrConstraintUnique) {
                writeJSON(w, http.StatusConflict,
                    ErrorResponse{Error: "student id already exists"})
                return
            }
            log.Printf("Create failed: %v", err)
            writeJSON(w, http.StatusInternalServerError,
                ErrorResponse{Error: "internal server error"})
            return
        }

        w.Header().Set("Location", "/students/"+strconv.Itoa(student.ID))
        writeJSON(w, http.StatusCreated, student)
    }
}

func main() {
    dbPath := filepath.Join("..", "day38-sql-persistence", "students.db")
    if _, err := os.Stat(dbPath); err != nil {
        log.Fatal(err)
    }

    db, err := sql.Open("sqlite3", dbPath)
    if err != nil {
        log.Fatal(err)
    }
    defer db.Close()
    if err := db.Ping(); err != nil {
        log.Fatal(err)
    }

    repo := NewStudentRepository(db)
    mux := http.NewServeMux()
    mux.HandleFunc("GET /students", studentsHandler(repo))
    mux.HandleFunc("GET /students/{id}", studentByIDHandler(repo))
    mux.HandleFunc("POST /students", createStudentHandler(repo))

    log.Println("Server listening on http://127.0.0.1:8081")
    if err := http.ListenAndServe("127.0.0.1:8081", mux); err != nil {
        log.Fatal(err)
    }
}

5.6 Stage 2 检查 4：POST 与 Repository
问题：为什么先解码和校验？为什么 Create() 不返回 HTTP 状态码？为什么成功创建返回 201？
我的回答（原文）
1. 为什么必须先解码并校验 JSON，再调用 Create()？因为客户端发来的请求数据不一定正确，需要先确保请求正确且数据满足业务逻辑再进行下游操作。
2. 为什么 Create() 方法内部不应该直接返回 HTTP 状态码？因为其属于数据库层，只专注于数据库相关操作以及返回结果，handler层负责根据数据库层返回的结果对应返回 HTTP 状态码，各司其职
3. 成功创建学生后，为什么使用 201 Created，而不是始终返回 200 OK？201 Created代表请求操作成功，更能凸显请求结果的正确性，而不是颗粒度较粗的200 OK

订正
三问正确。201 的精确语义是成功创建了新的资源，并非简单“比 200 更具体”。可以在响应中同时设置 Location 表示新资源访问地址。
相关示例
HTTP/1.1 201 Created
Location: /students/1005
Content-Type: application/json; charset=utf-8

{"id":1005,"name":"Eva","age":22}
面试专用回答
POST 创建资源时，Handler 负责解码、校验及 HTTP 响应，Repository 只负责写入数据库。成功创建应优先返回 201 Created，可通过 Location 指向新资源，避免在数据访问层直接耦合 HTTP 状态码。

5.7 Stage 2 检查 5：主键冲突与 errors.As()
问题：第二次插入为何失败？为何响应 409？errors.As(err, &sqliteErr) 做什么？
我的回答（原文）
1. 第一次插入成功后，第二次为什么可能失败？因为id是primary key主键，具有唯一性约束，所以第一次插入成功后，第二次插入会触发唯一性约束检验，导致重复主键无法插入
2. 为什么这种情况更适合返回 409 Conflict，而不是统一返回 500 Internal Server Error？同上题的第三问相似，更能凸显错误的具体原因，而不是颗粒度较粗的大类错误状态码
3. errors.As(err, &sqliteErr) 在这里起什么作用？判断错误是否是唯一性约束校验错误，用于handler层将具体错误映射成对应的状态码。

订正
前两问正确，第三问需精确：errors.As(err, &sqliteErr) 只负责识别并提取错误链中的 sqlite3.Error，并不能独自确认其为唯一性冲突。还需进一步检查 sqliteErr.ExtendedCode 是否为 ErrConstraintPrimaryKey 或 ErrConstraintUnique。
var sqliteErr sqlite3.Error
if errors.As(err, &sqliteErr) &&
    (sqliteErr.ExtendedCode == sqlite3.ErrConstraintPrimaryKey ||
     sqliteErr.ExtendedCode == sqlite3.ErrConstraintUnique) {
    // 409 Conflict
}
相关示例
第一次 INSERT 1005 → 成功
第二次 INSERT 1005 → SQLite 返回错误
  → errors.As 提取具体 SQLite 错误
  → ExtendedCode 判断主键/唯一约束类型
  → Handler 映射为 HTTP 409
后续工程化目标：将数据库专用错误在 Repository 中转换为应用统一错误，避免 Handler 对特定 SQLite 驱动的过强依赖。
面试专用回答
重复主键插入属于资源状态冲突，适合映射为 409。通过 errors.As 可以识别包装错误链中的具体 sqlite3.Error，再检查其 ExtendedCode 是否属于主键或唯一约束冲突。errors.As 自身不直接判断具体 SQLite 错误种类。

问题：解释 Decode、Create、writeJSON 发生在哪一层，解决什么问题。
我的回答（原文）
