## 二、C++ Day37：HashSet 与 HashMap

### 2.1 数据结构的本质区别

| 数据结构 | 主要用途 | 典型储存内容 |
| --- | --- | --- |
| `unordered_set<T>` | 判断某个元素是否出现，去重 | 元素本身，互异 |
| `unordered_map<K,V>` | 通过 Key 找到关联信息 | `元素 → 次数`、`元素 → 下标`、`ID → 姓名` |

判断思路：**如果只关心“在不在”，HashSet 足够；如果还需要“对应什么”，使用 HashMap。** 这不是绝对功能限制：HashMap 也能查询是否存在，但当不需要额外 Value 时，HashSet 更直接。两者的查找和插入平均为 O(1)，极端哈希冲突可能退化。

### 2.2 常用 `unordered_set` 操作

```cpp
#include <unordered_set>
using namespace std;

unordered_set<int> seen;
seen.insert(10);                          // 插入元素
bool exists = seen.find(10) != seen.end(); // 是否存在
bool found = seen.count(10) > 0;          // unordered_set 中为 0 或 1
size_t count = seen.size();               // 不同元素的数量
```

同一个值重复 `insert` 不会在集合中存储第二份；`unordered_set` 不保证遍历顺序。

### 2.3 Stage 1：检查 1（存在性判断）

**问题：** `nums=[1,5,7,9]`，判断是否存在数字 `5`。是否适合 HashSet？保存什么？为什么不用 HashMap？

**我的回答（原文）：**

> 1. 是否适合 HashSet？适合  
> 2. HashSet 保存什么？保存唯一的不重复的元素  
> 3. 为什么不用 HashMap？这里不需要保存元素的关联信息，只需要查看元素的存在性即可

**订正：** 完全正确。判断的是某个元素是否存在，不需要下标、频次或映射信息。

**相关示例：**

```cpp
unordered_set<int> seen{1, 5, 7, 9};
if (seen.find(5) != seen.end()) {
    cout << "5 exists\n";
}
```

**面试专用回答：** 当题目只要求元素存在性而不需要关联值时，优先使用 `unordered_set`；平均查找复杂度 O(1)。

### 2.4 Stage 1：检查 2（频次统计）

**问题：** `nums=[2,4,2,5,4]`，返回每个数字出现次数。HashSet 是否适合？更适合什么？Key 和 Value 是什么？

**我的回答（原文）：**

> 1. HashSet 是否适合？不适合  
> 2. 更适合什么？HashMap  
> 3. key 和 value 分别是什么？元素值和元素出现次数

**订正：** 完全正确。集合只保存不同元素，无法直接记录每个元素出现了几次；频次需要映射 `元素值 → 出现次数`。

**相关示例：**

```cpp
unordered_map<int, int> freq;
for (int num : nums) {
    freq[num]++;
}
// 2 → 2, 4 → 2, 5 → 1
```

**面试专用回答：** 需要元素频次时，以元素为 Key、次数为 Value 使用 HashMap，单次更新平均 O(1)，遍历 n 个元素平均 O(n)。

### 2.5 Stage 1：检查 3（综合识别）

**问题：** A. 判断数组中是否有重复；B. 返回每个元素首次出现的位置；C. 判断两个字符串包含的不同字符集合是否相同。

**我的回答（原文）：**

> A:  
> 数据结构：HashSet  
> 原因：不需要保存元素的关联信息，只需要查看元素的存在性即可  
>
> B:  
> 数据结构：HashMap  
> 原因：需要保存元素的关联信息，即元素的出现位置  
>
> C:  
> 数据结构：HashSet  
> 原因：不需要保存元素的关联信息，只需要查看元素的存在性即可，而且可以去重，完全相同的字符集合即看两个去重字符集合是否相等。

**订正：** 三项均正确。B 还需保证首次下标不被后来重复值覆盖；C 比较的是不同字符的集合，不是每种字符的出现次数。

**相关示例（B）：**

```cpp
vector<int> nums{5, 2, 5};
unordered_map<int, int> firstIndex;
for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
    if (firstIndex.find(nums[i]) == firstIndex.end()) {
        firstIndex[nums[i]] = i;
    }
}
// firstIndex[5] == 0，不会被第三个元素覆盖。
```

**相关示例（C）：** `"aaab"` 与 `"ab"` 的不同字符集合都为 `{a,b}`，所以集合相同；但频次不同，所以不是相同的字符频次分布。

**面试专用回答：** 仅判断重复可使用 HashSet；需要首次下标则用 HashMap，并仅在 Key 不存在时记录；比较字符种类用 HashSet，比较字符频次则需要 HashMap 或计数数组。

### 2.7 Stage 2：LeetCode 217（本人独立实现）

**问题：** 给定 `nums`，只要一个元素至少出现两次，就返回 `true`，否则返回 `false`。

**我的代码（原文）：**

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        unordered_set<int> set;
        for(int num : nums){
            if(set.find(num) == set.end()){
                set.insert(num);
            }
            else{
                return true;
            }
        }
        return false;
    }
};
```

**我的复杂度分析（原文）：**

> 时间复杂度：O(n)，只需要遍历一次数组，且每个元素最多insert一次进set中，insert一次的复杂度为O(1)  
> 空间复杂度：O(n)，遍历一次数组最坏情况下存储所有数组元素，即数组中全是不重复的元素  
> 提交至leetcode答题区域已通过。

**订正：** 代码正确，无须修改。`find()==end()` 表示未出现过，插入；否则发现重复直接返回 `true`。遍历结束返回 `false`。更能表达用途的可选命名是 `seen`，而非 `set`。

**相关示例：** 对 `[2,4,2,5,4]`：读到第一个 `2` 存 `{2}`；读 `4` 存 `{2,4}`；读到第二个 `2` 时已存在，立即返回 `true`，无需继续遍历。

**复杂度：** 数组规模 n，每次哈希查找/插入平均 O(1)，平均时间 O(n)；最坏存储 n 个不同元素，额外空间 O(n)。严谨地说，哈希严重冲突时可能退化，面试中通常给平均复杂度。

**面试专用回答：** 使用 HashSet 保存已经遍历的数字；每访问一个数字，先判断其是否已存在，若存在则发现重复并返回 true，否则插入集合。平均时间复杂度 O(n)、空间复杂度 O(n)。

### 3.3 Stage 1：INSERT 新增

例子：

```sql
INSERT INTO students (id, name, age)
VALUES (1004, 'David', 23);
```

- `INSERT INTO students`：要向哪张表插入。
- `(id, name, age)`：指定要填写的**列名**，不是列值。
- `VALUES (1004, 'David', 23)`：与列名按位置对应的实际数据。

#### 检查 1

**问题：** 解释 `INSERT INTO students`、列名列表 `(id, name, age)`、`VALUES (1004, 'David', 23)`。

**我的回答（原文）：**

> INSERT INTO students 的作用 = 决定向students表中插入记录  
> (id, name, age) 的作用 = 决定插入记录的字段数据，即需要插入的字段值  
> VALUES (1004, 'David', 23) 的作用 = 决定插入记录的实际值，且必须跟之前的字段名类型一一对应

**订正：** 总体正确，需将第二句“需要插入的字段值”精确改为“本次插入要填写的字段/列名”；真正的字段值在 `VALUES` 里。列名与值按顺序对应，且值必须满足对应列的数据类型和约束。

**相关示例：** `id ← 1004`、`name ← 'David'`、`age ← 23`。

**面试专用回答：** `INSERT INTO` 指定目标表与需要赋值的字段列表，`VALUES` 提供与其按位置对应的值，新增一条或多条记录。

#### 检查 2

**问题：** 新增 `id=1005, name=Eric, age=24`。

**我的回答（原文）：**

```sql
INSERT INTO students(id, name, age)
VALUES (1005, 'Eric', 24);
```

**订正：** 完全正确。可以统一排版为 `INSERT INTO students (id, name, age)`，属于风格优化。

**相关示例：** 此条插入后存在 `1005 | Eric | 24`，其他记录保持不变。

**面试专用回答：** 新增学生可以指定表名、字段名和对应 VALUES，为每个字段提供满足约束的数据。

#### 检查 3

**问题：** `id INTEGER PRIMARY KEY`，已有 `1001 | Alice | 20`，再插入 `1001 | Jack | 25` 会如何？

**我的回答（原文）：**

> 应该失败，因为id是主键，即区分记录的唯一标识，目前已经存在id=1001的记录，如果再插入id=1001的记录就打破了这个唯一性，所以我觉得应该插入失败，并且原纪录不变，只是插入操作失败。

**订正：** 正确。在当前表约束和普通 INSERT 下，重复的非空主键 `1001` 将违反唯一性而失败，原记录保持不变。

**相关示例：** 不能同时存在 `(1001,'Alice',20)` 与 `(1001,'Jack',25)` 两条相同主键的记录。

**面试专用回答：** 主键用于唯一标识一条记录；普通 INSERT 如果违反主键唯一约束，数据库会拒绝该插入，避免出现两个相同主键的记录。

**实际实验：** 已提供 PowerShell 截图，成功展示 `Before INSERT` 三行及 `After INSERT` 四行，新增 `1004 | David | 23`。此阶段已实测通过。

### 3.4 Stage 2：UPDATE 修改

例子：

```sql
UPDATE students
SET age = 21
WHERE id = 1001;
```

- `UPDATE students`：指定目标表。
- `SET age = 21`：指定要更改的字段和值。
- `WHERE id = 1001`：限制哪些行发生修改。

#### 检查 1

**问题：** 对 `UPDATE students SET age = 25 WHERE id = 1002;` 分析各部分职责。

**我的回答（原文）：**

> SET作用= 决定要修改哪个字段值  
> WHERE作用= 决定要修改的记录

**订正：** 完全正确。`SET` 不仅决定哪个字段，还指定其新值；`WHERE` 决定受影响的行。

**相关示例：** 原 `1002 | Bob | 21` 变为 `1002 | Bob | 25`，其余行不变。

**面试专用回答：** `UPDATE` 指定表，`SET` 定义要修改的字段及新值，`WHERE` 限制更新操作的目标行。

#### 检查 2

**问题：** 将 `id=1003` 的 `name` 修改为 Jerry。

**我的回答（原文）：**

```sql
UPDATE students
SET name = 'Jerry'
where id = 1003
```

**订正：** 正确，SQL 关键字大小写通常不敏感；建议统一 `WHERE` 大写并加分号。

```sql
UPDATE students
SET name = 'Jerry'
WHERE id = 1003;
```

**相关示例：** Tom 变为 Jerry，年龄仍然保持 22。

**面试专用回答：** 使用 UPDATE 修改已有记录，SET 指定需要更改的字段及新值，WHERE 按主键筛选目标记录。

#### 检查 3

**问题：** 为什么 `UPDATE students SET age = 30;` 危险？

**我的回答（原文）：**

> 这个修改数据的操作没有用where，最终会使得该表中所有记录全部更新，即所有记录的年轻全部更新为30，这通常不是用户预期的操作，一般要先筛选出需要修改的记录再执行修改操作

**订正：** 完全正确。无 WHERE 会修改所有行；“年轻”按上下文应为“年龄”，只是笔误。

**相关示例：** 之前 Alice、Bob、Tom 的年龄不同，执行无 WHERE 更新后都会变为 30。

**面试专用回答：** UPDATE 省略 WHERE 时会作用于整张表全部记录。上线前应检查条件和预期影响范围，可先使用相同条件的 SELECT 验证。

### 3.5 Stage 3：DELETE 删除

例子：

```sql
DELETE FROM students
WHERE id = 1003;
```

- `DELETE FROM students`：指定要从哪张表删除记录。
- `WHERE id = 1003`：限定删除哪条或哪些记录。

`DELETE FROM students;` 没有 WHERE，将删除全部记录，但表结构仍然存在；这和 `DROP TABLE students;` 删除整张表不同。

#### 检查 1

**问题：** 对 `DELETE FROM students WHERE id = 1002;` 解释 DELETE FROM 与 WHERE 的职责。

**我的回答（原文）：**

> DELETE FROM students作用= 决定要删除哪张表中的记录  
> WHERE作用=决定要删除哪些记录

**订正：** 完全正确。

**相关示例：** 删除 `id=1002` 时 Bob 消失，Alice、Tom 不受影响。

**面试专用回答：** DELETE FROM 指定目标表，WHERE 限定要移除哪些行，必须确认目标条件与影响范围。

#### 检查 2

**问题：** 删除 `name='Alice'` 的记录。

**我的回答（原文）：**

```sql
DELETE FROM students
WHERE name = 'Alice'
```

**订正：** SQL 正确，仅需按书写习惯补分号。注意若存在多位同名 Alice，将删除所有同名记录；删除特定个体最好使用唯一主键。

**相关示例：** `DELETE FROM students WHERE id = 1001;` 可以唯一指定 id 为 1001 的记录。

**面试专用回答：** 按姓名删除可用 WHERE name 条件，但姓名未必唯一；删除具体记录时应优先使用主键等唯一标识。

#### 检查 3

**问题：** 为什么 `DELETE FROM students;` 很危险？

**我的回答（原文）：**

> 因为该操作没有用where筛选出想要删除的记录，所以默认直接删除该表中所有记录，使得该表成为空表，这是非常危险的操作，所以DELETE操作和UPDATE操作一样需要事先确定where正确使用，避免一些误操作。

**订正：** 完全正确。无 WHERE 会删除表中全部记录，但不删除表结构。是否能撤销取决于执行方式、事务等，不能默认认为一定可恢复。

**相关示例：** 无 WHERE DELETE 后 `SELECT * FROM students` 返回空结果；但还可以向 `students` 表 INSERT 新记录，因为表仍存在。

**面试专用回答：** DELETE 没有 WHERE 会删除表内全部行。生产开发应确认 WHERE、影响行数及事务策略，避免误删。

### 4.5 `run_sql.py`（建议直接替换为这一份完整代码）

此前每阶段分别要求“追加代码”，但追加在 `finally: conn.close()` 后面会导致数据库连接已关闭，因此这里提供完整且一致的版本；在一个连接存活期间依次执行 INSERT、UPDATE、DELETE。

```python
from pathlib import Path
import sqlite3

base_dir = Path(__file__).resolve().parent

# 使用内存数据库，每次启动都从相同数据开始。
with sqlite3.connect(":memory:") as conn:
    def show_students(title):
        print(f"\n{title}")
        rows = conn.execute(
            "SELECT id, name, age FROM students ORDER BY id;"
        ).fetchall()
        for row in rows:
            print(*row, sep=" | ")

    setup_sql = (base_dir / "setup.sql").read_text(encoding="utf-8")
    conn.executescript(setup_sql)
    show_students("Before INSERT:")

    insert_sql = (base_dir / "insert.sql").read_text(encoding="utf-8")
    conn.executescript(insert_sql)
    show_students("After INSERT:")

    update_sql = (base_dir / "update.sql").read_text(encoding="utf-8")
```

## 五、今日易错点汇总

1. **HashSet 与 HashMap**：存在性/去重用 HashSet；需要下标、频次等关联信息用 HashMap。
2. **首次出现位置**：HashMap 只在 Key 尚不存在时写入，防止后续重复值覆盖首次下标。
3. **LeetCode 217**：先查找、后插入；发现重复就立即返回。
4. **复杂度**：哈希操作平均 O(1)，不能无条件声称最坏情况也是 O(1)。
5. **INSERT**：列名列表说明填写哪些字段，VALUES 提供实际值，须按位置与约束对应。
6. **PRIMARY KEY**：普通 INSERT 不能插入重复主键。
7. **UPDATE / DELETE**：不写 WHERE 就可能更新或删除全部行。
8. **DELETE ≠ DROP TABLE**：DELETE 删除行，DROP TABLE 删除表。
9. **按姓名删除**：姓名不一定唯一；删除特定实体更适合按主键筛选。
10. **连续 SQL 实验**：同一个内存数据库中前面的 INSERT / UPDATE 会影响后面的 DELETE 结果；每次重启 Python 进程则会重新建立内存数据库。
