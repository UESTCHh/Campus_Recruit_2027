# 二、C++ Stage 1：LC236 普通二叉树最近公共祖先

题目：LeetCode 236《二叉树的最近公共祖先》
https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/

## 2.1 LC235 与 LC236 的区别

LC235 的输入是 BST，可以利用左小右大的性质比较 p、q 与当前节点的值，沿一条方向搜索。

LC236 的输入是普通二叉树，不保证 BST 有序性，不能仅凭节点值大小决定搜索方向，需要分别递归左右子树。

示例：

```text
           3
         /   \
        5     1
       / \   / \
      6   2 0   8
         / \
        7   4
```

节点 5、4 都大于根节点 3，但它们都在根节点 3 的左子树中。这说明普通二叉树不能使用 BST 的大小关系判断搜索方向。

| 对比 | LC235 | LC236 |
|---|---|---|
| 树类型 | BST | 普通二叉树 |
| 是否利用节点值大小搜索 | 可以 | 不可以 |
| 搜索方式 | 沿一条方向 | 分别递归左右子树 |
| 时间复杂度 | O(h) | O(n) |
| 递归空间复杂度 | O(h) | O(h) |

## 2.2 递归返回值的含义

```cpp
TreeNode* left = lowestCommonAncestor(root->left, p, q);
TreeNode* right = lowestCommonAncestor(root->right, p, q);
```

在 LC236 原题保证 p、q 都存在的前提下：

1. 左右都非空：两个目标分别位于当前节点两侧，当前节点是 LCA。
2. 只有左侧非空：向上传递左侧结果。
3. 只有右侧非空：向上传递右侧结果。
4. 左右都为空，且当前节点不是 p、q：返回 nullptr。
5. 当前节点就是 p 或 q：直接返回当前节点。它可能是最终 LCA，也可能只是把找到的目标向上传递。

递归返回的非空节点既可能是目标 p/q，也可能是已经确定的最近公共祖先。

## 2.3 三道理解检查题

### 问题 1：普通二叉树为什么不能使用 LC235 的方法？

**我的回答（准确原话）：**

> 不能，因为今天的树是普通二叉树，不一定满足BST特性，所以5 和 4虽然比根节点一个大一个小，但是依然可能出现在同一侧子树中，不能再通过比较节点值大小来判断搜索方向了。最近公共祖先是5

**订正：完全正确。**

p=5、q=4。节点 5 是节点 4 的祖先，同时节点也可以是自己的祖先，因此最近公共祖先为 5。

**相关示例：** BST 可用大小关系判断方向；普通二叉树不具备该保证，必须检查左右子树。

**面试专用回答：**

> LC235 的输入是 BST，可以利用左小右大的性质，只沿一个方向查找。LC236 的输入是普通二叉树，不具有这种大小关系，因此需要递归检查左右子树，根据两个递归结果判断最近公共祖先。

### 问题 2：理解左右子树的递归返回值

**我的回答（准确原话）：**

> 1. 左子树（节点 6）应返回什么？返回6
> 2. 右子树（节点 2）最终应向节点 5 返回什么？返回4
> 3. 节点 5 根据两个返回值应该如何判断？如果两个返回值均不为空，则说明节点5两侧子树各一个目标节点，将自己返回给上一层，即将节点5返回给上一层，如果两个返回值有一个为空，一个非空，说明在一侧中找到了至少一个目标节点，另一个目标节点可能也在该侧子树中，也可能在其他节点的子树中，但肯定答案不是当前处理节点，所以将返回的非空节点返回给上一层，如果两个返回值都为空，则说明当前节点的子树中压根不含有目标节点，故直接返回空给上一层即可。

**订正：完全正确。**

递归过程：

1. 节点 6 是 p，返回节点 6。
2. 节点 2 的左侧没有目标，右侧节点 4 是 q，因此节点 2 返回节点 4。
3. 节点 5 收到左侧 6、右侧 4，左右均非空，返回节点 5。
4. 根节点 3 收到左侧节点 5、右侧 nullptr，继续返回节点 5。

**关键补充：** 非空返回值也可能是已经确定的 LCA，而不只是 p 或 q。

**面试专用回答：**

> 递归分别查找当前节点的左右子树。如果左右都返回非空指针，说明两个目标分别位于两侧，当前节点就是最近公共祖先。如果只有一侧非空，则把该侧结果继续向上传递；如果都为空且当前节点不是目标节点，则返回空指针。

### 问题 3：递归终止条件与结果传递

**我的回答（准确原话）：**

> 1. 当 `root == nullptr` 时应该返回什么？返回空
> 2. 当 `root == p` 或 `root == q` 时，为什么通常可以直接返回当前节点？因为如果当前节点等于其中一个目标节点，那另一个目标节点要么在该节点的子树中，要么在其他节点的子树中，上层通过比较两侧子树的返回值是否为空来判断另一个目标节点在该节点的子树中还是在其他节点的子树中，以根节点为例，假设左子树返回了p，右子树返回了空，那肯定q就是p的一棵子树包含的节点，所以p就是正确的最近公共祖先，故以p为答案提交。
> 3. 如果左递归返回有效指针、右递归返回 `nullptr`，为什么不能直接返回 `nullptr`，而要把左侧结果向上传递？因为无法判断另一个目标节点在该节点的子树中还是在其他节点的子树中，所以返回非空值让上一层再去判断。

**订正：**

第 1、3 问正确。第 2 问整体理解正确，但需要区分局部递归节点和最终 LCA：

```text
       3
      / \
     5   1
```

p=5、q=1。节点 5 发现自己是 p，会返回节点 5；节点 1 会返回 q；根节点 3 收到左右两个非空结果，才确定自己是 LCA。

如果 q 确实在 p 的子树中，则 p 本身就是 LCA。

**面试专用回答：**

> 当 root 为空时返回 nullptr；当 root 等于 p 或 q 时直接返回该节点，因为它可能是最近公共祖先，也可能只是需要继续向上传递的目标节点。其他情况下递归查找左右子树，根据返回值判断：左右均非空时当前节点是最近公共祖先；只有一侧非空时返回该侧结果；都为空时返回 nullptr。

## 2.4 Stage 2：独立编码 LC236

用户独立完成并提交通过的代码：

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        if(root == p || root == q || root == nullptr){
            return root;
        }
        TreeNode* left = lowestCommonAncestor(root -> left, p, q);
        TreeNode* right = lowestCommonAncestor(root -> right, p, q);

        if(left != nullptr && right != nullptr){
            return root;
        }
        return left != nullptr? left : right;
    }
};
```

**验收：LeetCode Accepted。**

复杂度：

- 时间复杂度 O(n)：普通二叉树最坏情况下需要遍历所有节点。
- 递归空间复杂度 O(h)：来自递归调用栈。平衡树通常 O(log n)，退化链表时 O(n)。

## 2.5 扩展：如果 p、q 可能不存在怎么办？

用户提出：

> 但是我想问如果该两个目标节点可能不存在如何处理？

原 LC236 代码依赖题目保证 p、q 均存在。若 q 不存在、p 存在，递归可能只找到 p，并将 p 当作结果返回。因此扩展题需要验证两个目标是否都存在。

### 方法一：先分别检查存在性，再运行原 LCA

```cpp
bool contains(TreeNode* root, TreeNode* target) {
    if (root == nullptr) {
        return false;
    }
    if (root == target) {
        return true;
    }
    return contains(root->left, target) ||
           contains(root->right, target);
}

TreeNode* dfs(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (root == nullptr || root == p || root == q) {
        return root;
    }

    TreeNode* left = dfs(root->left, p, q);
    TreeNode* right = dfs(root->right, p, q);

    if (left != nullptr && right != nullptr) {
        return root;
    }
    return left != nullptr ? left : right;
}

TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (!contains(root, p) || !contains(root, q)) {
        return nullptr;
    }
    return dfs(root, p, q);
}
```

时间复杂度 O(n)，递归空间复杂度 O(h)。最多多次遍历，但常数倍不改变大 O。

### 方法二：一次 DFS 记录 foundP、foundQ

```cpp
class Solution {
private:
    TreeNode* dfs(TreeNode* root, TreeNode* p, TreeNode* q,
                  bool& foundP, bool& foundQ) {
        if (root == nullptr) {
            return nullptr;
        }

        TreeNode* left = dfs(root->left, p, q, foundP, foundQ);
        TreeNode* right = dfs(root->right, p, q, foundP, foundQ);

        if (root == p) foundP = true;
        if (root == q) foundQ = true;

        if (root == p || root == q) {
            return root;
        }

        if (left != nullptr && right != nullptr) {
            return root;
        }

        return left != nullptr ? left : right;
    }

public:
    TreeNode* lowestCommonAncestor(TreeNode* root,
                                   TreeNode* p, TreeNode* q) {
        bool foundP = false;
        bool foundQ = false;

        TreeNode* result = dfs(root, p, q, foundP, foundQ);

        if (!foundP || !foundQ) {
            return nullptr;
        }
        return result;
    }
};
```

注意：一次 DFS 版本不能在发现 p 或 q 时立即停止遍历其子树，因为另一个目标可能位于它的后代中。

复杂度：时间 O(n)，递归空间 O(h)。

### 扩展检查题

树中有节点 5，但没有节点 99；p=5、q=99。

**我的回答（准确原话）：**

> 1. 递归结束后，`foundP` 和 `foundQ` 分别是多少？true, false
> 2. `dfs()` 返回的 `result` 是哪个节点？5
> 3. `lowestCommonAncestor()` 最终返回哪个节点？为什么？nullptr，因为有一个节点不存在，更不用说其公共祖先了，所以直接返回nullptr即可。

**订正：完全正确。**

`foundP=true`、`foundQ=false`；`dfs()` 可能返回节点 5，但外层检查到有一个目标不存在，最终返回 `nullptr`。

**面试专用回答：**

> 原 LC236 保证两个目标均存在，因此可以直接使用递归。如果不保证存在，需要额外检查两个目标是否都被找到。可以先分别进行存在性检查，也可以在一次 DFS 中记录 foundP、foundQ，只有两者都为 true 时才返回 LCA。一次 DFS 的时间复杂度 O(n)，递归空间复杂度 O(h)。

## 3.1 问题 1：数据库初始化与 Repository

**我的回答（准确原话）：**

> 1. `*sql.DB` 是不是代表一个固定的数据库连接？不是，它是一个数据库连接池管理对象，管理数据库连接，不是一个固定的数据库连接，而是管理数据库连接的池对象。
> 2. `NewStudentRepository(db)` 当前有没有真正执行 SQL？没有，只是将外部传入的数据库连接池管理对象赋值给Repository struct实例中，获得访问数据库的能力
> 3. 如果数据库文件存在，但没有 `students` 表，为什么 `initStudentTable(db)` 要放在 HTTP 服务启动之前？因为HTTP服务启动后可能业务逻辑中已经需要调用数据库对目标表进行相应的SQL操作了，这时如果没有students表就会报404 资源not found的错误，所以必须在HTTP服务启动之前将数据库结构初始化。

**订正：**

第 1、2 问完全正确。

`*sql.DB` 是数据库连接池管理对象，不是一条固定连接。`sql.Open()` 通常先返回管理对象，不代表已经立即建立实际连接；调用 `Ping()` 或执行 SQL 时才会按需获取或建立连接。

`NewStudentRepository(db)` 只是保存外部传入的 `*sql.DB`，不会自动执行 SQL。

第 3 问需要纠正 HTTP 状态码：

- 数据库没有 `students` 表，执行 SQL 时通常返回 SQLite 错误，Handler 将其映射为 HTTP 500。
- `students` 表存在，但没有对应学生记录，通常是 `sql.ErrNoRows`，Handler 返回 HTTP 404。
- HTTP 路由没有匹配，也可能返回 HTTP 404。

因此应在服务开始接收请求前初始化数据库结构。

启动顺序：

```text
读取 STUDENT_DB_PATH
    ↓
检查数据库文件
    ↓
sql.Open()
    ↓
db.Ping()
    ↓
initStudentTable(db)
    ↓
NewStudentRepository(db)
    ↓
registerStudentRoutes(mux, repo)
    ↓
http.ListenAndServe()
```

**面试专用回答：**

> `*sql.DB` 是数据库连接池管理对象，而不是单个数据库连接。Repository 通过依赖注入获得 `*sql.DB`，负责具体的数据访问操作。数据库初始化应该在 HTTP 服务启动前完成，确保业务请求到来时所依赖的表结构已经存在，避免因缺少数据库表而产生 SQL 执行错误。

## 3.2 问题 2：真实 HTTP CRUD 的执行链路

**我的回答（准确原话）：**

> 1. `ServeMux` 如何知道应该调用哪个 Handler？通过mux路由注册表中绑定的路由查找对应的handler。“PUT /students/{id}” -> updateStudentHandler(repo)

**订正：全部正确。**

### ServeMux

根据 HTTP 方法和请求路径匹配 Handler：

```go
mux.HandleFunc(
    "PUT /students/{id}",
    updateStudentHandler(repo),
)
```

请求 `/students/1001` 时，路径参数可以通过：

```go
r.PathValue("id")
```

获取。

### Handler

负责 HTTP 层：

- 解析请求参数。
- 解码 JSON。
- 校验请求数据。
- 调用 Repository。
- 根据结果或错误映射 HTTP 状态码。
- 返回 HTTP 响应。

### Repository

负责数据访问：

- 执行 SQL。
- 查询、插入、更新和删除记录。
- 返回查询结果、受影响行数和错误。

Repository 不应直接决定 HTTP 状态码，因为它不应依赖 HTTP 层。

此前真实 HTTP 验收流程：

```text
POST → GET → PUT → GET → DELETE → GET 404
```

PUT 返回 200 只能说明 Handler 返回成功状态；再次 GET 可以确认数据库实际保存的内容。

**面试专用回答：**

> ServeMux 根据 HTTP 方法和请求路径匹配对应的 Handler。Handler 负责请求解析、参数校验、业务处理及 HTTP 响应，Repository 负责具体的 SQL 数据访问操作。更新接口返回 200 只能说明请求处理成功，还需要通过 GET 验证数据库中的实际持久化结果。
