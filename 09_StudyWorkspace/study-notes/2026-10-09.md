# 第一部分：C++ Day36｜HashMap

## 三、核心知识：什么时候选择 HashMap

`unordered_map<Key, Value>` 使用键值映射，根据 Key 平均 `O(1)` 查询相应 Value。它适合快速判断一个键是否存在、定位键对应的额外信息，以及进行频次统计。

典型映射：

```text
数字         → 出现次数
数字         → 所在下标
学生 ID      → 姓名
商品 ID      → 库存数量
```

HashMap 的 Value 取什么，由题目要返回/维护什么决定：不总是「出现次数」。

与其他结构对照：

| 场景 | 优先考虑 | 理由 |
|---|---|---|
| 仅求一次数组最大值 | 遍历并维护最大值 | `O(n)` 时间、`O(1)` 额外空间，不需要额外结构 |
| 根据 ID 快速取关联数据 | HashMap | Key → Value 的平均快速查询 |
| 统计某数字出现次数 | HashMap | 数字 → 次数 |
| 多次动态取最小/最大 | Heap / Priority Queue | 反复访问当前极值 |
| 两数之和需要返回原数组下标 | HashMap | 数字 → 下标，快速查询补数 |

注意：`unordered_map` 的 `find`、插入等操作**平均**为 `O(1)`，哈希冲突极端情况下可能退化，不能称为无条件最坏 `O(1)`。

## 四、C++ Stage 1 检查与订正

### 检查 1：出现频率最高的数字

**问题：** `nums = [4,7,1,7,3]`，找出现次数最多的数字。应使用 HashMap 吗？保存什么？为什么不优先用 Heap？

**我的原回答：**

> 1. 是否优先想到 HashMap？是
> 2. HashMap 中保存什么？保存键值对即元素值 -> 出现次数
> 3. 为什么不用 Heap？heap适合动态集合反复取极值的问题，而这里需要记录元素的出现次数，需要有个数据机构能快速查询元素的出现次数。

**订正：** 完全正确。首先建立 `数字 → 次数` 的映射，例如 `7 → 2`。只求单个最高频数字时，可以在统计频次后遍历映射寻找最大频次，也可以在更新时维护当前最高频。**注意**如果是反复查询最高频或寻找 Top K 高频元素，HashMap + Heap 也可能合适；不能理解为 Heap 完全无用。

**相关示例：**

```cpp
unordered_map<int, int> freq;
for (int x : nums) {
    freq[x]++;
}
// freq[7] == 2
```

**面试专用回答：**

> 这类题首先需要统计每个元素出现的次数，因此使用 HashMap 保存元素值到频次的映射；若只需要一个最高频元素，可进一步维护或寻找最大频次，平均时间复杂度 O(n)、额外空间 O(n)。

### 检查 2：按学生 ID 查询姓名

**问题：** `students = [{id:1001,name:"Alice"},{id:1002,name:"Bob"}]`，输入 `1002` 快速查询姓名。

**我的原回答：**

> 1. 最自然的数据结构是什么？hashmap
> 2. key 和 value 分别是什么？key是id，value是对应的name值

**订正：** 完全正确。Key 是学生 ID，Value 是学生姓名，例如 `1002 → Bob`。

**相关示例：**

```cpp
unordered_map<int, string> names;
names[1001] = "Alice";
names[1002] = "Bob";
```

**面试专用回答：**

> 如果需要根据唯一 ID 快速查询关联信息，可以使用 HashMap 建立 ID 到信息的映射，平均查询复杂度为 O(1)。

### 检查 3：三个场景综合识别

**问题：** A 求数组最大值；B 找到和为 target 的两个元素；C 商品 ID 到当前库存数量。

**我的原回答：**

> A 维护一个最大值变量，遍历一次即可
>
> B hashmap，记录元素出现次数，每处理一个元素时判断target - 当前元素是否出现过
>
> C HashMap，将商品ID设为KEY，当前库存数量设为VALUE，这样通过商品ID能够实时且快速地得到当前商品库存数

**订正：**

- **A 正确：** 单次求最大值直接遍历维护变量；不需要为此建 HashMap。
- **B 模型正确，但 Value 不准确：** 两数之和题目要求返回**下标**，所以 HashMap 应保存 `元素值 → 已见元素下标`，而不是 `元素值 → 出现次数`。查找 `target - nums[i]` 的思路正确。
- **C 正确：** 商品 ID → 库存数量。HashMap 能平均快速查询、更新，但内存数据结构本身不自动保证数据持久化或并发一致性。

**相关示例（Two Sum）：**

```text
nums = [2,7,11,15], target = 9
读到 nums[0]=2，记录 2 → 0
读到 nums[1]=7，需要找 9-7=2
查到 2 → 0，返回下标 0 和 1
```

**面试专用回答：**

> 选择数据结构时先看所需操作：单次找最大值直接遍历；快速判断补数是否出现并返回索引，使用 HashMap 的值到索引映射；基于商品 ID 查询库存，使用 ID 到数量的映射。

## 五、`unordered_map` 基础代码实验

文件：`unordered_map_demo.cpp`

```cpp
#include <iostream>
#include <string>
#include <unordered_map>
#include <vector>

using namespace std;

int main() {
    // 1. 数字 -> 出现次数
    vector<int> nums{4, 7, 1, 7, 3};
    unordered_map<int, int> freq;

    for (int num : nums) {
        // key不存在时，operator[]会创建一个默认的int值0
        freq[num]++;
    }

    cout << "7 count = " << freq[7] << '\n';
    cout << "4 count = " << freq[4] << '\n';

    // 2. 学生ID -> 姓名
    unordered_map<int, string> students;
    students[1001] = "Alice";
    students[1002] = "Bob";

    auto it = students.find(1002);
    if (it != students.end()) {
        cout << "Student 1002 = " << it->second << '\n';
    }

    // 3. find查找不存在的key不会自动插入
    auto notFound = students.find(9999);
    if (notFound == students.end()) {
        cout << "Student 9999 not found\n";
    }

    return 0;
}
```

## 六、LeetCode 1：Two Sum 独立实现

### 题意与关键思路

给定 `nums` 和 `target`，找到两个不同下标 `i`、`j`，使 `nums[i]+nums[j]==target`，并返回这两个下标。

思路：

```text
从左至右遍历 nums[i]
↓
计算 complement = target - nums[i]
↓
查询已经出现过的元素值是否包含 complement
↓
若存在，直接返回保存的下标和 i
↓
若不存在，保存 nums[i] → i
```

**先查后存**能防止同一个数组下标被使用两次。

### 我的完整原代码

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> map;
        for(int i = 0; i < static_cast<int>(nums.size()); i++){
            auto it = map.find(target - nums[i]);
            if(it != map.end()){
                return {i, map[target - nums[i]]};
            }
            map[nums[i]] = i;
        }
        return {-1, -1};
    }
};
```

**我的复杂度回答：**

> 时间复杂度O(n)
> 空间复杂度O(n)

### 订正

**算法正确，复杂度正确。** 先查再插保证了不会把当前元素与它自己配对。

可做的小优化：

```cpp
auto it = map.find(target - nums[i]);
if (it != map.end()) {
    return {it->second, i};
}
```

因为 `find()` 已经返回迭代器，无须再调用 `map[target - nums[i]]` 重复查找。

### 相关示例：重复值

```text
nums=[3,3], target=6

i=0: map为空，先查3失败，保存 3 → 0
i=1: 查3成功，得到之前下标0
返回 [0,1] 或 [1,0] 都正确
```

### 推荐写法（补齐独立编译所需头文件）

```cpp
#include <unordered_map>
#include <vector>

using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> indices;

        for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
            int complement = target - nums[i];
            auto it = indices.find(complement);

            if (it != indices.end()) {
                return {it->second, i};
            }

            indices[nums[i]] = i;
        }

        return {-1, -1};
    }
};
```

这是 LeetCode 提交用的 `class Solution`，并非带 `main()` 的 ACM 格式程序。

### 复杂度

- `n` 为数组长度。
- 平均时间复杂度：`O(n)`，一次遍历，每次 HashMap 查询/插入平均 `O(1)`。
- 额外空间复杂度：`O(n)`，HashMap 最多保存线性数量的键值对。
- `unordered_map` 在极端哈希冲突情况下可能退化，面试通常说明平均复杂度即可。

### 面试专用回答

> 使用 HashMap 保存已经遍历的元素值及对应下标。对当前元素求 `target-nums[i]`，先查询补数是否在 HashMap 中，存在则返回两个不同下标，否则记录当前元素。平均时间复杂度 O(n)，额外空间复杂度 O(n)。

## 十、SQL Stage 2：WHERE 条件查询

### 概念

`WHERE` 根据条件筛选记录（行）。

```sql
SELECT id, name, age
FROM students
WHERE id = 1002;
```

查询出 Bob 的一条记录。

比较符号：

| SQL | 含义 |
|---|---|
| `=` | 等于 |
| `<>` | 不等于 |
| `>` | 大于 |
| `>=` | 大于等于 |
| `<` | 小于 |
| `<=` | 小于等于 |

SQL 判断相等用 `=`，不要机械套用 C++/Go 的 `==`。

### 检查 1：SELECT 与 WHERE 的职责

**问题：** `SELECT name FROM students WHERE age >= 21;`

**我的原回答：**

> SELECT 决定显示的列，即最后返回字段为name的列信息
> WHERE 决定显示的行，即最后返回age>=21的学生信息
> 最终返回哪些学生的姓名？'Bob'、'Tom'

**订正：** 完全正确。`WHERE` 保留 Bob、Tom 两行，`SELECT` 返回两行中的 `name` 字段。没有 `ORDER BY` 时不保证返回顺序。

**相关示例：** 改成 `SELECT id FROM students WHERE age >= 21;`，返回字段就变成 1002、1003。

**面试专用回答：**

> SELECT 控制查询结果中的列，WHERE 控制哪些记录进入结果集。例如年龄不低于21的学生姓名，可写 `SELECT name FROM students WHERE age >= 21;`。

### 检查 2：独立写 SQL

**问题：** 查询 `id = 1003` 的学生，只返回 `name`、`age`。

**我的原回答：**

```sql
SELECT name, age from students where id = 1003
```

**订正：** 语义完全正确。建议关键字大写、换行、结尾加分号。

```sql
SELECT name, age
FROM students
WHERE id = 1003;
```

**相关示例：** 结果是 `Tom | 22`。

**面试专用回答：**

> 按主键查询时，在 WHERE 中指定主键条件，并通过 SELECT 选择所需字段即可，避免返回无关列。

### 检查 3：`>` 与 `>=`

**我的原回答：**

> 前者筛选age > 20的学生记录，后者筛选age >=20的学生记录，即多了一个等于的满足条件
> 分别会得到'Bob'、'Tom' 和 'Alice'、'Bob'、'Tom'

**订正：** 完全正确。

**相关示例：** `age > 20` 不包含 Alice（20岁）；`age >= 20` 包含 Alice。

**面试专用回答：**

> WHERE 的 `>` 表示严格大于，不包括边界；`>=` 表示大于等于，包含边界值。

```sql
LIMIT 2;
```

含义：筛选年龄不低于20岁的学生，按年龄降序排序，最多返回两条，只返回姓名与年龄字段。

| 关键字 | 作用 |
|---|---|
| `ORDER BY age ASC` | 按年龄升序排序（ASC 通常可省略） |
| `ORDER BY age DESC` | 按年龄降序排序 |
| `LIMIT 2` | 最多返回两条记录，不决定哪两条“最大/最小” |

**没有 `ORDER BY` 时，SQL 结果没有保证的顺序**。如果要稳定处理年龄并列，可进一步写 `ORDER BY age DESC, id ASC`。

### 检查 1：升序和 LIMIT

**问题：** `SELECT name, age FROM students ORDER BY age ASC LIMIT 2;`

**我的原回答：**

> ORDER BY age ASC 的含义 = 根据age字段的值升序排列
> LIMIT 2 的含义 = 只返回两条记录
> 最终返回哪些记录 = Alice  20
> Bob 21

**订正：** 完全正确。更严谨地说，LIMIT 2 是“最多”返回两行；这里只有三条符合记录，所以确实返回两行。

**相关示例：** 改成 `ORDER BY age DESC LIMIT 2` 则返回 Tom、Bob。

**面试专用回答：**

> ORDER BY 指定排序字段和方向，ASC 为升序；LIMIT 用于限制最大返回记录数。先按年龄升序排序再取前两条，得到年龄最小的两位学生。

### 检查 2：独立编写组合 SQL

**问题：** 查询年龄严格大于20岁的学生，只返回姓名，按年龄降序，最多一条。

**我的原回答：**

```sql
SELECT name
From students
where age > 20
ORDER BY age DESC
LIMIT 1
```

**订正：** 完全正确。统一格式：

```sql
SELECT name
FROM students
WHERE age > 20
ORDER BY age DESC
LIMIT 1;
```

**相关示例：** 返回 `Tom`。改成升序 `ASC` 则返回 `Bob`。

**面试专用回答：**

> 使用 WHERE 筛选年龄大于20的学生，再通过 ORDER BY age DESC 排序，最后 LIMIT 1 获取年龄最大的学生姓名。

### 检查 3：LIMIT 为什么不能替代 ORDER BY

**我的原回答：**

> ORDER BY 负责决定根据哪个字段的值进行排序，默认是ASC升序排序，而不用该关键字则无法保证返回结构的顺序
>
> LIMIT负责决定返回记录的数量
>
> SELECT name
> FROM students
> LIMIT 2;
>
> 只能确定返回2条记录
>
> SELECT name
> FROM students
> ORDER BY age DESC
> LIMIT 2;
>
> 能确定返回根据年龄降序排列的两条记录，即年龄前2大的两条记录

**订正：** 完全正确。前者没有排序约束，不能保证是哪两位学生；后者按年龄降序选取前两条。若存在年龄并列，是否稳定返回同一组/同一顺序还取决于并列处理规则。

**相关示例：**

```sql
SELECT name
FROM students
ORDER BY age DESC, id ASC
LIMIT 2;
```

**面试专用回答：**

> LIMIT 只限制结果行数，不保证记录顺序；如需 Top N，应结合 ORDER BY 明确排序规则，必要时增加次级排序字段以处理并列数据。

## 十二、今日易错点与统一记忆

**C++**

1. HashMap 的 Value 不是固定的频次：Two Sum 需要返回下标，因此记录 `数字 → 下标`。
2. `m[key]` 在 Key 不存在时可插入默认 Value；`m.find(key)` 仅查找，不自动插入。
3. Two Sum 应先查补数、后保存当前数，防止同一位置被使用两次。
4. `it->second` 已经获取目标下标，无须重复用 `m[complement]` 查询。
5. `unordered_map` 的 `O(1)` 是平均复杂度，不是严格保证的最坏复杂度。

**SQL**

1. `SELECT` 选列；`WHERE` 筛选行；`ORDER BY` 排序；`LIMIT` 限数量。
2. SQL 等号是 `=`，不是 C++/Go 的 `==`。
3. `>` 不包含边界，`>=` 包含边界。
4. 不写 `ORDER BY`，即使表中展示顺序看起来稳定，也不能依赖它。
5. `LIMIT 2` 是最多返回两条，不代表返回年龄最大的两条。
6. 普通 Go map 不自动持久化；SQLite 的内存模式与文件模式的持久化行为不同。
