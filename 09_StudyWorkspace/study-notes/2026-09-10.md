# 三、Prefix Sum 的核心问题

原数组：

```text
2 4 1 7 3 6
```

如果只查询一次：

```text
[1, 4]
```

可以直接：

```text
4 + 1 + 7 + 3
= 15
```

使用循环：

```cpp
int sum = 0;

for (int i = 1; i <= 4; ++i)
{
    sum += numbers[i];
}
```

一次区间查询最坏：

```text
O(n)
```

但如果存在大量 Query：

```text
[1, 4]
[0, 2]
[2, 5]
[3, 3]
[0, 5]
...
```

每次重新遍历区间会产生大量重复计算。

Prefix Sum 的目标：

```text
提前做一次预处理
↓
保存累计信息
↓
以后快速回答任意区间和
```

---

# 四、Prefix Sum 定义

今天采用：

```text
prefix[i]
```

表示：

```text
原数组前 i 个元素的累加和
```

因此：

```text
prefix[0]
→ 前0个元素之和
→ 0
```

```text
prefix[1]
→ numbers[0]
```

```text
prefix[2]
→ numbers[0] + numbers[1]
```

```text
prefix[3]
→ numbers[0] + numbers[1] + numbers[2]
```

一般：

```text
prefix[i]

=
numbers[0]
+ numbers[1]
+ ...
+ numbers[i - 1]
```

注意：

```text
prefix[i]
```

不是：

```text
numbers[i]位置的前缀和
```

而是：

```text
前 i 个元素之和
```

---

# 五、为什么 `prefix[0] = 0`

```text
prefix[0]
```

表示：

```text
前0个元素的和
```

所以自然：

```text
prefix[0] = 0
```

如果：

```text
numbers.size() = n
```

则：

```text
prefix.size() = n + 1
```

例如：

```text
numbers:

2 4 1 7 3 6

size = 6
```

Prefix：

```text
0 2 6 7 14 17 23

size = 7
```

---

# 六、Prefix Sum 构造公式

核心递推：

```cpp
prefix[i + 1]
=
prefix[i] + numbers[i];
```

原因：

```text
prefix[i]
→ 已经保存前i个元素之和
```

再加入：

```text
numbers[i]
```

即数组中：

```text
第 i+1 个元素
```

就得到：

```text
前 i+1 个元素之和
```

因此：

```text
prefix[i]
+
numbers[i]
↓
prefix[i + 1]
```

# 八、闭区间 Range Sum

要求查询：

```text
[left, right]
```

核心公式：

```cpp
prefix[right + 1]
-
prefix[left]
```

即：

```text
sum(left, right)

=
prefix[right + 1]
-
prefix[left]
```

# 九、为什么公式成立

例如：

```text
[left, right]
=
[1, 4]
```

原数组：

```text
2 4 1 7 3 6
```

`prefix[right + 1]`：

```text
prefix[5]

=
numbers[0]
+ numbers[1]
+ numbers[2]
+ numbers[3]
+ numbers[4]
```

即：

```text
2 + 4 + 1 + 7 + 3
= 17
```

而：

```text
prefix[left]
=
prefix[1]
```

表示：

```text
numbers[0]
= 2
```

相减：

```text
(2 + 4 + 1 + 7 + 3)
-
2
```

公共前缀：

```text
numbers[0]
```

被抵消。

最终：

```text
4 + 1 + 7 + 3
= 15
```

所以：

```cpp
prefix[right + 1] - prefix[left]
```

本质是：

```text
两个Prefix的公共部分相互抵消
```

# 十、为什么必须 `right + 1`

定义：

```text
prefix[i]
→ 前i个元素之和
```

如果右边界：

```text
right = 4
```

我们希望包含：

```text
numbers[4]
```

那么需要包含：

```text
numbers[0]
numbers[1]
numbers[2]
numbers[3]
numbers[4]
```

一共：

```text
5
```

个元素。

所以应该：

```text
prefix[5]
```

即：

```text
prefix[right + 1]
```

而：

```text
prefix[right]
```

只会包含到：

```text
numbers[right - 1]
```

无法包含 `numbers[right]`。

# 十一、`prefix[0] = 0` 带来的统一公式

如果查询：

```text
[0, 2]
```

依然：

```cpp
prefix[2 + 1] - prefix[0]
```

得到：

```text
prefix[3] - 0
= 7
```

对应：

```text
2 + 4 + 1
= 7
```

因此不需要：

```cpp
if (left == 0)
{
    ...
}
else
{
    ...
}
```

所有区间统一：

```cpp
prefix[right + 1] - prefix[left]
```

---

# 十二、如果不用 n+1 Prefix

假设定义：

```text
prefix[0] = numbers[0]
```

那么普通查询可能要：

```cpp
prefix[right] - prefix[left - 1]
```

但当：

```text
left == 0
```

时：

```text
left - 1
```

不存在。

所以要单独：

```cpp
if (left == 0)
{
    return prefix[right];
}
```

而今天的设计：

```text
prefix[0] = 0
prefix.size() = n + 1
```

消除了这种边界特判。

这是一种很重要的思想：

```text
通过数据结构设计
↓
减少边界特殊处理
```

# 十五、Prefix Sum 时间复杂度

构造 Prefix：

```text
遍历一次numbers
```

所以：

```text
Preprocessing
→ O(n)
```

以后每次查询：

```cpp
prefix[right + 1]
-
prefix[left]
```

只涉及：

```text
两次数组访问
+
一次减法
```

所以：

```text
Single Query
→ O(1)
```

# 十六、多次 Query

假设：

```text
n个元素
q次区间查询
```

暴力：

```text
一次Query
→ 最坏O(n)

q次
→ O(qn)
```

Prefix Sum：

```text
预处理：
O(n)

q次Query：
q × O(1)
= O(q)
```

总：

```text
O(n + q)
```

---

# 十七、Prefix Sum Extra Space

Prefix 数组大小：

```text
n + 1
```

所以：

```text
Extra Space
→ O(n)
```

这也是 Prefix Sum 的代价：

```text
花 O(n) 预处理时间
+
花 O(n) Extra Space
↓
换取每次区间查询 O(1)
```

属于：

```text
Precomputation
预处理
```

思想。

---

# 十八、Prefix Sum vs Sliding Window

二者共同点：

```text
都在避免对连续区间进行重复计算
```

但使用方式不同。

## Sliding Window

```text
维护当前Window
↓
Window按照某种规则连续移动 / 扩张 / 收缩
↓
使用旧Window State
↓
增量更新新Window State
```

例如：

```text
[0,2]
↓
[1,3]
↓
[2,4]
↓
[3,5]
```

重点：

```text
当前Window
```

通常不保存所有过去的 Window State。

---

## Prefix Sum

```text
提前计算并保存
从数组开头到各个位置的累计State
```

预处理以后可以随机询问：

```text
[1,4]
[0,2]
[3,5]
[2,2]
```

Query 不需要：

```text
连续移动
```

直接：

```cpp
prefix[right + 1] - prefix[left]
```

即可。

---

## 最终区别

```text
Sliding Window
→ 维护当前Window
→ Window按规则移动
→ 增量更新当前State
```

```text
Prefix Sum
→ 预处理所有Prefix State
→ 任意区间随机Query
→ O(1)回答区间和
```

空间：

```text
Sliding Window
→ 常见O(1) Extra Space

Prefix Sum
→ O(n) Extra Space
```

## 问题 4

为什么：

```cpp
prefix[right + 1] - prefix[left]
```

得到 `[left, right]`？

### 我的回答

> prefix[right + 1]表示前right+1个元素的累加和，即numbers[0] + numbers[1] + ... + numbers[right]，而prefix[left]表示前left个元素的累加和,即numbers[0] + numbers[1] + ... + numbers[left - 1]；故prefix[right + 1] - prefix[left]即将它们的公共前缀抵消 ，得到numbers[left] + .... + numbers[right]，即[left, right]区间内的元素累加和

### 订正

完全正确。

这是 Prefix Sum 的核心数学原理：

```text
大Prefix
-
小Prefix
↓
公共前缀抵消
↓
得到目标区间
```

## 问题 5

为什么使用 `right + 1`？

### 我的回答

> 因为prefix[right + 1]表示前right+1个元素的累加和，而元素下标是从0开始的，故prefix[right + 1]代表numbers[0] + numbers[1] + ... + numbers[right]，所以如果有边界是right的话，需要用right + 1，这也因为prefix[0] = 0导致prefix数组比原数组多一个元素。

### 订正

完全正确。

```text
要包含numbers[right]
↓
需要包含前right+1个元素
↓
prefix[right+1]
```

## 问题 6

为什么 `prefix[0]=0` 可以消除特判？

### 我的回答

### 订正

完全正确。
