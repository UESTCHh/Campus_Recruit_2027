# 四、Iterator Range

标准算法大量使用：

```cpp
algorithm(first, last)
```

例如：

```cpp
sort(
    numbers.begin(),
    numbers.end()
);
```

其操作区间是：

```text
[begin, end)
```

即：

```text
左闭右开
```

其中：

```text
begin()
→ 指向第一个元素

end()
→ 指向最后一个有效元素之后的位置
```

所以：

```text
[begin, end)
```

刚好包含全部有效元素。

常见时间复杂度：


# 六、`std::reverse`

例如：

```cpp
reverse(
    numbers.begin(),
    numbers.end()
);
```

它的作用：

```text

```

例如：

```text

```

变成：

```text

```

但是：

```text

≠
降序排序
```


```text

```

`reverse` 常见复杂度：

```text
O(n)
```

# 八、为什么 `std::find` 是 O(n)

需要特别修正一个认识。

`std::find` 在 `vector` 中通常：

```text
O(n)
```

并不是因为：

```text
vector是连续存储
```

真正原因是：

```text
std::find本身就是线性扫描算法
```

可以近似理解为：

```cpp
for (auto it = first; it != last; ++it)
{
    if (*it == value)
    {
        return it;
    }
}
```

最坏情况：

```text
目标在最后
或
目标不存在
```

需要检查全部：

```text
n个元素
```

所以：

```text
O(n)
```

# 九、`std::find` vs `map::find`

```cpp
std::find(
    first,
    last,
    value
)
```

属于：

```text
通用算法
```

通常：

```text
逐个比较
→ O(n)
```

而：

```cpp
map.find(key)
```

属于：

```text
map自己的成员函数
```

它可以利用：

```text
map内部维护的有序关联结构
+
Comparator
```

进行查找。

所以常见：

```text
O(log n)
```

同样：

```text
unordered_map.find()
```

利用 Hash Table，平均：

```text
O(1)
```

因此：

```text
函数名字都叫find
≠
算法和复杂度相同
```

# 十三、Comparator

`sort` 可以：

```cpp

    first,
```

第三个参数：


称为：

```text
Comparator
```

它定义：


# 十四、普通函数 Comparator

例如：

```cpp
bool descending(
    int a,
    int b
)
{
    return a > b;
```

```cpp

    numbers.end(),
```

```cpp

```

```cpp

```

```text

```

排序过程中：

```text

```

类似：

```cpp

```

而：

```cpp
descending()
```

表示：

```text
现在立即调用函数
```

不是把函数本身传进去。

# 二十、Comparator 为什么不能随便使用 `>=`

例如：

```cpp
return a >= b;
```

当：

```text
a == b
```

时：

```text
comp(a, b)
→ true
```

同时：

```text
comp(b, a)
→ true
```

于是规则同时认为：

```text
a应该在b前
+
b应该在a前
```

产生矛盾。

因此给 `sort` 写 Comparator 时，一般应该使用：

```cpp
<
>
```

这样的严格比较。

不要使用：

```cpp
<=
>=
```

以后会正式学习：

```text
Strict Weak Ordering
```
