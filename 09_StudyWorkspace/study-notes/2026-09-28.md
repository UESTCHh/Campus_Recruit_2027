# 十七、LeetCode 23 Merge k Sorted Lists

核心：

```text
K条升序链表
↓
每条链表只暴露当前头节点
↓
Min Heap
↓
pop当前最小节点
↓
连接到结果链表
↓
push node->next
```

# 十八、我的代码

```cpp
class Solution {
private:
    struct Compare {
        bool operator()(
            ListNode* a,
            ListNode* b
        ) const {
            return a->val > b->val;
        }
    };

public:
    ListNode* mergeKLists(
        vector<ListNode*>& lists
    ) {
        if(static_cast<int>(lists.size()) == 0) return nullptr;

        priority_queue<
            ListNode*,
            vector<ListNode*>,
            Compare
        > minHeap;

        for (ListNode* Node : lists){
            if(!Node) continue;
            minHeap.push(Node);
        }

        ListNode dummy;
        ListNode* tail = &dummy;

        while(!minHeap.empty()){
            ListNode* topNode = minHeap.top();
            minHeap.pop();

            tail->next = topNode;

            if(topNode && topNode -> next){
                minHeap.push(topNode -> next);
            }

            tail = tail->next;
        }

        return dummy.next;
    }
};
```

# 三十五、Stage 3检查 4

### 我的回答

> Context 中的数据传播方向，和 Middleware 的 Before / After 洋葱执行方向之间是相同的。
>
> Context随着请求r不断沿请求链传播，而Middleware 的 Before / After 洋葱执行方向就跟普通函数调用类似，也是沿着请求链不断调用返回，r也在此过程中随着调用函数的传入不断沿请求链传播

### 订正

这里需要校准。

Middleware：

```text
Before
外 → 内

After
内 → 外
```

Context新Request：

```text
通过next向下游传播
外 → 内
```

不会随着 After 自动反向传播。

# 三十六、最终确认题

A 添加：

```text
userID
```

B 添加：

```text
traceID
```

### 我的回答

```text
Handler：
能读userID？是
能读traceID？是

B After：
能读userID？是
能读traceID？是

A After：
能读userID？是
能读traceID？否
```

> 因为Context会随着新请求r沿请求链向下游传播但不会自动返回给上层，所以上层是无法获取内层创建的新请求r，自然也无法读取新请求r携带的新数据

### 订正

完全正确。

### 面试专用回答

> Middleware 的控制流在返回阶段会从内向外，但通过 `WithContext` 创建的新 Request 只会向下游传播。下游创建的新 Context 不会自动更新上游 Middleware 手中的 Request。
