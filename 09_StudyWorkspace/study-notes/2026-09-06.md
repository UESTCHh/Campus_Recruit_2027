## 问题 1：map / set / multiset

### 我的回答

> map key-value键值对 key不能重复，value可以重复
>
> set 只存储元素本身，元素本身value就是key，key不能重复
>
> multiset 只存储元素本身，元素本身value就是key，key能重复

### 订正

整体正确。

统一表达：

```text
map
→ Key → Value
→ Key唯一
→ Value可以重复

set
→ 只存Key
→ 元素本身就是Key
→ Key唯一

multiset
→ 只存Key
→ 元素本身就是Key
→ Key允许重复
```

更标准的术语是：

```text
set没有独立的mapped value
元素本身就是Key
```

而不是简单说：

```text
value就是key
```

状态：

```text
✅ 已牢固
```

## 问题 2：为什么 set 元素不能直接修改

### 我的回答

> 因为set 只存储元素本身，元素本身value就是key，key不能重复，元素不能通过普通 Iterator 随意修改

```text
set中的元素本身就是Key
```

```text
Key不能重复
```

所以：

```text
set元素不能直接修改的根本原因
```

如果需要改变元素：

```text
erase旧值
↓
insert新值
```

## 问题 3：lower_bound / upper_bound

### 我的回答

> lower_bound(k)是查找第一个大于或等于k的元素，upper_bound(k)是查找第一个严格大于k的元素，这样形成的左闭右开区间[lower_bound(k), upper_bound(k))刚好可以表示`multiset` 中所有等于 `k` 的元素 ，即 k <= target < k + o -> target = k

### 订正

核心完全正确：

```text
lower_bound(k)
→ 第一个 >= k

upper_bound(k)
→ 第一个 > k
```

所以：

```text
[lower_bound(k), upper_bound(k))
```

就是：

```text
从第一个等于k的位置
一直到第一个大于k的位置之前
```

因此恰好包含所有：

```text
== k
```

的元素。

最后：

```text
k <= target < k + o
```

不需要保留，直接使用：

```text
第一个 >= k
到
第一个 > k
```

更加准确。

状态：

```text
✅ 已牢固
```

## 问题 8：vector vs deque

### 我的回答

> vector是连续内存空间，而deque不是
>
> 随机访问都是O（1）的时间复杂度
>
> vector适合后端插入/删除，复杂度为O（1），但前端插入/删除需要搬移整个容器内的元素，故复杂度为O(n)，而deque适合两端插入/删除，且复杂度均为O(1)

### 订正

主体正确。

```text
vector
→ 整体连续存储

deque
→ 不保证整体连续存储
```

随机访问：

```text
vector
→ O(1)

deque
→ O(1)
```

前端：

```text
vector前端插入/删除
→ O(n)

deque push_front / pop_front
→ O(1)
```

尾端需要更精确：

```text
vector::push_back
→ Amortized O(1)
→ 均摊O(1)

vector::pop_back
→ O(1)
```

因为 `push_back()` 偶尔会遇到：

```text
capacity不足
↓
重新分配更大的连续内存
↓
搬移已有元素
↓
单次可能O(n)
```

状态：

```text
⚠️ 核心理解正确
```

```text

```

```text
调用Wait()的当前goroutine阻塞
↓
等待counter == 0
↓
继续执行
```

