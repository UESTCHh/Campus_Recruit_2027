# 三、Queue 核心语义

Queue：

```text
FIFO
=
First In First Out
=
先进先出
```

例如：

```cpp
numbers.push(10);
numbers.push(20);
numbers.push(30);
```

逻辑：

```text
front              back
 ↓                   ↓
10  →  20  →  30
```

最早进入：

```text
10
```

因此最先离开：

```text
10
```

# 五、空 Queue 边界

空 Queue 上不能直接：

```cpp
front()
back()
pop()
```

这些操作要求 Queue 当前非空。

因此：

```cpp
if (!numbers.empty())
{
    int value = numbers.front();
    numbers.pop();
}
```

更准确的理解：

> 空 Queue 不满足这些接口的前置条件，因此不能依赖程序产生某一个确定的错误结果或异常。

# 十、Queue 与底层接口对应关系

```text

↓

```

```text

```


# 十二、为什么 vector 不满足 Queue 底层要求

Stack 需要：

```text
back
push_back
pop_back
```

`vector` 全部支持，因此：

```cpp
stack<int, vector<int>>
```

可以使用。

而 Queue 需要：

```text
front
back
push_back
pop_front
```

`vector` 缺少：

```text
pop_front
```

所以不满足：

```text
std::queue
```

完整底层要求。

注意：

```text
vector不能作为std::queue底层
≠
vector绝对不能模拟FIFO
```

可以人为模拟 FIFO，只是不满足 Queue Adapter 的底层接口契约。

# 十四、C++ Day21 第二阶段完整代码

## `queue_adapter_demo.cpp`

```cpp
#include <deque>
#include <iostream>
#include <list>
#include <queue>

using namespace std;

template <typename QueueType>
void printAndClear(
    QueueType& numbers)
{
    while (!numbers.empty())
    {
        cout << numbers.front()
             << ' ';

        numbers.pop();
    }

    cout << endl;
}

int main()
{
    queue<int> defaultQueue;

    defaultQueue.push(10);
    defaultQueue.push(20);
    defaultQueue.push(30);

    cout << "=== default queue ==="
         << endl;

    cout << "front = "
         << defaultQueue.front()
         << endl;

    cout << "back = "
         << defaultQueue.back()
         << endl;

    cout << "pop order = ";

    printAndClear(defaultQueue);

    queue<int, deque<int>> dequeQueue;

    dequeQueue.push(10);
    dequeQueue.push(20);
    dequeQueue.push(30);

    cout << endl;

    cout << "=== deque based queue ==="
         << endl;

    cout << "front = "
         << dequeQueue.front()
         << endl;

    cout << "back = "
         << dequeQueue.back()
         << endl;

    cout << "pop order = ";

    printAndClear(dequeQueue);

    queue<int, list<int>> listQueue;

    listQueue.push(10);
    listQueue.push(20);
    listQueue.push(30);

    cout << endl;

    cout << "=== list based queue ==="
         << endl;

    cout << "front = "
         << listQueue.front()
         << endl;

    cout << "back = "
         << listQueue.back()
         << endl;

    cout << "pop order = ";

    printAndClear(listQueue);

    cout << endl;

    cout << "=== adapter conclusion ==="
         << endl;

    cout << "different underlying containers, "
         << "same FIFO interface"
         << endl;

    return 0;
}
```

```text

10 20 30

deque:
10 20 30

list:

```

# 十六、Queue 的算法思想

今天最重要的一句话：

> Queue 适合处理“最早进入但尚未处理的对象需要优先处理”的问题。

和 Stack 对比：

```text
Stack
→ 最近进入但尚未完成
→ 优先处理
```

```text
Queue
→ 最早进入但尚未完成
→ 优先处理
```

# 十七、Task Queue

Queue 中保存：

```text
已经到达
+
尚未处理
```

的任务。

例如：

```text
101
102
103
104
```

Queue：

```text
front                         back
 ↓                              ↓
101 → 102 → 103 → 104
```

每轮：

```text
front
↓
处理
↓
pop
```

严格保证：

```text
First Arrived
↓
First Processed
```

# 十八、C++ Day21 第三阶段完整代码

## `task_queue_demo.cpp`

```cpp
#include <iostream>
#include <queue>
#include <string>

using namespace std;

struct Task
{
    int id;
    string name;
};

int main()
{
    // Queue保存已经到达但尚未处理的Task。
    queue<Task> tasks;

    tasks.push(
        Task{101, "compile"}
    );

    tasks.push(
        Task{102, "test"}
    );

    tasks.push(
        Task{103, "deploy"}
    );

    cout << "=== tasks arrived ==="
         << endl;

    cout << "queue size = "
         << tasks.size()
         << endl;

    cout << "next task id = "
         << tasks.front().id
         << endl;

    cout << "latest task id = "
         << tasks.back().id
         << endl;

    tasks.push(
        Task{104, "monitor"}
    );

    cout << endl;

    cout << "=== task 104 arrived ==="
         << endl;

    cout << "next task id = "
         << tasks.front().id
         << endl;

    cout << "latest task id = "
         << tasks.back().id
         << endl;

    cout << endl;

    cout << "=== process tasks ==="
         << endl;

    while (!tasks.empty())
    {
        Task currentTask =
            tasks.front();

        cout << "processing task "
             << currentTask.id
             << ": "
             << currentTask.name
             << endl;

        // 当前任务处理完成，
        // 从尚未处理任务集合中删除。
        tasks.pop();
    }

    cout << endl;

    cout << "=== final state ==="
         << endl;

    cout << boolalpha;

    cout << "tasks.empty() = "
         << tasks.empty()
         << endl;

    cout << "tasks.size() = "
         << tasks.size()
         << endl;

    return 0;
}
```

# 二十、Task Queue 复杂度

假设：

```text
n个Task
```

每个 Task：

```text
push一次
front一次
pop一次
```

这些操作：

```text
O(1)
```

如果任务本身处理也按 O(1) 计算：

```text
Time Complexity
O(n)
```

最坏情况下全部 n 个任务尚未处理：

```text
Extra Space
O(n)
```

# 二十五、为什么只有 Error Message 不够

昨天：

```json
{
    "error": "user not found",
    "request_id": "req-4"
}
```

如果 Client：

```text
error == "user not found"
```

来判断错误类型，那么以后 Message 改为：

```text

```

客户端逻辑就会失效。

因此：

```text
Message
→ Human-readable
```

不应该承担稳定机器协议职责。

增加：

```text
Error Code
→ Machine-readable
```

例如：

```json
{
    "code": "USER_NOT_FOUND",
    "message": "user not found",
    "request_id": "req-4"
}
```

```go
	"requestID"

// ==================================================

var requestCounter uint64

func nextRequestID() string {
	number :=
		atomic.AddUint64(
			&requestCounter,
			1,
		)

	return "req-" +
		strconv.FormatUint(
			number,
			10,
		)
}

func requestIDFromContext(
	ctx context.Context,

	requestID, ok :=

	}

					r.Context(),
					requestIDKey,
					requestID,
				)

			r =
				r.WithContext(ctx)

			log.Printf(
				"[%s] request started: %s %s",
				requestID,
				r.Method,
				r.URL.Path,
			)

			next.ServeHTTP(
				w,
				r,
			)

			log.Printf(
				"[%s] request finished",
				requestID,
			)
		},
	)
}

// ==================================================
// Handler
// ==================================================

func userHandler(
	w http.ResponseWriter,
	r *http.Request,
) {
	requestID :=
		requestIDFromContext(
			r.Context(),
		)

	idText :=
		r.PathValue("id")

	// Parsing
	id, err :=
		strconv.Atoi(idText)

	if err != nil {
		log.Printf(
			"[%s] invalid user id format: %q",
			requestID,
			idText,
		)

		writeAPIError(
			w,
			r,
			apiErrorInvalidUserIDFormat,
		)

		return
	}

	// Validation
	if id <= 0 {
		log.Printf(
			"[%s] invalid user id value: %d",
			requestID,
			id,
		)

		writeAPIError(
			w,
			r,
			apiErrorInvalidUserIDValue,
		)

		return
	}

	// Business Logic
	user, err :=
		findUserByID(id)

	if err != nil {
		log.Printf(
			"[%s] find user failed: %v",
			requestID,
			err,
		)

		apiError :=
			mapBusinessError(err)

		writeAPIError(
			w,
			r,
			apiError,
		)

		return
	}

	// Success
	user.RequestID =
		requestID

	writeJSON(
		w,
		http.StatusOK,
		user,
	)
}

func main() {
	mux :=
		http.NewServeMux()

	mux.HandleFunc(
		"GET /users/{id}",
		userHandler,
	)

	handler :=
		requestIDMiddleware(mux)

	fmt.Println(
		"server listening on http://localhost:8080",
	)

	err :=
		http.ListenAndServe(
			":8080",
			handler,
		)

	if err != nil {
		log.Fatal(err)
	}
}
```

## 问题 8

### 面试专用回答

> 我会让 Business Layer 只返回内部 Business Error，不依赖 HTTP。API 层通过集中 Mapping Function 将 Business Error 映射为 APIError，APIError 统一保存 HTTP Status、稳定 Error Code 和 Human-readable Message。同一种 Error Contract 会预定义成 Single Source of Truth，避免不同 Handler 重复维护并产生不一致。
