# 二、C++ Stage 1：LC98 验证二叉搜索树

## 2.1 题目

LeetCode 98《验证二叉搜索树》

https://leetcode.cn/problems/validate-binary-search-tree/

题目要求判断给定二叉树是否为合法的二叉搜索树。

对本题而言，BST 必须满足：

1. 每个节点的左子树中，所有节点值都严格小于该节点值。
2. 每个节点的右子树中，所有节点值都严格大于该节点值。
3. 左右子树自身也必须满足 BST 的性质。
4. 不允许重复节点值。

## 2.2 与 Day48 LC700 的区别

Day48 的 LC700《二叉搜索树中的搜索》默认输入已经是合法 BST。

因此可以根据目标值决定搜索方向：

```text
val < root->val → 左子树
val > root->val → 右子树
```

而 LC98 要判断输入的二叉树是否满足 BST 的全部性质。

因此需要检查所有可能不合法的节点。

| 题目 | 核心任务 | 最坏时间复杂度 |
|---|---|---|
| LC700 | 在合法 BST 中搜索目标节点 | O(h) |
| LC98 | 判断整棵树是否为 BST | O(n) |

## 2.3 为什么只比较直接父子节点不够？

考虑：

```text
        8
       / \
      3   10
       \
        9
```

直接父子关系：

```text
3 < 8
10 > 8
9 > 3
```

虽然均正确，但整棵树不是 BST。

因为节点 9 同时属于：

- 节点 3 的右子树；
- 节点 8 的左子树。

所以必须同时满足：

```text
9 > 3
9 < 8
```

显然第二条不成立。

**结论：BST 的合法性必须考虑所有祖先节点形成的范围约束。**

---

## 2.4 核心原理：递归上下界

定义两个约束：

```text
lower：当前节点的合法下界
upper：当前节点的合法上界
```

任何非空节点都必须满足：

```text
lower < root->val < upper
```

即严格开区间。

递归时：

**进入左子树：**

```text
下界不变
上界更新为当前节点值
```

**进入右子树：**

```text
下界更新为当前节点值
上界不变
```

例如：

```text
         8
        /
       3
        \
         6
        /
       4
```

各节点合法范围：

| 节点 | 合法范围 |
|---|---|
| 8 | (-∞, +∞) |
| 3 | (-∞, 8) |
| 6 | (3, 8) |
| 4 | (3, 6) |

注意：范围会随着递归过程逐渐收紧，不能忘记更早的祖先约束。

## 3.1 问题 1：BST 全局有序性

### 问题

为什么下面这棵树的每组直接父子关系都正确，却不是合法 BST？

```text
        8
       / \
      3   10
       \
        9
```

### 我的回答（准确原话）

> 这棵树每个节点都满足直接左右孩子节点的值满足BST需求，但是节点9是节点3的右子树节点，但同样属于根节点8的左子树节点，所以该节点值应该大于3小于8，但9>8，所以整棵树仍然不是合法BST

### 订正

完全正确。

你已经理解：

- 节点 9 大于直接父节点 3。
- 但节点 9 还受到祖先节点 8 的约束。
- 节点 9 位于节点 8 左子树中，必须小于 8。

因此整棵树不是 BST。

### 相关示例

```text
       10
      /
     5
      \
       12
```

虽然：

```text
12 > 5
```

但节点 12 仍然位于根节点 10 的左子树中，因此违反：

```text
12 < 10
```

### 面试专用回答

验证 BST 不能只检查直接父子节点，因为每个节点还受到所有祖先节点的取值范围约束。可通过递归维护上下界，使每个节点都满足严格的取值区间要求。

## 3.2 问题 2：上下界变化

### 问题

给定：

```text
         8
        /
       3
        \
         6
        /
       4
```

分别写出节点 3、6、4 的合法范围。

### 我的回答（准确原话）

> 1. 节点 3 的合法范围是什么？（lower, 8）
> 2. 节点 6 的合法范围是什么？(3, 8)
> 3. 节点 4 的合法范围是什么？(3, 6)

### 订正

核心推导正确。

节点 3 的 `lower` 代表初始无下界约束，因此更明确的表达为：

```text
节点 3：(-∞, 8)
节点 6：(3, 8)
节点 4：(3, 6)
```

### 相关示例

递归到节点 6：

```text
lower = 3
upper = 8
```

进入节点 6 的左孩子 4：

```text
lower = 3
upper = 6
```

下界保持不变，上界被更新为 6。

### 面试专用回答

递归验证 BST 时，从根节点开始传递上下界。进入左子树时，用当前节点值更新上界；进入右子树时，用当前节点值更新下界。这样可以保证子孙节点同时遵守所有祖先节点的约束。

## 3.3 问题 3：递归返回值与逻辑合并

### 问题

如果当前节点违反上下界，应返回什么？

当前节点合法，是否代表整棵子树合法？

验证左右子树时，应该使用 `&&` 还是 `||`？

### 我的回答（准确原话）

> 返回false；否，因为当前节点满足要求不代表所有节点都满足要求，BST检查需要整棵树所有非空节点均满足BST特性；如果都需要验证，则使用逻辑&&合并结果，必须同时满足才算满足要求。

### 订正

全部正确。

另外补充：

**空子树应返回 `true`。**

因为空子树不会违反 BST 的任何约束。

而对于非空节点：

```text
当前节点合法
    &&
左子树合法
    &&
右子树合法
```

才能返回 `true`。

### 相关示例

```text
左子树合法：true
右子树非法：false
```

```cpp
true && false   // false
```

这与 LC112《路径总和》不同：

```text
LC112：只需要存在一条符合条件的路径 → ||
LC98：所有节点都要满足要求 → &&
```

### 面试专用回答

递归验证 BST 时，空节点返回 true，违反范围的节点返回 false。当前节点合法后，还必须递归验证左右子树，并使用逻辑与合并结果。只有全部节点合法，整棵树才是 BST。

# 四、C++ Stage 2：LC98 独立编码

## 4.1 我的原始代码

```cpp
class Solution {
public:
    bool isBST(TreeNode* root, long long lower = LLONG_MIN, long long upper = LLONG_MAX){
        if(root == nullptr){
            return true;
        }
        if(root -> val <= lower || root -> val >= upper){
            return false;
        }
        return isBST(root -> left, lower, root -> val) && isBST(root -> right, root -> val, upper);
    }
    bool isValidBST(TreeNode* root) {
        return isBST(root);
    }
};
```

## 4.2 代码逐项分析

### ① 空节点

```cpp
if(root == nullptr){
    return true;
}
```

正确。

空子树不会违反 BST 的有序性。

### ② 检查合法范围

```cpp
if(root -> val <= lower || root -> val >= upper){
    return false;
}
```

正确。

BST 使用严格不等式。

边界值不能相等，因为题目不允许重复节点值。

### ③ 验证左子树

```cpp
isBST(root -> left, lower, root -> val)
```

正确。

左子树的新上界为当前节点值。

### ④ 验证右子树

```cpp
isBST(root -> right, root -> val, upper)
```

正确。

右子树的新下界为当前节点值。

### ⑤ 合并左右结果

```cpp
&&
```

正确。

只要任意子树不合法，整棵树就不合法。

### ⑥ 整数边界

```cpp
long long lower = LLONG_MIN
long long upper = LLONG_MAX
```

正确处理 `TreeNode::val` 可能取到 `INT_MIN` 或 `INT_MAX` 的情况。


## 4.4 复杂度分析

### 我的回答（准确原话）

> 时间复杂度：O(n)，因为有遍历所有非空节点，判断所有非空节点是否满足BST要求。
> 空间复杂度：O(h)，递归深入子树，额外空间复杂度与递归调用栈深度有关，即与树的深度h有关。

**最坏时间复杂度：O(n)**

## 5.3 区分三个概念

### ① `*sql.DB`

例如：

```go
db, err := sql.Open("sqlite3", dbPath)
```

`sql.Open()` 返回数据库访问句柄，内部管理连接池。

它不保证此时已经建立真实数据库连接，也不保证数据库中的业务表存在。

### ② SQLite 数据库文件

例如：

```text
students.db
```

它用于持久化保存 SQLite 数据库内容。

一个文件中可以有多张数据表。

### ③ 数据表

例如：

```text
students
```

包含：

```text
id
name
age
```

只有表已经创建，才能正常执行针对该表的查询和写入操作。

---

## 5.4 核心 SQL：CREATE TABLE IF NOT EXISTS

```sql
CREATE TABLE IF NOT EXISTS students (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    age INTEGER NOT NULL
);
```

其中：

| SQL | 含义 |
|---|---|
| `CREATE TABLE` | 创建数据表 |
| `IF NOT EXISTS` | 如果表不存在才创建 |
| `INTEGER PRIMARY KEY` | 整数主键 |
| `TEXT NOT NULL` | 非 NULL 文本字段 |
| `INTEGER NOT NULL` | 非 NULL 整数字段 |

重要结论：

- 首次执行且表不存在：创建表。
- 再次执行且表已存在：不重复创建，也不会因表已存在而报错。
- 已有表中的数据不会因此被删除。
- 已有表的结构不会自动更新。
- `IF NOT EXISTS` 不能代替数据库迁移。

## 6.2 问题 2：IF NOT EXISTS 的作用

### 问题

第一次创建 `students` 表并插入 Alice。

第二次执行相同的：

```sql
CREATE TABLE IF NOT EXISTS students (...);
```

是否重新建表、删除 Alice、自动增加新字段？

### 我的回答（准确原话）

> 1. 这一次还会重新创建 `students` 表吗？不会
> 2. 原来已经插入的 Alice 是否应该被删除？不会，因为重新创建表的操作失败，不会影响旧表资源状态
> 3. 如果原来的 `students` 表缺少一个新增加的字段，`IF NOT EXISTS` 会自动把它补上吗？不会，它只会检查同名存在错误，不会检查旧表的结构是否与新表的定义，更不会修改旧表的结构。

### 订正

第一问：正确。

第二问：结论正确，但原因有误。

第三问：正确。

**重点订正：**

使用：

```sql
CREATE TABLE IF NOT EXISTS students (...);
```

时，如果表已存在，SQL 不会因为同名表存在而失败。

正确理解应是：

```text
表已经存在
    ↓
跳过重复创建
    ↓
语句正常完成
    ↓
原有数据保留
```

不能将“不创建新表”理解为“SQL 执行失败”。

### 相关示例

不带 `IF NOT EXISTS`：

```sql
CREATE TABLE students (
    id INTEGER PRIMARY KEY
);
```

当同名表已存在时，一般会报：

```text
table students already exists
```

带 `IF NOT EXISTS`：

```sql
CREATE TABLE IF NOT EXISTS students (
    id INTEGER PRIMARY KEY
);
```

同名表已存在时，不会因此报错。

但它也不会修改原表结构。

### 面试专用回答

`CREATE TABLE IF NOT EXISTS` 可以让基础建表操作重复执行。表不存在时创建，表存在时不重复创建且不因同名表报错。它不会删除已有数据，也不会自动更新表结构，后续字段变更需要数据库迁移。

# 九、Go 代码优化建议

这两处是代码规范优化，不影响今天的测试通过结果。

## 9.1 不建议长期使用 SELECT *

实际代码：

```go
db.QueryRow("SELECT * FROM students where id = ?", 1001)
```

建议：

```go
db.QueryRow(
    "SELECT id, name, age FROM students WHERE id = ?",
    1001,
)
```

原因：

`SELECT *` 返回所有列。

如果将来增加其他字段，返回列的数量或顺序发生变化，而 `Scan()` 仍然只接收三个目标变量，就可能出错。

明确列名更稳定。

## 9.2 结构体初始化建议写字段名

实际代码：

```go
want := Student{1001, "Alice", 20}
```

建议：

```go
want := Student{
    ID:   1001,
    Name: "Alice",
    Age:  20,
}
```

这种方式更容易阅读，且不依赖字段定义顺序。

以上均属于建议，不是本日必须返工的内容。

# 十、今日易错点和复盘

## 10.1 BST 不是局部有序即可

一个节点与直接父节点满足大小关系，不代表整棵树合法。

必须检查祖先节点形成的上下界。

## 10.2 BST 上下界是严格开区间

必须满足：

```text
lower < node->val < upper
```

不能包含上下界，否则可能允许重复值。

## 10.3 LC98 与 LC700 复杂度不同

LC700 已知是 BST，只需要沿一条搜索路径移动。

LC98 要判断整棵树是否为 BST，最坏需要访问所有节点。

因此：

```text
LC700：O(h)
LC98：O(n)
```

## 10.4 注意极端整数边界

使用 `long long` 与 `LLONG_MIN`、`LLONG_MAX` 处理初始范围，避免错误排除合法的 `INT_MIN`、`INT_MAX` 节点。

## 10.5 sql.Open 不等于数据库和表都已经可用

`sql.Open()` 返回访问句柄，不保证连接已经成功建立，更不能证明所需业务表存在。

## 10.6 IF NOT EXISTS 不等于忽略所有 SQL 错误

它主要用于避免因为同名表已存在而重复创建或报错。

它不意味着其他 SQL 错误都会被忽略。

## 10.7 IF NOT EXISTS 不会更新原表结构

如果旧表缺少新字段，这条语句不会自动补充字段。

以后需要学习数据库迁移。

## 10.8 测试数据库必须隔离

使用：

```go
t.TempDir()
```

将实验数据与原有数据库隔离，避免测试污染真实或历史练习数据。

## 10.9 测试 PASS 应记录实际依据

今天保存了：

- 实际代码。
- 实际执行命令。
- 单项测试 PASS。
- 完整测试 PASS。

不要编造 LeetCode 耗时、内存指标或未执行的测试步骤。
