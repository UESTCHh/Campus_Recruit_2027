prev->next = current->next;

2.2 Dummy Node 的作用
Dummy Node：
也叫：
虚拟头节点
哨兵节点
它不是实际业务数据。
例如：
原链表：
head

10 -> 20 -> 30
增加 Dummy Node：
dummy

 |

10 -> 20 -> 30
此时：
原来的第一个节点：
10
也拥有：
previous = dummy
所以：
删除10：
和删除20：
可以使用同一套逻辑。
3. Dummy Node 删除模型
统一：
previous -> current -> next
删除：
previous->next = current->next;

delete current;
过程：
删除：
dummy -> 10 -> 20 -> 30

         ^
      current
执行：
dummy->next = current->next;
得到：
dummy -> 20 -> 30
然后：
delete current;
释放10。
4. 为什么删除节点需要先修改指针？
错误：
delete current;

previous->next = current->next;
原因：
delete之后：
current
指向的对象已经不存在。
此时：
current->next
属于：
访问已经释放的内存
产生：
undefined behavior
正确：
previous->next = current->next;

delete current;
原则：
先修改链表结构

↓

再释放节点
5. 删除头节点为什么需要特殊处理？
没有 Dummy Node：
head
 |
10 -> 20
删除10：
没有：
prev
所以只能：
head = head->next;
加入 Dummy Node：
dummy -> 10 -> 20
          ^
       current
此时：
previous = dummy
所以：
previous->next = current->next;
可以直接删除。
6. delete 前保存 next
错误：
delete current;

current = current->next;
原因：
delete之后：
current已经无效。
正确：
ListNode* nextNode = current->next;

delete current;

current = nextNode;
核心：
释放之前保存需要继续使用的信息

8. C++ Day18 面试总结
问题：
Dummy Node 的作用是什么？
回答：
Dummy Node 是一个不存储实际数据的辅助节点，通过人为增加一个虚拟前驱节点，让原来的头节点也拥有 previous，从而统一删除头节点和普通节点的逻辑，减少边界判断。

问题：
链表为什么插入删除快？
回答：
链表节点不要求连续存储，插入删除时只需要修改节点之间的指针关系，不需要像 vector 一样移动大量元素。

11. Go Day19 面试总结
问题：
为什么 Middleware Chain 需要倒序包装？
回答：
Middleware列表表示最终执行顺序，而Handler包装过程需要从内层向外层构造，因此需要倒序遍历。

问题：
Middleware 和 Handler 区别？
回答：
Handler负责具体业务处理并返回响应，Middleware负责请求处理过程中的通用逻辑，例如日志、认证、监控等。

问题：
Context解决什么问题？
回答：
Context用于在一次请求生命周期内，在不同处理阶段之间传递请求相关数据，例如用户身份、请求ID等。
