# 一、C++ Day43 Stage 2 检查批改

## 检查 4：LeetCode 100 独立实现

### 1. 问题

独立实现 `isSameTree()`，给出提交结果，并解释递归终止条件。

### 2. 我的回答

你提交的核心代码：

```
class Solution {
public:
    bool isSameTree(TreeNode* p, TreeNode* q) {
        if(p == nullptr || q == nullptr){
            return p == q;
        }
        return (p -> val == q -> val) &&
               isSameTree(p -> left, q -> left) &&
               isSameTree(p -> right, q -> right);
    }
};
```

提交结果：

> 提交正确

关于递归条件，你的回答：

> 第一个解决节点存储的数据值是否相同，第二个解决两棵树的左子树是否相同，第三个解决两棵树的右子树是否相同

### 3. 订正

✅ 代码完全正确，LeetCode 提交通过。

你的代码写得很简洁，没有多余的判断。

先看：

```
if (p == nullptr || q == nullptr) {
    return p == q;
}
```

这段代码同时处理：

| p  | q  | 返回值     |
| -- | -- | ------- |
| 空  | 空  | `true`  |
| 空  | 非空 | `false` |
| 非空 | 空  | `false` |

只有当两者都非空时，才继续执行下面的代码。

随后：

```
return (p->val == q->val)
    && isSameTree(p->left, q->left)
    && isSameTree(p->right, q->right);
```

这是三个必须满足的条件：

1. 当前节点值相同。
2. 左子树相同。
3. 右子树相同。

但严格区分：

- `if (p == nullptr || q == nullptr)`：明确的递归终止条件。
- `p->val == q->val`：当前节点值的比较。
- 两次 `isSameTree()`：递归处理两个子问题。
- `&&`：通过短路求值，在发现不同时提前返回。

特别是，当节点值不同时，后面的两次递归根本不会执行。

### 4. 相关示例

例如：

```
树 A：          树 B：

   1              1
  / \            / \
 2   3          2   4
```

执行：

```
isSameTree(1, 1)
       ↓
当前值相同
       ↓
isSameTree(2, 2) → true
       ↓
isSameTree(3, 4) → false
       ↓
最终返回 false
```

如果两个根节点的值直接不同：

```
isSameTree(1, 9)
```

那么：

```
p->val == q->val
```

立即为 `false`，由于 `&&` 短路，左右子树不再递归比较。

### 5. 面试专用回答

> 判断两棵二叉树是否相同，可以采用双节点递归。首先处理空节点情况：两个节点都为空则相同，只有一方为空则不同。之后比较当前节点值，并递归比较对应的左右子树，三个条件全部满足才返回 true。通过逻辑与的短路特性，可以在发现不同后提前结束比较。

## 检查 5：时间与空间复杂度

### 1. 问题

分析最坏时间复杂度、递归空间复杂度以及提前结束的情况。

### 2. 我的回答

> 1. 为什么最坏时间复杂度可以表示为 `O(n)`？当两棵相同的树均有n个节点时，最坏需要比对n对节点，每次比较为O(1)
> 2. 为什么递归额外空间复杂度是 `O(h)`？因为递归额外空间复杂度取决于递归调用栈最大的深度，而递归调用栈的最大的深度即树的最大深度h
> 3. 平衡二叉树和退化为链表的情况分别是多少？O(log n) 和 O(n)
> 4. 如果一开始发现两个根节点值不同，后续还需要递归比较左右子树吗？为什么？不需要，因为一开始就发现两个根节点存储的数据值不同，那这两棵树必定不是同一棵树，所以可以直接返回，不用耗费复杂度再去递归比较左右子树

### 3. 订正

✅ 四问全部正确。

你已经准确掌握了递归复杂度的分析方法。

在两棵树都有 `n` 个节点、结构和值完全相同的情况下，需要比较全部对应节点，因此时间复杂度为 `O(n)`。

递归栈最大深度与树高 `h` 有关，因此空间复杂度为 `O(h)`。

| 树形    | 时间复杂度  | 递归额外空间     |
| ----- | ------ | ---------- |
| 平衡二叉树 | `O(n)` | `O(log n)` |
| 退化为链表 | `O(n)` | `O(n)`     |
| 一般二叉树 | `O(n)` | `O(h)`     |

还有一个小的严谨性细节：这里使用的是两棵规模和形态相同、需要完整比较的情况。对于一开始就发现不同的输入，实际执行成本可能更低。

### 4. 相关示例

两棵树根节点不同：

```
树 A：1       树 B：9
```

执行：

```

```

只需要比较一次根节点值，即可返回：

```

但算法的最坏情况仍然需要完整比较所有节点，因此最坏时间复杂度为 `O(n)`。

### 5. 面试专用回答

> 判断相同二叉树时，最坏情况下需要逐一比较 n 对对应节点，每次比较为常数时间，因此时间复杂度为 O(n)。递归调用栈深度取决于树高 h，额外空间复杂度为 O(h)。对于平衡二叉树是 O(log n)，对于退化为链表的二叉树是 O(n)。如果提前发现节点值或结构不同，可以利用短路判断避免继续递归。

## 2. `json.Encoder` 和 `json.Decoder` 的区别

昨天：

```
json.NewEncoder(w).Encode(student)
```

是将 Go 数据转换为 JSON，发送给客户端。

今天：

```
json.NewDecoder(r.Body).Decode(&student)
```

方向正好相反。

| 方法         | 数据流向      | 作用          |
| ---------- | --------- | ----------- |
| `Encode()` | Go → JSON | 生成 HTTP 响应  |
| `Decode()` | JSON → Go | 解析 HTTP 请求体 |

HTTP 请求与响应中的 JSON 转换

客户端请求体（JSON）

```
{"id":1005,"name":"Eva","age":22}
```

Decode(&student)

Go 结构体

```
Student{
    ID:   1005,
    Name: "Eva",
    Age:  22,
}
```

Encode(student)

服务器响应体（JSON）

```
{"id":1005,"name":"Eva","age":22}
```

你需要重点理解：

```
&student
```

为什么有 `&`？

因为 `Decode()` 需要修改 `student` 这个变量，将解析出的 JSON 字段值写入结构体。

这与之前数据库查询使用：

```
rows.Scan(&student.ID, &student.Name, &student.Age)
```

存在相似之处：都需要把外部读取的数据写入 Go 变量。

不过 `Scan()` 接收多个目标字段地址，而 `Decode()` 这里接收整个结构体的地址。

## 2. 完整代码

```

package main

import (
	"encoding/json"
	"log"
	"net/http"
)

// Student表示一名学生
type Student struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
	Age  int    `json:"age"`
}

// ErrorResponse用于统一错误响应
type ErrorResponse struct {
	Error string `json:"error"`
}

// writeJSON负责写入JSON响应
func writeJSON(w http.ResponseWriter, status int, data any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)

	if err := json.NewEncoder(w).Encode(data); err != nil {
		log.Printf("write JSON failed: %v", err)
	}
}

// studentPreviewHandler只解析JSON，不写入数据库
func studentPreviewHandler(w http.ResponseWriter, r *http.Request) {
	var student Student

	// 将HTTP请求体中的JSON解析到student
	err := json.NewDecoder(r.Body).Decode(&student)
	if err != nil {
		writeJSON(
			w,
			http.StatusBadRequest,
			ErrorResponse{Error: "invalid JSON body"},
		)
		return
	}

	// 简单的数据有效性检查
	if student.ID <= 0 || student.Name == "" ||
		student.Age <= 0 {
		writeJSON(
			w,
			http.StatusBadRequest,
			ErrorResponse{Error: "invalid student data"},
		)
		return
	}

	// 这里只返回解析结果，不执行数据库插入
	writeJSON(w, http.StatusOK, student)
}

func main() {
	mux := http.NewServeMux()

	mux.HandleFunc(
		"POST /students/preview",
		studentPreviewHandler,
	)

	log.Println("Preview server listening on http://127.0.0.1:8081")

	if err := http.ListenAndServe("127.0.0.1:8081", mux); err != nil {
		log.Fatal(err)
	}
}

```

这里使用 `8081`，是为了避免你昨天的 Day42 HTTP 服务仍在使用 `8080` 时发生端口冲突。

目前的字段校验只是练习用的简单规则。例如 `Age <= 0` 被视为非法，但实际业务中是否允许 0 岁学生，需要根据需求决定。更严谨的请求体校验、大小限制和额外 JSON 内容检查，后续再逐步完善。

第一阶段：JSON 解码与类型检查

假设结构体：

```

虽然 `"1005"` 看起来可以转换为整数，但 `encoding/json` 默认不会自动把 JSON 字符串转换为 Go `int` 字段。

> HTTP JSON 请求通常需要先进行解码和类型检查，再进行业务参数校验。解码阶段负责将 JSON 映射为 Go 数据类型，类型不匹配会导致 Decode 返回错误；业务校验则负责判断已经成功解码的数据是否满足实际规则，例如 ID 必须为正数、姓名不能为空。通过校验后，才应该将数据交给 Repository 执行持久化操作。

## 检查 3：从 JSON 请求到数据库插入

### 问题

`Decode()` 和 `repo.Create()` 分别属于哪一层？为什么当前预览接口没有插入数据？如何升级为真正的 POST API？

### 我的回答

> 1. 这两个操作应该分别发生在 Handler 和 Repository 中的哪一层？前者发生在Handler层，后者发生在Repository层
> 2. 为什么 `POST /students/preview` 当前不能真正新增学生？因为当前只是将客户请求中的数据解码后再编码发回给用户，没有真正调用repo.Create(student)，所以不能真正新增学生
> 3. 下一阶段要实现真正的 `POST /students`，你认为最关键的新增步骤是什么？加入Repository层逻辑，调用repo.Create(student)

### 订正

✅ 全部正确。

再规范一下：`repo.Create(student)` 的调用动作可以发生在 Handler 中，但 `Create()` 方法内部的具体数据库操作属于 Repository 层。

这和你今天的理解并不冲突。

### 相关示例

```
// Handler 中
var student Student

if err := json.NewDecoder(r.Body).Decode(&student); err != nil {
    // 处理解码错误
    return
}

// 校验完成后，调用 Repository
err := repo.Create(student)
```

对应：

```
Handler
  解析 JSON
  参数校验
  调用 repo.Create()
       ↓
Repository
  执行 INSERT INTO
       ↓
SQLite
```

### 面试专用回答

> 在 Go HTTP 后端中，Handler 负责读取和解码请求体、执行基础参数校验以及组织 HTTP 响应。Repository 负责具体数据库持久化操作。实现 POST 新增接口时，可以在 Handler 解码和校验请求后调用 Repository 的 Create 方法，并根据返回错误决定响应状态码。

       ↓

       ↓

       ↓

       ↓

这里有一个新的 HTTP 状态码。

### `201 Created` 是什么？

之前我们已经学过：

| 状态码                       | 含义       |
| ------------------------- | -------- |
| 200 OK                    | 请求成功     |
| 400 Bad Request           | 客户端请求错误  |
| 404 Not Found             | 请求的资源不存在 |
| 500 Internal Server Error | 服务端内部错误  |

今天新增：

| 状态码          | 含义            |
| ------------ | ------------- |
| 201 Created  | 成功创建新的资源      |
| 409 Conflict | 请求与当前资源状态存在冲突 |

例如：

第一次插入：

```
id = 1005
```

数据库没有该学生，插入成功，返回：

```
201 Created
```

第二次插入同样的：

```
id = 1005
```

由于 ID 是主键，会产生唯一约束冲突。

对于这个 API，我们希望将其转换为：

```
409 Conflict
```

注意：`409` 是 Handler 根据数据库错误进行的 HTTP 语义映射，不是数据库直接返回 HTTP 状态码。

```

package main

import (
	"database/sql"
	"encoding/json"
	"errors"
	"log"
	"net/http"
	"os"
	"path/filepath"
	"strconv"
	"strings"

	sqlite3 "github.com/mattn/go-sqlite3"
)

// JSON错误响应
type ErrorResponse struct {
	Error string `json:"error"`
}

// 统一写入JSON响应
func writeJSON(w http.ResponseWriter, status int, data any) {
	body, err := json.Marshal(data)
	if err != nil {
		log.Printf("JSON encoding failed: %v", err)
		http.Error(
			w,
			"internal server error",
			http.StatusInternalServerError,
		)
		return
	}

	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)

	if _, err := w.Write(append(body, '\n')); err != nil {
		log.Printf("write response failed: %v", err)
	}
}

// GET /students/{id}
func studentByIDHandler(repo *StudentRepository) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		idText := r.PathValue("id")

		studentID, err := strconv.Atoi(idText)
		if err != nil || studentID <= 0 {
			writeJSON(
				w,
				http.StatusBadRequest,
				ErrorResponse{Error: "invalid student id"},
			)
			return
		}

		student, err := repo.GetByID(studentID)

		if errors.Is(err, sql.ErrNoRows) {
			writeJSON(
				w,
				http.StatusNotFound,
				ErrorResponse{Error: "student not found"},
			)
			return
		}

		if err != nil {
			log.Printf("GetByID failed: %v", err)

			writeJSON(
				w,
				http.StatusInternalServerError,
				ErrorResponse{Error: "internal server error"},
			)
			return
		}

		writeJSON(w, http.StatusOK, student)
	}
}

// GET /students
func studentsHandler(repo *StudentRepository) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		students, err := repo.List()
		if err != nil {
			log.Printf("List failed: %v", err)

			writeJSON(
				w,
				http.StatusInternalServerError,
				ErrorResponse{Error: "internal server error"},
			)
			return
		}

		writeJSON(w, http.StatusOK, students)
	}
}

// POST /students
func createStudentHandler(repo *StudentRepository) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		// 1. 读取并解码请求JSON
		var student Student

		err := json.NewDecoder(r.Body).Decode(&student)
		if err != nil {
			writeJSON(
				w,
				http.StatusBadRequest,
				ErrorResponse{Error: "invalid JSON body"},
			)
			return
		}

		// 2. 校验学生数据
		if student.ID <= 0 ||
			strings.TrimSpace(student.Name) == "" ||
			student.Age <= 0 {
			writeJSON(
				w,
				http.StatusBadRequest,
				ErrorResponse{Error: "invalid student data"},
			)
			return
		}

		// 3. 调用Repository写入SQLite
		err = repo.Create(student)
		if err != nil {
			// 判断是否属于SQLite的主键或唯一约束冲突
			var sqliteErr sqlite3.Error

			if errors.As(err, &sqliteErr) &&
				(sqliteErr.ExtendedCode == sqlite3.ErrConstraintPrimaryKey ||
					sqliteErr.ExtendedCode == sqlite3.ErrConstraintUnique) {
				writeJSON(
					w,
					http.StatusConflict,
					ErrorResponse{Error: "student id already exists"},
				)
				return
			}

			// 其他数据库错误
			log.Printf("Create failed: %v", err)

			writeJSON(
				w,
				http.StatusInternalServerError,
				ErrorResponse{Error: "internal server error"},
			)
			return
		}

		// 4. 新增成功：设置资源地址
		w.Header().Set(
			"Location",
			"/students/"+strconv.Itoa(student.ID),
		)

		// 5. 返回201及新建学生
		writeJSON(w, http.StatusCreated, student)
	}
}

func main() {
	// 复用之前的文件型SQLite数据库
	dbPath := filepath.Join(
		"..",
		"day38-sql-persistence",
		"students.db",
	)

	// 防止意外创建新的空数据库
	if _, err := os.Stat(dbPath); err != nil {
		log.Fatal(err)
	}

	db, err := sql.Open("sqlite3", dbPath)
	if err != nil {
		log.Fatal(err)
	}
	defer db.Close()

	if err := db.Ping(); err != nil {
		log.Fatal(err)
	}

	// 复用现有Repository
	repo := NewStudentRepository(db)

	mux := http.NewServeMux()

	mux.HandleFunc(
		"GET /students",
		studentsHandler(repo),
	)

	mux.HandleFunc(
		"GET /students/{id}",
		studentByIDHandler(repo),
	)

	mux.HandleFunc(
		"POST /students",
		createStudentHandler(repo),
	)

	log.Println("Server listening on http://127.0.0.1:8081")

	if err := http.ListenAndServe("127.0.0.1:8081", mux); err != nil {
		log.Fatal(err)
	}
}

```

这份程序沿用了之前的练习写法。当前只进行一次 `Decode()`，对于额外 JSON 字段、多段 JSON 内容和请求体大小还没有实施严格控制；这些属于后续 HTTP API 健壮性改进内容，暂时不影响今天理解 POST 与数据库插入的主线。
