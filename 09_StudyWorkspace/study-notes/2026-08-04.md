### 2. Application Factory 的作用是什么？

我的回答：暂时不会

订正：Application Factory 就是一个专门负责创建和配置 FastAPI 应用的函数。
例如：
def create_app() -> FastAPI:
    app = FastAPI()

    app.add_middleware(...)
    register_exception_handlers(app)
    app.include_router(...)

    return app
它集中完成：
    创建 FastAPI 对象
    加载配置
    初始化日志
    注册 Middleware
    注册异常处理器
    注册 Router
以前如果所有内容都堆在 main.py：
app = FastAPI()
app.add_middleware(...)
app.include_router(...)
项目变大后会越来越乱，也不方便测试。
使用应用工厂以后：
from app.factory import create_app

app = create_app()
核心作用是：
把“如何创建应用”集中管理，让项目更清晰、更容易测试，也更容易支持开发、测试和生产等不同环境。

    DeepSeek

    例如：
    class MockLLM(BaseLLM):

            ...
可以这样记：
    Router：处理 HTTP
    Service：处理业务
    Provider：处理外部能力
完整调用链：
    用户请求
    ↓
    Router
    ↓
    ChatService

### 5. 镜像和容器有什么区别？

我的回答：镜像是本体的复制品，容器是本体的集合

订正：这个理解不准确。
镜像 Image
镜像是一个只读模板，里面包含：
    操作系统基础层
    Python
    项目代码
    项目依赖
    启动命令
例如：
ai-service-demo:latest
镜像本身通常不会运行。
容器 Container
容器是镜像启动后产生的运行实例。
例如：
docker run ai-service-demo:latest
会根据镜像创建一个容器。
同一个镜像可以启动多个容器：
一个镜像
 ├── 容器 A
 ├── 容器 B
 └── 容器 C
    可以使用“类和对象”理解：
    镜像 ≈ 类
    容器 ≈ 根据类创建出来的对象
    或者：
    镜像 ≈ 游戏安装包
    容器 ≈ 正在运行的游戏进程
最准确的一句话：
镜像是只读运行模板，容器是镜像的一个运行实例。

### 6. Docker 如何判断容器 healthy？

我的回答：通过docker build命令观察 UP xx seconds (healthy)

订正：不是为了模拟客户，而是为了安全。
Linux 中的 root 拥有最高权限。
如果应用存在漏洞，并且攻击者控制了以 root 身份运行的进程，可能获得更高权限，造成更严重的破坏。
使用：
USER appuser
以后，应用只能使用 appuser 拥有的权限。
这叫：
最小权限原则
含义是：
程序只获得完成工作所必需的最低权限。

因此，即使程序遭到攻击，攻击者能够利用的权限也会受到限制。
正确答案：
生产容器使用 appuser 是为了避免应用以 root 最高权限运行，降低安全漏洞造成的影响。

订正：这里把“生成状态”和“查看状态”混在了一起。
docker build 只负责构建镜像，它不会判断运行中的容器是否健康。
Docker Compose 中配置了：
healthcheck:
  test:
    [
      "CMD",
      "python",
      "-c",
      "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/v1/healthz')"
    ]
  interval: 30s
  timeout: 5s
  retries: 3
  start_period: 10s
Docker 启动容器后，会定期在容器内执行这个检测命令。
检测过程：
访问 /api/v1/healthz
          ↓
请求成功
          ↓
健康检查命令返回成功
          ↓
Docker 将状态标记为 healthy
如果连续多次失败，就会显示：
unhealthy
docker ps 的作用只是显示 Docker 已经计算出的健康状态：
Up 15 seconds (healthy)
所以正确答案是：
Docker 根据 healthcheck 配置周期性执行检测命令；检测成功后标记为 healthy，docker ps 只是把这个状态显示出来。

### 8. 为什么不能提交 `.env`？

我的回答：.env是私密文件，应该提交.envsample

订正：这个方向正确。
项目中通常使用的文件名是：
.env.example
而不是：
.envsample
.env 中可能包含：
    OPENAI_API_KEY=真实密钥
    DATABASE_PASSWORD=真实密码
    JWT_SECRET=真实密钥
提交到 Git 后可能造成：
    API Key 泄漏
    数据库密码泄漏
    密钥被 Git 历史永久保留
    账号产生费用或遭到攻击
因此：
.env
加入 .gitignore，不提交。
提交的是：
.env.example
示例：
    OPENAI_API_KEY=
    DATABASE_PASSWORD=
    LLM_MODEL=mock-model-v1
它只告诉其他开发者“需要配置哪些变量”，但不包含真实秘密。
正确答案：
.env 可能包含真实密码和 API Key，不能提交；应提交不含敏感值的 .env.example 作为配置模板。

## 顺序执行耗时

实验代码：

```python
await fake_request("A")
await fake_request("B")
await fake_request("C")
运行结果：
A started
A finished
B started
B finished
C started
C finished

sequential: 3.03s
原因分析
三个任务按照顺序执行：
A 请求
 |
 等待1秒
 |
完成

B 请求
 |
 等待1秒
 |
完成

C 请求
 |
 等待1秒
 |
完成
总耗时：
1s + 1s + 1s ≈ 3s
并发执行耗时
实验代码：
await asyncio.gather(
    fake_request("A"),
    fake_request("B"),
    fake_request("C"),
)
运行结果：
A started
B started
C started

A finished
B finished
C finished

concurrent: 1.03s
原因分析
三个任务同时启动。
当任务遇到：
await asyncio.sleep(1)
表示：
当前任务正在等待，不需要继续占用 CPU。
Python 事件循环可以切换执行其他任务。
执行过程：
A 开始
B 开始
C 开始

三个任务同时等待1秒

A 完成
B 完成
C 完成
总耗时：
max(1s,1s,1s) ≈ 1s
我的解释
async def：
async def 用于定义异步函数。
异步函数调用后不会立即执行全部代码，而是返回一个 coroutine（协程）对象。
例如：
async def request():
    pass
表示：
这个函数内部可能包含等待操作，可以被事件循环调度。
在 FastAPI 中：
@router.post("/chat/mock")
async def chat_endpoint():
表示该接口可以处理异步任务。
await：
await 用于等待一个异步操作完成。
例如：
await asyncio.sleep(1)
表示：
等待1秒，但是不会阻塞整个程序。
等待期间：
当前任务暂停
事件循环可以执行其他任务
所以多个请求可以同时处理。
asyncio.gather():
asyncio.gather() 用于并发运行多个异步任务。
例如：
await asyncio.gather(
    task1(),
    task2(),
    task3(),
)
表示：
同时启动多个协程，并等待它们全部完成。
适合：
多个 API 请求
多个数据库查询
多个 IO 操作
为什么 LLM API 适合异步：
LLM API 调用通常属于 IO 密集型任务。
例如：
用户请求
    |
FastAPI
    |
调用 OpenAI / DeepSeek API
    |
等待网络返回
    |
得到结果
等待时间可能达到：
几百毫秒 ~ 几秒
这段时间 CPU 不需要计算。
如果使用同步方式：
用户A请求
等待LLM返回

用户B请求
等待LLM返回
服务器大量时间浪费在等待。
如果使用异步：
用户A请求
发送LLM请求
等待

用户B请求
发送LLM请求
等待

事件循环切换任务
可以同时处理更多用户请求。
因此：
AI Backend 中：
FastAPI
LLM API调用
数据库访问
向量数据库查询
通常适合使用异步编程。
今日核心理解
async 不代表代码执行速度一定更快。
async 的作用是：
在等待 IO 时释放执行权，让其他任务继续运行，提高系统并发能力。

对于 AI 后端：
异步提升的是：
同时处理请求数量
服务吞吐量
用户等待体验
而不是单个请求的计算速度。

## 错误代码

```python
result = chat_service.chat(message)
错误结果
得到：
Coroutine object
而不是：
LLMResult
原因
async def 定义的函数：
调用时：
func()
返回 coroutine。
只有：
await func()
才会真正执行并获得结果。
正确流程
Router
↓

↓
await LLM.generate()
↓
LLMResult
核心理解
async 不会自动执行。
await 是启动协程并获取结果的关键。
