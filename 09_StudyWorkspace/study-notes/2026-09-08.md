# 六、Brute Force

最直接方法：

```cpp
for (int i = 0; i < n; ++i)
{
    for (int j = i + 1; j < n; ++j)
    {
        if (numbers[i] + numbers[j] == target)
        {
            ...
        }
    }
}
```

即：

```text
枚举所有元素对
```

时间复杂度：

```text
O(n²)
```

因为两层循环嵌套：

```text
O(n) × O(n)
→ O(n²)
```

---

# 七、利用有序性优化

对于升序数组：

```text
1 2 4 6 8 10
↑          ↑
L          R
```

定义：

```cpp
int left = 0;
int right = numbers.size() - 1;
```

计算：

```cpp
sum = numbers[left] + numbers[right];
```

存在三种情况：

```text
sum == target
→ 找到答案

sum < target
→ 当前和太小
→ ++left

sum > target
→ 当前和太大
→ --right
```

---

# 八、为什么 `sum < target` 时移动 left

假设：

```text
numbers[left] + numbers[right] < target
```

当前：

```text
numbers[right]
```

已经是 Search Space 中最大的候选元素。

对于当前 `numbers[left]`：

```text
numbers[left] + numbers[j]
<=
numbers[left] + numbers[right]
<
target
```

对所有：

```text
left < j <= right
```

都成立。

因此：

```text
numbers[left]
```

即使和当前范围最大的元素组合都太小，那么与其他更小元素组合只会更小。

所以：

```text
当前left不可能参与任何答案
```

可以安全：

```cpp
++left;
```

---

# 九、为什么 `sum > target` 时移动 right

假设：

```text
numbers[left] + numbers[right] > target
```

当前：

```text
numbers[left]
```

已经是 Search Space 中最小的候选元素。

对于当前 `numbers[right]`：

```text
numbers[i] + numbers[right]
>=
numbers[left] + numbers[right]
>
target
```

对所有：

```text
left <= i < right
```

都成立。

因此：

```text
numbers[right]
```

即使和当前最小元素组合都太大，那么和其他更大的元素组合只会更大。

所以：

```text
当前right不可能参与答案
```

可以安全：

```cpp
--right;
```

只承诺：


有效。

不保证：

