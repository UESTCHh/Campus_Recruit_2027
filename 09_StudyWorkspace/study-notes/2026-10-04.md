# 三、昨天的 Boundary Binary Search 模型

前一天已经学习：

```text
first >= target
→ lower_bound

first > target
→ upper_bound
```

例如：

```text
nums = [1,3,5,5,5,7,9]
```

寻找：

```text
first >= 5
```

判断结果：

```text
nums[i] >= 5 ?

F F T T T T T
    ↑
```

Boundary Binary Search 找：

```text
第一个满足条件的位置
```

---

# 四、今天为什么继续学习这个模型

昨天的：

```text
first >= target
first > target
```

容易让人形成：

```text
Binary Search
=
必须围绕某个target
```

这样的印象。

但 Boundary Binary Search 真正依赖的是：

```text
候选位置 / 候选答案按照某个方向变化时
↓
“是否满足要求”这个判断
↓
形成连续的两段
```

例如：

```text
不满足 不满足 不满足 | 满足 满足 满足
                      ↑
                    边界
```

也可以写成：

```text
F F F F | T T T
        ↑
```

---

# 五、“单调性”到底是什么意思

今天专门澄清：

```text
“具有单调性的判断结果”
```

这句话虽然概括准确，但直接用于面试比较抽象。

这里所谓的“单调性”：

```text
不一定是数组数值本身的单调性
```

真正指的是：

> 当候选位置或候选答案按照某个方向变化时，“是否满足要求”这个判断只会发生一次从不满足到满足的变化。

例如：

```text
候选：
1 2 3 4 5 6

是否满足：
F F F T T T
```

一旦：

```text
4满足
```

后面的：

```text
5
6
```

也都满足。

不会出现：

```text
F F T F T
```

这种反复变化。

---

# 六、为什么这种规律能够二分

假设：

```text
F F F F | T T T
```

如果 mid 落在：

```text
F
```

区域：

```text
mid不满足
```

那么在能够证明：

```text
mid左边也都不满足
```

的情况下，可以直接排除左半部分。

如果 mid 落在：

```text
T
```

区域：

```text
mid满足
```

说明：

```text
答案可能就是mid
也可能在mid左侧更早的位置
```

于是保留 mid，并继续向左寻找。

所以才能做到：

```text
每次排除一半搜索范围
```

# 七、今天的具体例子

数组：

```text
nums = [2,4,6,8,10,12]
```


逐个判断：

```text
2  >= 9 → false

```

得到：

```text
2   4   6   8 | 10  12
F   F   F   F | T   T
                ↑
```

所以：

```text
第一个满足条件的位置
=
index 4

value
=
10
```

# 十、如果面试官追问“什么叫单调性”

推荐回答：

> 这里的单调性主要指判定结果的单调性，而不一定要求搜索对象本身就是一个升序数组。比如候选答案逐渐增大时，判断结果可能是 `false false false true true true`，也就是一旦满足条件，后面的候选也都满足，不会再次变回 false。因为存在这样的唯一分界点，所以可以通过二分不断排除一半搜索范围。

可以理解为：

```text
候选值变化
↓
判断结果：

F F F F | T T T
```

而不是：

```text
F F T F T T
```

后一种：

```text
满足
↓
又不满足
↓
再次满足
```

不存在稳定的唯一边界，因此不能直接套今天的边界二分模型。

# 十二、今日 C++ 实验代码

文件：

```text
first_true_demo.cpp
```

代码：

```cpp
#include <iostream>
#include <vector>

using namespace std;

// 找到第一个满足：
// nums[i] >= requirement
// 的位置。
//
// 今天重点不是背lower_bound模板，
// 而是理解：
//
// false false false | true true true
//                   ↑
//             找第一个true
int firstSatisfied(
    const vector<int>& nums,
    int requirement
) {
    int left = 0;
    int right =
        static_cast<int>(
            nums.size()
        );

    while (left < right) {
        int mid =
            left + (right - left) / 2;

        // 当前mid不满足要求。
        //
        // 因为数组升序，
        // mid以及mid左侧都不可能满足要求，
        // 因此可以全部排除。
        if (nums[mid] < requirement) {
            left = mid + 1;
        }
        else {
            // 当前mid已经满足要求，
            // 但左边可能还有更早满足的位置。
            //
            // 因此mid仍然可能是答案，
            // 不能将其排除。
            right = mid;
        }
    }

    return left;
}

int main()
{
    vector<int> nums{
        2, 4, 6, 8, 10, 12
    };

    int requirement = 9;

    int index =
        firstSatisfied(
            nums,
            requirement
        );

    if (
        index ==
        static_cast<int>(
            nums.size()
        )
    ) {
        cout
            << "no value satisfies requirement"
            << '\n';
    }
    else {
        cout
            << "first satisfied index = "
            << index
            << '\n';

        cout
            << "value = "
            << nums[index]
            << '\n';
    }

    return 0;
}
```

# 十九、http.Error 与 return 的职责

```text
http.Error()
→ HTTP响应层面的操作
→ 把错误信息写给客户端
```

而：

```text
return
→ Go控制流层面的操作
→ 停止当前Handler继续执行
```

因此：

```text
http.Error()
≠
return
```

正确写法：

```go
if name == "" {
    http.Error(
        w,
        "name is required",
        http.StatusBadRequest,
    )
    return
}
```

完整流程：

```text
检测到错误
↓
http.Error
↓
写错误响应
↓
return
↓
Handler结束
```

```go
	"fmt"
	"log"
	"net/http"
)

func helloHandler(
	w http.ResponseWriter,
	r *http.Request,
) {
	name := r.URL.Query().Get("name")

	if name == "" {
		http.Error(
			w,

		w,

	)

	http.HandleFunc(
		"/hello",
		helloHandler,
	)

		"server started at http://localhost:8080",
	)

	log.Fatal(
		http.ListenAndServe(
			":8080",
			nil,
		),
	)
}
```

## 问题

`http.Error()` 的主要作用是什么？

# 二十四、Go 检查 2

## 问题

为什么：

```go
if name == "" {
    http.Error(
        w,
        "name is required",
        http.StatusBadRequest,
    )
}

createOrder()
```

有问题？

## 我的回答

> 调用http.Error()后没有及时返回当前Handler而是继续调用正确条件下的业务处理逻辑createOrder()，可能会造成最后返回给客户端的响应逻辑混乱，Body中出现正常业务处理返回逻辑和判断错误逻辑，跟Status Code不相对应，造成逻辑混乱

## 订正

回答正确。

除了：

```text
Response Body
Status Code
```

可能出现逻辑混乱，更严重的问题是：

```text
正常业务副作用仍然可能发生
```

例如：

```text
INSERT数据库
扣库存
创建订单
发送消息
```

可能出现：

```text
客户端：
400 Bad Request

服务器：
订单却已经被创建
```

所以错误分支及时：

```go
return
```

不仅是为了让 Response 更整洁，也是为了保护业务逻辑。

### 相关示例

错误：

```go
if userID == 0 {
    http.Error(
        w,
        "invalid user",
        http.StatusBadRequest,
    )
}

createOrder()
```

可能：

```text
用户参数非法
↓
已经返回400
↓
却继续createOrder
↓
数据库发生真实写操作
```

### 面试专用回答

> 调用 `http.Error` 后如果不 return，Handler 会继续执行后续正常业务流程。不仅可能导致状态码和 Body 混乱，还可能继续进行数据库写入、创建订单等有副作用的操作，因此错误分支通常必须立即终止。
