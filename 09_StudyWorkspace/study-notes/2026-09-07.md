# 三、为什么 Binary Search 需要有序

之前学习：

```cpp
std::find(
    numbers.begin(),
    numbers.end(),
    target
);
```

其本质：

```text
从first开始
↓
逐个比较
↓
最坏检查n个元素
↓
O(n)
```

如果数据已经有序，则可以根据：

```text
target
与
middle value
```

之间的大小关系，一次排除一部分不可能包含答案的区间。

例如升序：

```text
1 3 5 7 9 11 13
      ↑
     mid
```

寻找：

```text
11
```

因为：

```text
11 > 7
```

所以：

```text
7以及7左边的元素
都不可能是11
```

可以直接排除左半部分。

因此 Binary Search 的真正核心不是简单：

```text
每次看中间元素
```

而是：

```text
有序性
↓
比较
↓
确定一部分Search Space不可能包含答案
↓
排除该范围
↓
不断缩小搜索空间
```

---

# 四、`std::binary_search`

```cpp
binary_search(
    first,
    last,
    value
);
```

返回：

```text
bool
```

只回答：

```text
目标值是否存在？
```

例如：

```cpp
bool found = binary_search(
    numbers.begin(),
    numbers.end(),

);
```

找到：

```text

```

没找到：

```text

```

与：

```cpp

```

区别：

```text

→ 返回Iterator
→ 找到第一个目标元素的位置

std::binary_search
→ 返回bool
→ 只回答目标是否存在
```


# 八、重复元素区间

默认升序：

```text
lower_bound(k)
→ 第一个 >= k

upper_bound(k)
→ 第一个 > k
```

因此：

```text
[lower_bound(k), upper_bound(k))
```

正好包含所有：

```text
== k
```

的元素。

例如：

```text
1 2 2 2 4 6
  ↑     ↑
  L     U
```

则：

```text
[L, U)
```

为：

```text
2 2 2
```

# 九、通过 Iterator 计算重复次数

对于 `vector`：

```cpp
auto first = lower_bound(
    numbers.begin(),
    numbers.end(),
    2
);

auto last = upper_bound(
    numbers.begin(),
    numbers.end(),
    2
);
```

可以：

```cpp
auto occurrences = last - first;
```

例如：

```text
lower index = 1
upper index = 4
```

则：

```text
4 - 1 = 3
```

即 `2` 出现三次。

原因：

```text
vector::iterator
→ Random Access Iterator
```

支持 Iterator 之间直接相减。

# 十、二分相关算法复杂度

今天使用的前提：

```text
有序 vector
```

复杂度：

```text
std::find
→ O(n)

std::binary_search
→ O(log n)

std::lower_bound
→ O(log n)

std::upper_bound
→ O(log n)
```

本日出现的一个重要错误：

最初回答：

```text
std::lower_bound
→ O(n)

std::upper_bound
→ O(n)
```

正确：

```text
std::lower_bound
→ O(log n)

std::upper_bound
→ O(log n)
```

因为它们同样利用二分思想不断缩小搜索空间。

搜索空间大致：

```text
n
↓
n / 2
↓
n / 4
↓
n / 8
↓
...
```

所以：

```text
O(log n)
```

注意：

```text
Binary Search本身O(log n)
```

不等于整个程序一定：

```text
O(log n)
```

如果先：

```cpp
sort(...)
```

则排序本身：

```text
O(n log n)
```

完整复杂度必须分析整个流程。

# 十一、`std::lower_bound` vs `map.lower_bound`

```cpp
std::lower_bound(
    first,
    last,
    value
)
```

属于：

```text
<algorithm>
中的通用Algorithm
```

而：

```cpp
m.lower_bound(key)
```

属于：

```text
map自己的成员函数
```

二者虽然默认语义都类似：

```text
第一个 >= target
```

但实现依赖的数据结构不同。

对有序 `vector`：

```text
Random Access Iterator
+
Binary Search
→ O(log n)
```

而 `map` 自己：

```text
知道内部维护的有序树结构
↓
沿树进行查找
↓
O(log n)
```

因此对：

```cpp
map
```

通常优先：

```cpp
m.lower_bound(key)
```

而不是为了使用通用 Algorithm 强行：

```cpp
std::lower_bound(
    m.begin(),
    m.end(),
    ...
)
```

核心工程思想：

```text
通用Algorithm很好
但容器自己的成员查找如果能够利用内部数据结构
通常应该优先使用成员函数
```


搜索空间：


# 十五、为什么循环是 `left <= right`

```cpp
while (left <= right)
```

因为当前使用：

```text
[left, right]
```

闭区间。

当：

```text
left == right
```

时：

```text
[left, left]
```

仍然包含：

```text
1个有效元素
```

所以这个元素仍然必须检查。

只有：

```text
left > right
```

时：

```text
Search Space为空
```

---

# 十六、计算 mid

推荐：

```cpp
int mid =
    left + (right - left) / 2;
```

而不是：

```cpp
int mid =
    (left + right) / 2;
```

原因：

```text
left + right
```

在数值很大时可能发生整数溢出。

而：

```cpp
left + (right - left) / 2
```

避免先计算过大的：

```text
left + right
```

更加稳妥。

---

# 十七、中间值小于 target

如果：

```cpp
numbers[mid] < target
```

因为数据升序：

```text
numbers[mid]
以及mid左侧所有元素
```

都不可能等于 target。

因此可以排除：

```text
[left, mid]
```

新范围：

```text
[mid + 1, right]
```

代码：

```cpp
left = mid + 1;
```

---

# 十八、中间值大于 target

如果：

```cpp
numbers[mid] > target
```

则：

```text
mid以及mid右侧
```

都可以排除。

新范围：

```text
[left, mid - 1]
```

代码：

```cpp
right = mid - 1;
```

---

# 十九、为什么不能轻易 `left = mid`

最重要原则：

```text
每一轮Binary Search
必须保证Search Space严格缩小
```

例如：

```text
index:
0 1

value:
3 5

target:
5
```

初始化：

```text
left = 0
right = 1
mid = 0
```

因为：

```text
numbers[0] < 5
```

如果错误：

```cpp
left = mid;
```

那么：

```text
left = 0
right = 1
```

下一轮：

```text
mid仍然是0
```

状态完全不变，从而：

```text
可能产生死循环
```

正确：

```cpp
left = mid + 1;
```

让 Search Space 真正缩小。

# 四十三、为什么 Decode Error 后不继续 Validation

不能简单认为：

```text

→ 所有字段都一定还是零值
```

因此：

```go

    return
}
```

当：

```text

```

时：

```text
user可能处于部分写入 / 不完整状态
```

当前应直接：

```text
400
+
return
```

不要继续把它当成完整业务数据 Validation。
