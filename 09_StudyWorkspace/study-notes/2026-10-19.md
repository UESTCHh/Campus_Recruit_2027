高度定义按节点个数：H(nullptr)=0，H(non-null)=1+max(H(left),H(right))。
2.2 基础递归方案
定义 isBalanced(root)：以 root 为根的整棵子树是否平衡。三个条件同时为真：当前节点左右子树高度差 ≤ 1；左子树平衡；右子树平衡。
int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;
    return 1 + std::max(maxDepth(root->left), maxDepth(root->right));
}

bool isBalancedBasic(TreeNode* root) {
    if (root == nullptr) return true;
    int leftH = maxDepth(root->left);
    int rightH = maxDepth(root->right);
    return std::abs(leftH - rightH) <= 1
        && isBalancedBasic(root->left)
        && isBalancedBasic(root->right);
}
复杂度： 每个节点都可能重新执行 maxDepth。对于满/平衡树，每层所有节点的高度计算合计约 O(n)，有 O(log n) 层，故 O(n log n)。对于高度 n 的退化树，n+(n-1)+...+1=Θ(n²)。递归栈空间 O(h)。
2.3 自底向上优化
定义 getHeight(root)：返回 非负整数 表示子树平衡且该整数是高度；返回 -1 表示子树不平衡。先左右递归获得高度，一旦遇 -1 立即传播；否则检查高度差，合格再 1+max。树节点最多进入一次 getHeight，最坏时间 O(n)，空间 O(h)。
高度为 3 的满二叉树（7 个节点）：非空节点的后序返回顺序可以是 4→5→2→6→7→3→1；每个节点只调用一次 getHeight，父节点直接接收子节点返回的高度。
基础解法同一树额外 maxDepth 非空访问数： 根层 6、第二层 4、叶子层 0，总计 10，加上 isBalanced 的 7 次非空进入，共计 17 次非空节点函数访问；优化解法是 7 次非空节点进入。高度 4 满二叉树有 15 个节点，基础解法 maxDepth 的非空访问为 14+12+8+0=34，再加 15 次 isBalanced 进入，共 49；优化法访问 15 个非空节点。这里统计口径不包含空指针调用，不代表实际机器指令数。

#include <iostream>
#include <algorithm>
#include <cstdlib>

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    explicit TreeNode(int value) : val(value), left(nullptr), right(nullptr) {}
};

int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;
    return 1 + std::max(maxDepth(root->left), maxDepth(root->right));
}

int heightDifference(TreeNode* root) {
    if (root == nullptr) return 0;
    return std::abs(maxDepth(root->left) - maxDepth(root->right));
}

bool isBalancedBasic(TreeNode* root) {
    if (root == nullptr) return true;
    int leftH = maxDepth(root->left);
    int rightH = maxDepth(root->right);
    return std::abs(leftH - rightH) <= 1
        && isBalancedBasic(root->left) && isBalancedBasic(root->right);
}

int getHeight(TreeNode* root) {
    if (root == nullptr) return 0;
    int leftH = getHeight(root->left);
    if (leftH == -1) return -1;
    int rightH = getHeight(root->right);
    if (rightH == -1) return -1;
    if (std::abs(leftH - rightH) > 1) return -1;
    return 1 + std::max(leftH, rightH);
}

bool isBalancedOptimized(TreeNode* root) {
    return getHeight(root) != -1;
}

int main() {

    a1.left=&a2; a1.right=&a3;
    a2.left=&a4; a2.right=&a5;
    // B: 根的左右高度均 3，但两个二级节点各有高度为 2 的单侧链
    TreeNode b1(1), b2(2), b3(3), b4(4), b5(5), b6(6), b7(7);

 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}

class Solution {
public:
    int getHeight(TreeNode* root){
        if(root == nullptr){
            return 0;
        }
        int leftH = getHeight(root -> left);
        if(leftH == -1){
            return -1;
        }
        int rightH = getHeight(root -> right);
        if(rightH == -1){
            return -1;
        }
        if(abs(leftH - rightH) > 1){
            return -1;
        }
        return 1 + max(leftH, rightH);
    }
    bool isBalanced(TreeNode* root) {
        return getHeight(root) != -1;
    }
};

            return

    })

// performRequest 在内存中执行一条 HTTP 请求；不会开启监听端口。
func performRequest(t *testing.T, handler http.Handler, method, path, jsonBody string) (int, http.Header, []byte) {
	t.Helper()

	var body io.Reader
	if jsonBody != "" {
		body = strings.NewReader(jsonBody)
	}
	req := httptest.NewRequest(method, path, body)
	if jsonBody != "" {
		req.Header.Set("Content-Type", "application/json")
	}

	recorder := httptest.NewRecorder()
	handler.ServeHTTP(recorder, req)
	resp := recorder.Result()
	defer resp.Body.Close()

	responseBody, err := io.ReadAll(resp.Body)
	if err != nil {
		t.Fatalf("read HTTP response: %v", err)
	}
	return resp.StatusCode, resp.Header, responseBody
}

Go Stage 1｜问题 1：httptest 工作原理
问题： NewRequest、NewRecorder、ServeHTTP 各做什么？为何不需监听网络？
我的回答（准确原话）：
httptest.NewRequest()生成一个http请求，httptest.NewRecorder()将handler返回的响应记录下来，handler.ServeHTTP()则真正调用handler内的业务逻辑，并生成返回响应。这样的测试可以绕过网络连接，在本地终端即可完成整套流程

订正： 正确。Recorder 实现 ResponseWriter，记录 Handler 写出的响应；Handler 本身通常没有返回值。
相关示例： req:=httptest.NewRequest(...); rec:=httptest.NewRecorder(); mux.ServeHTTP(rec,req)。
面试专用回答： 使用 httptest 构造请求、捕获响应并直接执行 Handler，无须真实监听端口，可验证状态码和 JSON。

Go Stage 4｜问题 1：POST 请求体

        http.MethodPost,
        "/students",
        strings.NewReader(requestBody),
    )

订正： 核心正确。strings.NewReader 提供可读数据，真正读取/解码的是 Handler 的 json.NewDecoder(r.Body).Decode(&student)。GET 并非理论上绝对不能有 body。
相关示例： strings.NewReader(jsonText) → r.Body → json.NewDecoder(r.Body).Decode(&student)。
面试专用回答： POST 用请求体传 JSON，测试中构造 Reader，服务端通过 r.Body 和 Decoder 解析。

Go Stage 6｜问题 1：DELETE 测试与数据库验证
问题： 为何除了 204 还要 GetByID；为什么检查 sql.ErrNoRows？
我的回答（准确原话）：
只检查HTTP 204是验证响应是否正确，还必须验证数据库真正删除了一条记录，所以要通过查询的方式验证；因为删除具有幂等性，删除0条记录造成的数据库资源状态和删除1条相同，所以要区分正确删除一条和数据不存在，删除了0条

订正： 核心正确。GetByID + ErrNoRows 验证删除后已不存在，不能单独区分此前删除了 1 行还是原本就不存在；RowsAffected 才区分 DELETE 的影响行数。因此测试先 Create、执行首个 204、再查询 ErrNoRows。
相关示例： affected,err:=repo.Delete(id) 区分受影响行数；errors.Is(err,sql.ErrNoRows) 说明后续查询无此记录。
面试专用回答： DELETE 测试检查 204、空体、数据库记录不存在；RowsAffected 用于实际影响行数判别。
Go Stage 6｜问题 2：204 No Content
问题： 204 的意义，为何响应体应为空？
我的回答（准确原话）：
代表删除成功。删除成功后返回http.Nocontent,所以响应体不能含有内容，应为空

订正： 在此 API 下正确。通用含义是请求成功处理且无响应内容，不局限删除。Go 常量是 http.StatusNoContent，而非 http.NoContent。
相关示例： w.WriteHeader(http.StatusNoContent)；测试 len(body)==0。
面试专用回答： 204 表示已处理且无响应体，测试同时检查 HTTP 204 和空响应体。
Go Stage 6｜问题 3：DELETE 幂等性
问题： 为何第一次 204、第二次 404 仍幂等？
我的回答（准确原话）：
因为相同的两次删除请求得到的数据库资源状态相同，所以具有幂等性。两次删除后数据库中对应id为9004的记录均不存在了

订正： 完全正确。幂等性关注请求重复执行对目标资源的预期效果相同，HTTP 状态码可不同。
相关示例： 第 1 次：204 且无记录；第 2 次：404 且仍无记录。
面试专用回答： DELETE 幂等不等于每次返回同一 HTTP 状态码，重复删除后的目标资源都不存在。
