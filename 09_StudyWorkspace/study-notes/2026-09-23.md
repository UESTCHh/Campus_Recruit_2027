# 四、第一类：反复获取当前最大值 / 最小值

例如：

```text
Last Stone Weight
```

需要：

```text
取当前最大的两个元素
↓

↓
可能产生新元素
↓
重新加入
↓
再次取当前最大的两个元素
```

这种问题的关键词：

```text
反复
动态变化
不断取最大 / 最小
```

适合：

```text
Heap
```

例如：

```cpp

```

：

```text
top()
→ 当前最大值
```

# 五、第二类：只维护最大的 K 个元素

例如：

```text
LC215
第 K 大元素
```

不需要完整排序所有元素。

只需要维护：

```text
当前最大的 K 个元素
```

因此使用：

```text
Size-K Min Heap
```

原因：

```text
求最大的 K 个
↓
最关心的不是当前最大的那个
↓
而是这 K 个里面最小的那个
↓
因为它是最容易被淘汰的候选
```

所以：

```text
minHeap.top()
→ 当前 Top K 中最小元素
→ Top K 门槛
```

# 八、Stage 1 实验

数组：

```cpp
vector<int> nums{
    10, 4, 8, 3, 15, 6
};
```

要求：

```text
最大的3个元素
```

使用：

```cpp
priority_queue<
    int,
    vector<int>,
    greater<int>
> minHeap;
```

核心：

```cpp
for (int value : nums)
{
    minHeap.push(value);

    if (
        static_cast<int>(
            minHeap.size()
        ) > k
    ) {
        minHeap.pop();
    }
}
```

最终：

```text
8
10
15
```

虽然弹出顺序是升序，但 Heap 中保存的集合正是：

```text
Top 3
```

# 十、Stage 1 检查 1

## 问题

```text
A. 不断加入新数字，随时获取当前最大值

B. 在大量数字中只维护最大的5个
```

应该分别使用什么 Heap？

## 我的回答

> A. Max heap，因为每次加入新数字都要获取目前为止出现过元素的最大值，所以每次取出来的就是优先级最高的元素是值最大的元素。
>
> B. Min heap，因为只在大量数字中维护最大的五个，那么即heap只保存前5大的元素，而进入前五大元素的集合内需要比当前第五大元素更大才行，而当前第五大即前5大中最小的那个元素，所以优先级最高的元素是当前集合内值最小的元素。

## 订正

完全正确。

A：

```text
不断获取当前最大值
→ Max Heap
```

B：

```text
只保存最大的5个
→ Size-5 Min Heap
```

因为真正需要不断观察：

```text
当前Top 5里最小的那个
```

。

## 相关示例

当前：

```text
100 90 80 70 60
```

：

```text
60
→ 当前Top 5门槛
```

新值：

```text
55
→ 不进入
```

新值：

```text
75
→ 淘汰60
```

## 面试专用回答

> 如果需要反复获得当前最大值，可以使用 Max Heap；如果只需要维护最大的 K 个元素，则使用 Size-K Min Heap，因为堆顶是当前 Top K 中最小的候选，也是最容易被新元素淘汰的门槛。

# 十二、Stage 1 检查 3

## 我的回答

```text
LC215
→ 给出一个确定原数组，并根据这个数组中的所有元素保存最大的K个
```

完全正确。

```text
LC215
→ Static Top K
→ priority = value

LC703

→ priority = value

LC347
→ Derived-priority Top K
→ priority = frequency
```

# 二十三、检查 2：为什么 Last Stone Weight 需要 Heap？

## 我的回答

> 因为Last Stone Weight需要不断取出当前剩余石头集合的最大值，不是只遍历一次，第一次最大值被取走后如果石头数量大于2个就必须再取一次最大值进行两个石头的粉碎，而只维护一个maxvalue只能知道当前一次遍历得到的最大值，无法维护取出该最大值后剩余元素的大小关系情况

## 订正

理解正确。

更完整：

```text
取最大两个
↓
删除
↓
可能产生新石头
↓
重新加入
↓
再次获取当前最大两个
```

集合不断动态变化。

一个 `maxValue` 无法维护：

```text
删除
+
插入
+
新的大小关系
```

。

## 面试专用回答

> Last Stone Weight 需要反复删除最大的两个元素，并可能插入新的元素，因此集合持续动态变化。单个最大值变量无法维护这些变化后的完整优先级关系，而 Max Heap 可以持续高效地维护当前最大元素。

# 二十四、检查 3：完整排序

## 我的回答

> std::sort，因为sort本身逻辑即将该数组元素排序，而priority_queue需要先push进去再通过top+pop的方式进行排序，而且结果必须用一个新数组来接收，不像sort可以直接在原数组上操作，时间复杂度和空间复杂度都较差

## 订正

选择 `std::sort` 正确。

但：

```text
priority_queue时间复杂度更差
```

这个说法需要修正。

逐个 push：

```text
O(n log n)
```

再全部 pop：

```text
O(n log n)
```

总体：

```text
O(n log n)
```

而：

```cpp
std::sort
```

同样通常是：

```text
O(n log n)
```

所以两者在大 O 时间复杂度上可能处于同一量级。

真正区别：

```text
题目本身就是完整排序
→ std::sort更直接自然

priority_queue
→ 更适合动态优先级、反复取极值、Top K
```

同时 `std::sort` 可以直接重排原容器，而构造 `priority_queue` 通常需要额外容器空间。

## 面试专用回答

> 如果目标就是对整个数组排序，应优先使用 `std::sort`，因为它直接表达排序需求并可以直接重排原容器。Heap 更适合动态维护优先级、反复取极值或 Top K，而不是普通完整排序。

```http

```

```go
w.Header().Set(...)
```

但并不意味着：

，而是：


# 六十二、Go Day27 易错点

## 1. Decode 必须传目标地址

```go
Decode(&req)
```

因为 Decoder 要修改：

```text
req
```

---

## 2. Encode 不要求必须传指针

通常：

```go
Encode(resp)
```

即可。

---

## 3. `r` 与 `w` 不是同一个方向

```text
r
→ Request输入

w
→ Response输出接口
```

---

## 4. Response Header 要先设置

```text
Header
↓
Status
↓
Body
```

---

## 5. 不写 WriteHeader 默认是 200

```text
第一次写Body
↓
隐式200 OK
```

---

## 6. Decode 成功不等于 Validation 成功

```text
Parse / Decode
→ 能不能转换

Validation
→ 业务允不允许
```

---

## 7. `http.Error` 不会自动结束 Handler

```go
http.Error(...)
return
```

通常需要一起出现。

---

## 8. `http.Error` 没有返回值

它通过：

```text
ResponseWriter
```

直接写 Response。

---

## 9. `http.Error` 的 Header 逻辑封装在函数内部

所以调用处看不到：

```go
w.Header().Set(...)
```

并不代表没有相关 Header 处理。
